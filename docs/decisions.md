## D-002. 1순위 AI 제공자 — `잠정` (PoC 후 확정)
- **Codex App Server** (stdio JSON-RPC)를 MVP의 유일한 AI 제공자로 사용합니다.
- 인증: ChatGPT 로그인 (`account/login/start`, type `chatgpt`). 사용자는 ChatGPT Pro 구독 보유.
- Claude 구독은 없으므로 Claude 어댑터는 계획에서 제외합니다 (API 키 기반 어댑터는 후속 버전에서 일반 API 어댑터로 수용 가능).
- Gemini CLI는 일반 사용자 대상 서비스가 2026-06-18 Antigravity CLI로 대체되어 CLI 통합 대상에서 제외합니다.
- **확정 조건 (PoC)**: ① 튜터 응답 품질(한국어, 교수법 지침 준수) ② 첫 토큰 지연 ③ `outputSchema` 구조화 출력 안정성 ④ 셸/파일 도구 비활성화(빈 cwd + readOnly sandbox + 승인 자동 거부) 동작 확인.
- 설계 원칙: Provider Adapter 계층을 두고, AI가 없어도 레슨·문제·채점·복습·통계는 동작해야 합니다.

## D-003. 콘텐츠 범위 — `확정`
- **JavaScript: 완전한 품질** (충분한 설명, 단원당 충분한 문제, 다양한 유형, 응용 실습).
- **HTML / CSS: 핵심 위주로 얕게** (JS 학습과 DOM 실습에 필요한 수준 + 기본 레이아웃).
- 해석 메모: JS 전체(기초 → 심화 → 브라우저 JS)를 완전한 품질로 만들되, 출시는 단계적으로 진행합니다. MVP는 HTML/CSS 핵심 + JS 기초 전체, 이후 JS 심화와 브라우저 JS를 추가합니다. → PRD §7 참고.

## D-004. 콘텐츠 제작 전략 — `확정`
세 갈래 혼합:
1. **사전 제작 문제은행 (content-as-code)**: 저장소에 MDX(레슨) + YAML(문제)로 저장. AI 보조로 초안 대량 작성 → 스키마 검증 → 샌드박스 실행 검증 → 샘플 검토.
2. **파라메트릭 템플릿**: 하나의 문제 템플릿에서 변수를 바꿔 여러 변형 생성, 정답은 실제 실행으로 계산.
3. **런타임 AI 생성 (보충)**: 학습자 요청 시 생성 → 검증 → `draft` 상태로 사용 → 사용 통계/신고에 따라 승격 또는 격리.
- 핵심 학습 경로는 AI 없이 1+2만으로 완결되어야 합니다.
- 개발 일정의 상당 부분(30~40%)이 콘텐츠 제작에 들어갑니다.

## D-009. 숙련도 · 복습 모델 — `확정`
- **숙련도(0~100)**: 설명 가능한 규칙 기반 가중 점수 (난이도, 1차 시도 여부, 힌트 단계, 확신도, 문제 유형, 최근성). 단계 게이트: 서로 다른 유형·L3 이상 응용·간격 복습 성공을 요구.
- **복습 스케줄**: **개념 단위 FSRS** (`ts-fsrs`). 복습 시에는 같은 문제가 아닌 새 변형 문제를 출제.
- **재학습 규칙**: 반복 실패 시 선수 개념 점검 → 단계적 풀이 예제로 하향 → 선수 개념 복습 제안. 결정은 규칙 엔진이 담당.

## D-010. AI 튜터 개입 정책 — `확정`
- 정답 공개 여부는 **프롬프트가 아니라 코드가 결정**합니다. 힌트 단계에 따라 AI 컨텍스트에 정답 포함 여부를 제어합니다.
- 힌트 3단계 (방향 제시 → 핵심 개념/부분 코드 → 거의 완성된 가이드) 이후 명시적 "정답 보기" 행동으로만 정답 공개. 정답 열람 시 숙련도 반영 가중치 감소.
- 소크라테스식 질문 유도를 기본으로 하되, 학습자가 연속으로 막히면 직접 설명으로 전환.
- 튜터의 선제 개입은 제한적으로: 반복 실패, 장시간 정체, 확신했는데 틀린 경우에만 제안 형태(배지/버튼)로 표시하고 대화를 강제로 열지 않습니다.
- AI는 학습자 모델에 직접 쓰지 않고, 근거가 있는 "제안"만 하며 앱이 검증 후 반영합니다.

- 다크 모드 지원 (라이트 기본).
- 상세는 UI/UX 설계서에서 다룹니다. 설계 시 실제 레퍼런스 화면 조사를 포함합니다.

## D-018. 샌드박스 러너 셸 방식 — `잠정` (M1-B PoC 후 확정)
- 서버가 `/sandbox/runner.html`을 전용 CSP 응답 헤더와 함께 제공하고, 앱은 `sandbox="allow-scripts allow-forms"` iframe으로 삽입합니다.
- 앱 문서에서 직접 `srcdoc` iframe을 만들지 않습니다. `srcdoc` 문서는 부모의 CSP를 상속하므로 러너 전용 정책(`connect-src 'none'` 등)을 독립적으로 줄 수 없기 때문입니다.
- 순수 JS는 셸 내부 Worker(`terminate()`로 중단), DOM·미리보기는 셸 내부 중첩 iframe + 루프 가드 + 워치독으로 실행합니다.
- 채점은 관측 모델입니다: 하네스는 관측값만 반환하고 서버가 기대값과 비교합니다.
- 상세: [코드 실행 샌드박스 설계](/docs/design/code-execution-sandbox.md).

## D-020. 기본 웹 실습의 MVP 포함 — `확정`
MVP 콘텐츠에 HTML/CSS 단원과 브라우저 JS 입문(DOM·이벤트)이 들어가므로, 단일 문서 기반 기본 웹 실습(HTML 구조, CSS 스타일·레이아웃, DOM 이벤트)을 P0로 올립니다. 여러 파일 실습, 뷰포트 전환, 박스 모델 인스펙터는 P1로 유지합니다.
