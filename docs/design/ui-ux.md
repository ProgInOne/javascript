# UI/UX 설계

ProgInOne의 시각 언어, 디자인 토큰, 컴포넌트, 화면 구조, 핵심 인터랙션, 접근성 기준, UI 품질 검증 절차를 정의합니다.
UI는 인프런 같은 밝고 친근한 한국형 교육 플랫폼의 톤을 자체 아이덴티티로 재해석하고, UX는 학습과학 연구 근거를 화면 결정에 직접 연결합니다.

- 상태: 승인됨 (2026-11-14)
- 작성: ProgInOne 팀
- 최종 수정: 2026-11-14 (M2 결과 반영, [D-024](/docs/decisions.md))
- 관련 문서: [PRD](/docs/product/prd.md), [결정 기록](/docs/decisions.md), [용어집](/docs/glossary.md), [시스템 아키텍처 설계](/docs/design/system-architecture.md), [학습 엔진 설계](/docs/design/learning-engine.md), [콘텐츠·문제 시스템 설계](/docs/design/content-and-exercises.md), [코드 실행 샌드박스 설계](/docs/design/code-execution-sandbox.md), [AI 시스템 설계](/docs/design/ai-system.md)

## 배경과 범위

PRD는 UI/UX를 "부가 요소가 아닌 핵심 요구사항"으로 정의합니다([PRD 제품 원칙](/docs/product/prd.md#제품-원칙)).
결정 [D-011](/docs/decisions.md)에 따라 UI는 **인프런 느낌**(화이트 기반, 산뜻한 그린 강조, 한글 가독성, 커리큘럼 아코디언과 진도 체크)을 참고하되 복제하지 않고, UX는 학습과학 근거로 설계합니다.
학습 화면은 **읽기 모드 ↔ 실습 모드 전환형**([D-007](/docs/decisions.md)), 에디터는 **CodeMirror 6**([D-008](/docs/decisions.md))입니다.

이 문서가 다루는 범위:

- 디자인 원칙과 레퍼런스 분석
- 브랜드 아이덴티티와 디자인 토큰(색, 타이포그래피, 간격, 반경, 그림자, 모션)
- 컴포넌트 목록과 상태별 규격
- 정보 구조(사이트맵)와 화면별 와이어프레임·명세, 빈·로딩·오류 상태
- 학습 인터랙션 설계와 그 학습과학 근거
- 마이크로카피 원칙
- 키보드, 포커스, 접근성(WCAG 2.2 AA), 반응형, 패널 규칙
- UI 품질 검증 절차와 구현 전 프로토타입 계획

이 문서가 다루지 않는 범위:

- 숙련도·복습 계산 방식: [학습 엔진 설계](/docs/design/learning-engine.md)
- 문제 유형의 데이터 스펙과 채점: [콘텐츠·문제 시스템 설계](/docs/design/content-and-exercises.md)
- 샌드박스 실행 방식: [코드 실행 샌드박스 설계](/docs/design/code-execution-sandbox.md)
- 튜터 프롬프트와 정답 공개 통제 로직: [AI 시스템 설계](/docs/design/ai-system.md)

## 목표와 비목표

### UI/UX 목표

- **장시간 학습에 편안한 화면.** 한 번에 30~60분, 수개월 동안 매일 써도 눈이 피로하지 않고 정보가 정돈되어 있어야 합니다.
- **학습 효과를 높이는 인터랙션.** 예측 후 실행, 확신도 입력, 힌트 사다리, 교차 복습처럼 근거 있는 기법을 별도 기능이 아니라 기본 흐름에 녹입니다.
- **한 화면 안의 학습 순환.** 레슨 → 문제 → 실행 → 피드백 → 튜터 질문이 화면 전환 없이 이어집니다.
- **명확한 상태 표현.** 지금 어디에 있고, 무엇을 잘하고, 무엇을 복습해야 하는지 3초 안에 알 수 있어야 합니다.
- **키보드만으로 모든 학습 흐름 완주.** WCAG 2.2 AA를 만족합니다.
- **상용 수준의 완성도.** 빈·로딩·오류 상태까지 모두 디자인합니다.

### UI/UX 비목표

- **인프런 화면 복제.** 로고, 고유 색상 값, 일러스트, 레이아웃을 그대로 쓰지 않습니다. 패턴과 톤만 참고합니다.
- **게임화된 보상 체계.** 경험치, 레벨, 리그, 하트, 캐릭터, 컨페티를 넣지 않습니다. 연속 학습일을 깨뜨렸다는 경고성 표현도 쓰지 않습니다.
- **모바일 우선 디자인.** 최소 폭 1024px 데스크톱이 대상입니다. 그 아래에서는 깨지지 않고 읽을 수 있는 수준만 보장합니다.
- **사용자 테마 커스터마이징.** 라이트·다크·시스템 외의 색 테마, 폰트 변경은 지원하지 않습니다. 단, 레슨 본문 글자 크기 3단계 조절은 제공합니다(접근성).
- **동영상 플레이어 UI.** 텍스트·인터랙티브 콘텐츠만 다룹니다.

## 설계

### 개요

ProgInOne의 디자인 콘셉트는 **"밝은 교실, 정돈된 작업대"** 입니다.

- **밝은 교실**: 대시보드·과정·복습·통계 같은 둘러보기 화면과 읽기 모드. 화이트 캔버스, 넉넉한 여백, 그린 강조, 친근한 한국어 문구. 인프런의 익숙한 톤을 계승합니다.
- **정돈된 작업대**: 실습 모드. 같은 색 체계를 쓰되 밀도를 높이고, 에디터·미리보기·콘솔이 분할 패널로 배치됩니다. VS Code와 Codecademy의 생산성 패턴을 가져옵니다.
- 두 영역은 같은 토큰, 같은 컴포넌트, 같은 상단 구조를 공유해서 한 제품으로 느껴지게 합니다.

### 디자인 원칙

1.  **학습이 주인공입니다.**
    콘텐츠 영역 외의 크롬(헤더, 사이드바, 툴바)은 낮은 대비와 작은 면적으로 둡니다. 강조색은 "다음에 할 행동"과 "학습 상태"에만 씁니다.
1.  **한 화면에 주요 행동은 하나입니다.**
    채움(primary) 버튼은 화면 영역당 하나입니다. 예: 문제 화면의 "제출", 대시보드의 "이어서 학습".
1.  **상태는 색만으로 전달하지 않습니다.**
    정답·오답·숙련 단계는 항상 아이콘 모양과 텍스트를 함께 씁니다(색약 대응, WCAG 1.4.1).
1.  **생각할 시간을 보장합니다.**
    정답은 클릭 한 번으로 노출되지 않습니다. 힌트는 단계적으로 열리고, 예측을 먼저 적게 합니다([D-010](/docs/decisions.md)).
1.  **부드럽지만 빠르게.**
    애니메이션은 상태 변화의 이해를 돕는 데만 쓰며 320ms를 넘지 않습니다. 결과 표시는 기다리게 하지 않습니다.
1.  **설명 가능한 시각화.**
    숫자와 그래프에는 항상 "왜 이렇게 나왔는지"로 가는 경로가 있습니다(예: 숙련도 → 근거 시도 목록).
1.  **AI는 구분되어 보입니다.**
    AI가 작성한 텍스트와 AI 생성 문제는 별도의 보조 색(바이올렛)과 표식으로 구분해, 학습자가 출처를 항상 알 수 있게 합니다.

### 레퍼런스 분석

#### 인프런 (주 레퍼런스)

공개 자료와 일반적으로 알려진 화면 패턴을 기준으로 정리했습니다.
제3자 디자인 시스템 갤러리 자료에 따르면, 인프런은 흰 캔버스에 그린 액센트를 쓰는 미니멀·플랫 스타일이고, 서체는 Pretendard, 간격은 4px 단위, 카드 반경은 10px 안팎입니다([oppadu 디자인 시스템 갤러리][oppadu-inflearn], 공식 자료는 아님).
실제 화면 구조(수강 화면의 커리큘럼 사이드바, 노트·질문 탭 위치 등)는 공개 문서로 확인하기 어려웠으므로, [프로토타입 단계](#디자인-프로토타입-계획)에서 실제 화면을 직접 관찰해 다시 검증합니다.

| 인프런 패턴 | 가져올 것 | 바꾸거나 피할 것 |
|---|---|---|
| 화이트 캔버스 + 그린 강조 | 밝고 신뢰감 있는 기본 톤, 강조색 절제 사용 | 인프런 그린(`#00C471`)과 구분되는 **청록 쪽 제이드 그린**을 자체 값으로 사용 |
| Pretendard 기반 한글 타이포그래피 | 한글 가독성, 굵은 제목과 차분한 본문 | 레슨 본문은 인프런 UI(14px)보다 크게(17px), 행간 넓게. 장문 학습용 |
| 강의 카드 그리드 | 과정 목록의 썸네일 카드 구조, 2줄 말줄임 제목 | 가격·할인 정보 대신 진도·숙련도·예상 시간 표시 |
| 강의 상세의 커리큘럼 섹션 아코디언 | 섹션별 접기, 수업 수·시간, 완료 체크 | 각 단원에 **숙련 단계 아이콘과 복습 예정 표시** 추가 |
| 수강 화면의 커리큘럼 사이드바 + 진도 체크 | 학습 중 위치 파악, 다음 수업 이동 | 영상 대신 텍스트·문제 단위. 사이드바를 접을 수 있는 레일로 |
| 내 학습(수강 중 강의 + 진도율) | "이어서 학습" 중심 대시보드 | 진도율만이 아니라 **숙련도와 복습**을 함께 보여줌 |
| 노트·질문(Q&A) | 학습 중 메모와 질문의 자리 | 사람 Q&A 대신 **AI 튜터 드로어**. 노트는 P2 |
| 로드맵 | 과정 간 학습 순서 제시 | 개념 선수 그래프 기반 **개념 지도** 로 확장 |
| 홍보 배너·할인 CTA | — | 학습 앱에는 상업적 요소 불필요. 모두 제외 |

### 학습과학 근거와 설계 결정

화면 결정마다 근거를 연결합니다. 근거의 강도는 [Dunlosky et al. (2013)][dunlosky2013]의 효용 평가를 따릅니다.
해당 리뷰는 10가지 학습 기법 중 **연습 테스트(practice testing)** 와 **분산 연습(distributed practice)** 을 "높은 효용", 정교화 질문·자기 설명·교차 연습을 "중간 효용", 요약·하이라이트·다시 읽기를 "낮은 효용"으로 평가했습니다.

| 근거 | 핵심 내용 | ProgInOne 설계 결정 |
|---|---|---|
| 인출 연습 ([Roediger & Karpicke 2006][roediger2006]) | 다시 읽기보다 기억에서 꺼내는 시험이 장기 기억에 유리 | 레슨 본문 사이에 인라인 확인 문제. 단원 끝 요약은 "다시 읽기"가 아니라 "떠올려보기" 질문으로 시작 |
| 분산 연습 ([Dunlosky 2013][dunlosky2013]) | 같은 시간이면 나눠서 반복하는 쪽이 오래 기억 | 대시보드 최상단 "오늘의 복습". 복습량을 시간으로 표시해 진입 부담을 낮춤 |
| 교차 연습 ([Kornell & Bjork 2008][kornell2008]) | 섞어서 연습하면 학습 중 체감은 어렵지만 구분 능력과 장기 성과 향상 | 복습 세트는 여러 개념을 섞음. "섞여 나와서 어렵게 느껴지는 게 정상"이라는 안내 문구 |
| 바람직한 어려움 ([Bjork & Bjork 2011][bjork2011]) | 학습 중 적당한 어려움이 장기 학습을 강화하지만, 학습자는 쉬움을 선호하는 착각을 함 | 정답 즉시 공개 금지, 힌트 단계화, 숙련도 화면에서 "체감과 실제" 차이를 설명 |
| 인지부하·풀이 예제 ([Sweller 1988][sweller1988], [Renkl & Atkinson 2003][renkl2003]) | 초보자에게는 완성된 풀이 예제를 보고 점차 빈칸을 늘리는 방식이 효과적 | 재학습 경로의 "단계적 풀이 예제" 화면. 레슨의 코드 예제는 한 번에 한 개념만 새로 등장 |
| 전문성 역전 효과 ([Kalyuga et al. 2003][kalyuga2003]) | 초보자에게 유익한 안내가 숙련자에게는 오히려 방해 | 숙련 단계가 높은 개념은 레슨 섹션을 접힌 상태로 시작, 힌트 버튼을 덜 강조 |
| PRIMM ([Sentance et al. 2019][sentance2019]) | Predict → Run → Investigate → Modify → Make 순서의 프로그래밍 교수법 | 실행 가능한 예제는 "예측 → 실행 → 비교" 흐름이 기본. 연습 세트는 읽기(예측) → 수정(버그 수정) → 작성(구현) 순서로 배치 |
| 파슨스 문제 ([Ericson et al. 2017][ericson2017]) | 코드 순서 배열은 같은 코드를 직접 쓰는 것보다 빠르게 풀리면서 학습 효과는 비슷함 | 새 문법을 처음 연습할 때 파슨스 문제를 먼저 배치. 키보드로도 조작 가능 |
| 확신도와 과잉 교정 ([Butterfield & Metcalfe 2001][butterfield2001]) | 확신했는데 틀린 오답은 교정 피드백을 받으면 오히려 더 잘 고쳐짐 | 제출 시 확신도 입력. "확신 + 오답"에는 더 자세한 교정 피드백과 오개념 설명을 우선 표시 |

### 브랜드 아이덴티티

#### 이름의 의미

**ProgInOne** = Programming + All-in-One.
레슨, 문제, 실행, 튜터, 복습이 **한 곳에** 모여 있다는 제품 약속을 그대로 담습니다.
시각 언어도 이 의미를 따릅니다: **흩어진 조각이 하나로 맞물리는 형태**.

#### 로고 방향 (텍스트 명세)

- **심볼**: 둥근 모서리 사각형 안에 코드 꺾쇠 `‹ ›` 두 개가 서로 맞물려 하나의 원(점)을 감싸는 형태. "코드 조각들이 하나로"를 표현합니다. 원(점)은 학습자, 꺾쇠는 코드와 커리큘럼을 상징합니다.
- **워드마크**: `ProgInOne`. Pretendard 800, 자간 -0.02em. `In`만 브랜드 그린으로 표시해 "All-in-One"을 암시합니다. 대문자 P, I, O를 유지합니다.
- **사용 규칙**: 최소 크기 심볼 20px, 워드마크 높이 16px. 단색(뉴트럴 900 / 화이트) 버전을 함께 정의합니다. 그린 그림자, 그라데이션, 3D 효과는 쓰지 않습니다.
- **확정(2026-11-14, [D-024](/docs/decisions.md))**: 위 명세를 따른 1안 "맞물린 꺾쇠"를 채택했습니다. SVG 원본은 [디자인 프로토타입](/design/prototypes/README.md)의 `index.html`에 있습니다. 3안 "네 조각 하나"는 온보딩·빈 상태 보조 그래픽으로 쓸 수 있습니다.

#### 어조

- 친근하고 정중한 **해요체**. 선배 개발자가 옆에서 알려주는 느낌.
- 칭찬은 구체적으로, 실패는 비난 없이, 다음 행동은 분명하게.
- 상세 규칙은 [마이크로카피](#마이크로카피-원칙)에 있습니다.

### 디자인 토큰

토큰은 CSS 변수로 정의하고 Tailwind CSS v4 테마에 연결합니다([D-006](/docs/decisions.md)).
토큰은 3계층입니다.

1.  **기본 토큰(primitive)**: 색 스케일 값. 예: `--jade-600`.
1.  **의미 토큰(semantic)**: 용도별 이름. 예: `--color-action-primary`. 컴포넌트는 의미 토큰만 사용합니다.
1.  **컴포넌트 토큰**: 꼭 필요한 경우만. 예: `--editor-gutter-bg`.

라이트·다크 전환은 의미 토큰의 매핑만 바꿉니다. 모든 색 값은 OKLCH로 정의하고, 대비는 토큰 확정 시 검증 스크립트로 측정해 문서의 목표를 만족하는지 CI에서 확인합니다.

구현(`packages/ui`, M3) 메모:

- 의미 색은 CSS `light-dark()`로 정의하고, 테마는 `<html data-theme="light|dark">`(없으면 `prefers-color-scheme`)가 `color-scheme`만 바꿉니다. 다크 작업대는 `<html data-workbench="dark">`일 때 `.workbench` 범위에 `color-scheme: dark`를 걸어 같은 매핑을 재사용합니다. 라이트·다크 값을 한 곳에 두어 중복과 누락을 막기 위해서입니다.
- 시각 방향 전환(A/B/C)은 프로토타입 전용이었으므로 구현에는 C만 기본값으로 둡니다.
- 대비 검사: `pnpm check:contrast`([`packages/ui/scripts/check-contrast.ts`](/packages/ui/scripts/check-contrast.ts))가 라이트·다크·다크 작업대에서 의미 토큰 쌍을 검사합니다. 이 과정에서 라이트 코드 줄 번호(`--code-gutter-fg`)를 `neutral-500`(4.5:1 미만)에서 `neutral-550`(4.83:1)으로 올렸습니다.
- `packages/ui` 기본 컴포넌트는 Tailwind 없이 의미 토큰만 쓰는 일반 CSS(`components.css`, `pi-` 접두사)로 스타일링합니다. 공용 컴포넌트가 앱의 CSS 도구에 묶이지 않게 하기 위해서입니다([D-025](/docs/decisions.md)).
- `apps/web`의 화면 배치는 Tailwind v4 유틸리티로 씁니다(`apps/web/src/app/tailwind.css`).
  - 토큰을 유틸리티 이름으로 연결합니다(`bg-canvas`, `text-fg-secondary`, `border-line`, `shadow-1`, `type-h1` 등). Tailwind 기본 색 팔레트는 지워서 토큰 밖 색을 쓸 수 없게 했습니다.
  - CSS 계층 순서는 `theme < base(ui base.css) < components(ui components.css) < utilities`입니다. 유틸리티가 항상 컴포넌트 스타일을 덮을 수 있고, `tokens.css`는 계층 밖에 두어 Tailwind 테마 변수보다 우선합니다.

#### 에디터와 코드 색

- 코드 블록과 에디터는 **라이트 모드에서도 라이트 테마** 를 기본으로 합니다(화면 전체 톤 일관성). M2 비교 후 확정했습니다([D-024](/docs/decisions.md)). 어두운 작업대는 설정 "작업대 테마: 어둡게"로 제공하며, `.workbench` 범위에서 의미 토큰을 다크 값으로 재매핑합니다.
- 구문 강조 색은 jade(키워드), blue(함수), amber(숫자·상수), violet(문자열), neutral-500(주석)로 구성하고, 각 색은 코드 배경과 4.5:1 이상을 만족합니다.
- 오류 줄은 `red-50`(다크: `red-950`) 배경 + 거터의 오류 아이콘. 색만으로 표시하지 않습니다.

#### 그림자와 elevation

라이트 모드는 **테두리 + 매우 약한 그림자**, 다크 모드는 **표면 명도 상승 + 테두리** 로 깊이를 표현합니다(다크에서 그림자는 거의 보이지 않으므로).

| 단계 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `elevation-0` | 테두리만 | `neutral-900` 표면 | 기본 카드, 패널 |
| `elevation-1` | `0 1px 2px oklch(0.2 0.01 168 / 0.06)` | `neutral-850` | 호버 카드, 고정 헤더 |
| `elevation-2` | `0 4px 12px oklch(0.2 0.01 168 / 0.08)` | `neutral-800` + 테두리 | 드롭다운, 팝오버, 툴팁 |
| `elevation-3` | `0 12px 32px oklch(0.2 0.01 168 / 0.12)` | `neutral-800` + 강한 테두리 | 모달, 커맨드 팔레트, 드로어 |

색이 들어간 그림자(그린 그림자 등)는 쓰지 않습니다.

#### 모션

| 토큰 | 값 | 용도 |
|---|---|---|
| `--duration-instant` | 80ms | 버튼 눌림, 체크박스 |
| `--duration-fast` | 140ms | 호버, 툴팁, 포커스 링 |
| `--duration-base` | 220ms | 드롭다운, 아코디언, 탭 전환, 피드백 배너 등장 |
| `--duration-slow` | 320ms | 드로어, 모드 전환, 패널 접기 |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 대부분의 전환 (빠르게 시작, 부드럽게 정지) |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 사라지는 요소 |
| `--ease-emphasized` | `cubic-bezier(0.3, 0, 0, 1.15)` | 정답 체크 아이콘, 숙련 단계 상승 (약한 오버슈트) |

규칙:

- 320ms를 넘는 애니메이션은 쓰지 않습니다. 반복 애니메이션은 로딩 표시에만 씁니다.
- **`prefers-reduced-motion: reduce`** 일 때: 이동·크기 변화 애니메이션을 끄고 80ms 불투명도 전환만 남깁니다. 진도 링 채움, 개념 타일 상승 효과도 즉시 상태로 바뀝니다.
- 피드백 결과(정답·오답)는 애니메이션이 끝나기를 기다리지 않고 즉시 읽을 수 있어야 합니다(라이브 영역 알림은 애니메이션과 독립).

#### 아이콘

- [Lucide](https://lucide.dev/) 아이콘을 기본으로 씁니다(선 두께 1.75px, 16/20/24px). 숙련 단계 아이콘과 로고는 자체 제작합니다.
- 아이콘만 있는 버튼은 반드시 `aria-label`과 툴팁(단축키 포함)을 가집니다.

### 컴포넌트

컴포넌트는 Radix 프리미티브를 기반으로 `packages/ui`(기본)와 `packages/exercise-ui`(문제 유형 렌더러)에 둡니다([시스템 아키텍처 모노레포 구조](/docs/design/system-architecture.md#모노레포-구조)).
모든 대화형 컴포넌트는 아래 공통 상태를 정의합니다: **기본, 호버, 포커스(키보드), 눌림, 선택, 비활성, 로딩, 오류**.
포커스 상태는 2px `--color-focus-ring` + 2px 오프셋 링이며, `:focus-visible`일 때만 표시합니다.

1.  **시작**: 첫 단원 카드 + "오늘의 학습" 미리보기 → 학습 화면 진입.

상태: 각 단계 진입 시 첫 입력에 포커스. AI 연결은 브라우저 OAuth 창을 열고 진행 중 상태(취소 가능)를 표시. 실패 시 원인과 "나중에 설정에서 연결" 안내.

- **개념 지도**([FR-DASH-02](/docs/product/prd.md#대시보드와-통계-dash)): 모듈을 행으로, 개념을 학습 순서대로 타일로 나열합니다. 선수 관계 그래프 전체를 노드-간선 다이어그램으로 그리지 않는 이유는 [검토한 대안](#개념-지도-표현)에 있습니다. "보기" 메뉴: 모듈별(기본) / 복습 예정만 / 약점만. 타일 클릭 → 개념 상세 시트.
- **목표 페이스**(목표 완료일을 정한 경우): 학습 엔진의 `PaceStatus`를 문장으로 보여줍니다. `on_track` "이 페이스면 목표일 전에 끝나요"(neutral), `tight` "조금 빠듯해요. 하루 n분이면 맞출 수 있어요"(neutral), `behind` "목표일을 맞추려면 하루 n분이 필요해요"(amber), `overdue` "목표일이 지났어요. 새 목표일을 정할까요?"(amber + [목표 수정]). 빨간색이나 경고 아이콘은 쓰지 않습니다.

- **과정 진도**: ProgressRing + 단계별 개념 수. 진도율은 "완료한 단원 비율", 숙련 분포는 별도 숫자로 보여줘 두 개념을 혼동하지 않게 합니다.
- **최근 활동**: 최근 5개 세션 요약.
- **구현 메모 (v1.0, [D-061](/docs/decisions.md))**: "세션"은 연습 세트입니다(학습 세션 테이블 없이 기존 기록에서 파생, `GET /activity/recent`). 행마다 "오늘 14:20 · 어제 14:20 · 11/11"과 세트 이름("화살표 함수 연습", "복습 6개 개념", "약점 집중: …", "… 단원 평가"), 아래 줄에 숫자("7문제 · 정답 5 · 숙련 상승 2", 진행 중·중단)를 씁니다. 통과한 단원 세트는 "단원 완료" 배지를 붙이고, 세트 없이 끝난 단원(프로젝트)은 "… 단원 완료" 행입니다. 진행 중인 단원 평가는 "3/8문항 답함 · 진행 중"만 보이고 정답 수는 끝난 뒤에 보입니다. 기록이 없으면 "아직 활동이 없어요" 안내를 보여 줍니다. 과정 진도(5열) 옆 7열이고 약점 개념 카드는 아래 한 줄 전체입니다. "전체 보기 →"는 전체 기록 화면이 없어 뺐습니다.

"숙련까지" 줄은 학습 엔진의 게이트 조건([FR-LRN-03](/docs/product/prd.md#학습-엔진-lrn))에서 아직 충족하지 못한 항목(`missing`)을 학습자 언어로 보여줍니다. 숫자 점수보다 단계와 "다음 단계까지 필요한 것"을 주로 보여주며, 근거 목록의 각 줄은 숙련도 근거의 이유 코드(`why`)를 문장으로 바꾼 것입니다([학습 엔진 설계](/docs/design/learning-engine.md#설명-가능성)).

상태:

| 상태 | 표현 |
|---|---|
| 첫 실행 직후(기록 없음) | 오늘의 학습에 "첫 단원 시작하기" 한 항목만. 개념 지도는 모두 `◌`로 표시하고 "학습하면 여기가 채워져요" 안내 |
| 복습 없음 | 복습 카드에 "오늘 복습할 개념이 없어요. 다음 복습: 내일 3개" |
| 로딩 | 카드별 스켈레톤(300ms 이후) |
| 서버 연결 실패 | 페이지 오류 상태: "ProgInOne 서버에 연결할 수 없어요. 터미널에서 실행 중인지 확인해 주세요." + 다시 시도 |

#### 과정 목록과 과정 상세

과정 목록은 인프런식 카드 그리드입니다. 카드: 과정 아이콘(언어 로고 대신 자체 기하 아이콘), 제목, 한 줄 소개, 단원 수, 예상 총 시간, 진도 막대, 숙련 분포 미니 막대. 가격·평점은 없습니다.

명세:

- **선수 개념 경고**([FR-CUR-05](/docs/product/prd.md#커리큘럼과-콘텐츠-cur), v0.3 구현, [D-052](/docs/decisions.md)): 단원이 소개하는 개념의 직계 `required` 선수 개념 중 약한 것(학습 엔진 재학습 규칙과 같은 기준: 유효 숙련도 60 미만 또는 `practicing` 미만)이 있으면 제목 아래에 막지 않는 안내 상자를 둡니다. 제목 "먼저 ‘형 변환’부터 확인하면 더 쉬워요"(두 개까지 이름, 나머지는 "외 n개"), 본문 "…그대로 읽어도 괜찮아요.", 개념마다 MasteryIcon·단계·숙련도와 **개념 보기**(개념 상세), **‘…’ 단원 보기**(그 개념을 소개하는 단원), **약점 연습**(한 번이라도 푼 개념만: 약점 집중 세트는 풀어 본 개념만 약점으로 봄). amber(`--color-warning-*`) 상자와 아이콘이며 빨간색은 쓰지 않습니다. 제목이 있는 `section`이라 랜드마크 목록에서 찾을 수 있고, 페이지를 열 때 낭독을 가로채지 않도록 라이브 영역이 아닙니다. 닫기 버튼은 두지 않습니다(본문을 가리지 않고, 선수 개념이 익숙해지면 저절로 사라짐).
- **선수 개념 확인 섹션**([FR-CUR-02](/docs/product/prd.md#커리큘럼과-콘텐츠-cur)): 콘텐츠의 빈 `prerequisites` 섹션에 선수 개념(직계 `required` → `helpful` → `lesson.yaml`의 `reviewed`, 단원이 소개하는 개념 제외)을 MasteryIcon·단계·숙련도(푼 적이 있을 때)·요약과 개념 상세 링크로 보여 줍니다. 약한 `required` 개념에는 "먼저 확인하면 좋아요"를 덧붙입니다. 숙련도를 불러오기 전이나 실패하면 `reviewed` 개념의 제목·요약만 보여 줍니다(단원은 항상 열림).
- **전문성 역전 대응**: 이 단원의 모든 개념이 `proficient` 이상이면 상단에 "이미 잘 알고 있는 내용이에요. 요약만 보고 바로 연습할까요?" 배너 + 섹션 기본 접힘.
- **인라인 확인 문제**: 객관식·빈칸 등 짧은 유형만. 제출 즉시 피드백. 결과는 숙련도에 반영됩니다(가중치는 학습 엔진이 결정).
- **선택해서 질문**: 본문 텍스트나 코드를 선택하면 작은 팝오버 "튜터에게 질문 (⌘J)". 선택 영역이 ContextChip으로 붙은 채 드로어가 열립니다.
- **읽음 추적**: 섹션이 화면에 일정 시간(본문 길이 기반) 머물면 목차에 읽음 표시. 다 읽지 않아도 연습으로 넘어갈 수 있습니다.
- 단원 끝 **"떠올려보기"**: 요약을 보여주기 전에 "이 단원의 핵심 두 가지를 떠올려보세요"라는 접힌 카드를 둡니다. 펼치면 요약이 나옵니다(인출 연습).

| 파슨스(순서 배열) | 1열 중앙, 좌우 2칸 | 왼쪽 "코드 조각", 오른쪽 "내 답안". 조각 버튼(Enter로 답안 끝에 추가), 답안 목록(↑↓로 줄 고르기, Alt+↑↓로 옮기기, Alt+←→ 또는 `[`/`]`로 들여쓰기, Delete로 되돌리기)과 같은 동작의 버튼 묶음. 드래그는 보조 수단([D-031](/docs/decisions.md)). "필요 없는 조각이 섞여 있을 수 있어요"를 항상 표시 |

| 함수 구현, 버그 수정 | **2열** (문제 | 에디터 + 테스트/콘솔) | 위 와이어프레임 |

#### 콘솔 패널

실습 모드의 `[콘솔]` 탭, 레슨의 `RunnableExample` 출력, 미리보기 아래 콘솔이 같은 **ConsoleView** 를 씁니다.
입력 데이터는 샌드박스의 `RunResult.console`([코드 실행 샌드박스 설계](/docs/design/code-execution-sandbox.md#직렬화-형식-serializedvalue))입니다.

- **값 표시**: `SerializedValue`를 ProgInOne 콘솔 형식으로 한 줄 미리보기하고, 객체·배열·Map·Set은 ▸로 펼치는 트리로 보여줍니다. 함수는 `ƒ name()`, DOM 노드는 태그 미리보기, 순환 참조는 `[Circular]`, getter는 `(getter)`로 표시합니다.
- **잘림 안내**: 컬렉션 항목·문자열이 잘린 값은 끝에 `… 외 n개`를 붙입니다. 실행 출력이 상한(1,000개, 1MB)을 넘으면 목록 끝에 "출력이 너무 많아 1,000개만 표시합니다 (n개 생략)"를 고정 표시합니다.
- **대체 구현 표시**: `alert`/`confirm`은 모달 대신 콘솔에 아이콘이 붙은 항목으로 표시합니다(`confirm`은 미리 정한 응답값을 함께 표시). `prompt`는 콘솔 위의 **입력값 패널**("prompt에 줄 값: [ ] [+]")에서 미리 입력한 값을 차례로 돌려주며, 값이 모자라면 `null`을 돌려주고 그 사실을 콘솔에 안내합니다.
- **실행 상태**: 헤더에 "실행 중", "타이머 대기 중 (n개)", "완료 · 12ms", "중단됨 — 시간 제한 3초", "반복이 너무 오래 실행되어 멈췄어요 (n번째 줄)", "실행 환경 오류 — 다시 실행해 주세요"(`crashed`)를 `RunResult.status`와 1:1로 표시합니다. 실행 중에는 [중지] 버튼을 보여줍니다.
- **오류**: 오류 이름과 메시지를 한국어 설명과 함께 보여주고, 위치(파일:줄)를 누르면 에디터의 해당 줄로 이동합니다.
- 접근성: 새 출력은 `aria-live="polite"`로 묶어서(배치 단위) 알리고, 출력 폭주 시에는 "출력 n개 추가됨" 요약만 알립니다.

명세:

- 스레드는 단원·문제 단위입니다([FR-AI-07](/docs/product/prd.md#ai-튜터-ai)). 헤더에 현재 스레드의 맥락을 표시하고, `⋯` 메뉴에서 이전 스레드 보기·새 스레드를 엽니다.
- **ContextChip**: 튜터에게 전달되는 맥락을 보여주고 제거할 수 있게 합니다(투명성, 개인정보). `＋`로 콘솔 출력 등 추가.
- **빠른 질문 버튼**은 맥락별로 바뀝니다: 오답 직후에는 "왜 틀렸나요?", 읽기 모드에서는 "다른 예시로 설명해줘요".
- 스트리밍 중에는 "응답 중… [중단]". 중단 시 부분 응답을 보존합니다.
- 힌트 정책 때문에 정답을 주지 않을 때, 튜터 메시지 하단에 작은 안내를 표시해 혼란을 줄입니다: "정답 코드는 힌트 3단계 이후에 볼 수 있어요".
- **선제 제안**([D-010](/docs/decisions.md)): 반복 실패·장시간 정체·확신 오답 시 드로어를 자동으로 열지 않고, 헤더의 튜터 버튼에 violet 점과 툴팁 "도움이 필요하면 물어보세요"를 표시합니다. 설정에서 끌 수 있습니다.
- 후처리 검증에서 정답 누설 등으로 숨김 처리된 응답(`tutor_messages.status = 'withheld'`)은 "이 답변에는 아직 보여줄 수 없는 정답이 포함되어 숨겼어요. 질문을 조금 바꿔보거나 힌트를 열어보세요."로 표시합니다. 중단된 응답(`cancelled`)은 부분 응답 아래 "(중단됨)"을 붙입니다.
- AI 생성 문제에는 문제 헤더에 violet `AI 생성` 배지를 붙이고, 아직 `trusted`가 아니면 툴팁으로 "자동 검증을 통과한 AI 생성 문제예요"를 표시합니다.
- AI가 연결되지 않았으면 드로어 본문 대신 연결 안내 EmptyState를 보여줍니다. 한도 도달 시 "AI 사용량 한도에 도달했어요. 14:30에 다시 쓸 수 있어요. 그동안 힌트와 해설은 계속 볼 수 있어요."
- **구현 메모 (v0.1)**:
  - 드로어는 Radix 오버레이(`packages/ui` Drawer)가 아니라 학습 화면 레이아웃 안의 `<aside>`입니다. 1280px 이상에서는 본문을 밀어내고(sticky, 헤더 아래), 그 미만에서는 오른쪽에 고정된 오버레이가 됩니다. 폭은 360~560px(기본 400, 1920px 이상 480), 핸들은 `←`/`→` 10px·`Home`/`End`·더블클릭 기본값, `localStorage`에 기억합니다.
  - 헤더 튜터 버튼(`⌘J`)은 AI 상태와 관계없이 열 수 있습니다. 대화 기록은 AI 없이도 볼 수 있고, 연결이 필요하면 드로어가 이유와 설정 링크를 보여 주며 입력란을 끕니다. "선택해서 질문하기" 팝오버와 AI 힌트처럼 AI를 바로 부르는 진입점은 비활성 + 이유 툴팁입니다.
  - 스레드는 실습 문항이 열려 있으면 그 문제(`exercise`), 아니면 단원(`lesson`)입니다. 복습 세트도 문항별 `exercise` 스레드를 씁니다. `⋯` 메뉴(이전 스레드·새 스레드)는 서버에 스레드 닫기 API가 없어 v0.2로 미룹니다.
  - ContextChip: "현재 문제"/"이 단원"(고정), "내 코드"·"실행 결과"(빼기 가능, 문항이 바뀌면 다시 켬), 선택 칩(`선택한 코드 3줄`/`선택한 텍스트 42자`, 질문과 함께 한 번 보냄). 학습자 코드·실행 결과는 보낼 때 읽고 요청 스키마 한도로 자릅니다.
  - 스트리밍은 `fetch` 스트림으로 읽고 `delta`를 누적 렌더링합니다. `reset`은 지금까지의 글을 지우고, 끊기면 저장된 대화를 다시 불러와 서버가 마칠 때까지 확인합니다. 중단은 메시지 ID가 오기 전에 눌러도 ID가 오는 즉시 보냅니다. 스트림 전에 거절되면(AI 미연결, 평가 잠금) 질문과 선택 칩을 입력란에 되돌립니다.
  - 낭독: 대화 목록은 라이브 영역이 아니고, 별도 `aria-live="polite"` 영역이 **완성된 문단 단위**로 읽습니다(코드 블록은 "코드 예시"로 요약). 중단·숨김·실패는 짧은 문장으로 알립니다.
  - AI 출력 마크다운은 React 요소만 만드는 자체 렌더러입니다(`react-markdown` 대신, 원시 HTML은 글자 그대로). 제목은 실제 제목 요소가 아니라 굵은 문단으로 그려 페이지 개요를 바꾸지 않고, 링크는 `http(s)`만 새 탭으로, 이미지는 대체 텍스트만, 코드 블록은 복사 버튼만 둡니다(실행하지 않음).
- **구현 메모 (v0.3, [D-051](/docs/decisions.md))**: 선제 제안은 실습 문항에서 (1) 재학습 제안(`remediation`, 반복 실패)이 나오거나 (2) "확실해요"로 낸 답이 틀렸을 때 켭니다. 헤더 튜터 버튼에 violet 점(`--color-ai-accent`)과 툴팁 "도움이 필요하면 물어보세요"를 붙이고, 같은 문장을 버튼의 스크린 리더 이름에도 넣습니다(색이나 툴팁만으로 전하지 않음). 드로어는 열지 않으며, 학습자가 드로어를 열면 꺼집니다. 설정 > 학습 방식 > 튜터 선제 제안을 끄면 켜지 않고, 진행 중인 단원 평가에서는 켜지 않습니다. "장시간 정체"는 활동 측정과 함께 정할 기준이 없어 아직 쓰지 않습니다. 재학습 카드의 튜터 안내(`tutorBadge`)는 그대로 둡니다.

- 항목은 시도에서 파생됩니다([용어집 `MistakeNote`](/docs/glossary.md#학습-기록-용어)).
- "확실했어요 ⚠" 표시는 확신 오답(과잉 교정 기회)을 강조합니다. 기본 정렬에서 확신 오답을 위로 올리는 옵션을 제공합니다.
- **과거 풀이와 비교**(P1): 코드 문제는 과거 제출과 현재 제출을 diff로, 객관식은 이전 선택과 현재 선택을 나란히 표시합니다.
- "비슷한 문제 풀기"는 같은 개념·유형의 미사용 문제 또는 템플릿 변형을 냅니다(AI 생성은 사용자가 고를 때만).

#### 약점 집중

- 숙련도가 낮거나 오개념이 확정된 개념 목록(최대 10개)을 보여주고, 선택한 개념으로 연습 세트를 만듭니다.
- 각 개념에 "왜 약점인가요?" 펼침: 최근 오답 패턴, 관련 오개념, 선수 개념 상태.
- 선수 개념이 원인으로 보이면 "선수 개념 ‘형 변환’부터 확인해요" 경로를 먼저 제안합니다(재학습 경로).

구현 메모 (v0.3, [D-044](/docs/decisions.md)·[D-046](/docs/decisions.md)): 복습 허브는 네 구역입니다. `/review`(오늘의 복습), `/review/mistakes`(오답 노트, 상세는 `/review/mistakes/:exerciseId`), `/review/weak`(약점 집중), `/review/progress`(숙련도 변화). 구역은 주소가 다른 화면이라 ARIA 탭이 아니라 `aria-current` 링크 목록(`nav "복습 화면"`)입니다.

- **오답 노트**: 필터(과정·모듈·개념, "아직 못 맞힌 것만")와 정렬(최근순·확신 오답 먼저)은 주소에 남깁니다(`?course=…&open=true&sort=confident`). 유형·기간 필터는 노트 수가 적은 v0.3에서는 빼고, 개수 요약("오답 n개 · 아직 못 맞힌 것 n개 · 다시 맞힌 것 n개")과 20개씩 "더 보기"를 둡니다. 항목은 ✕ 또는 ✕ → ✓ 아이콘에 화면 읽기용 "아직 못 맞힌/다시 맞힌 오답"을 붙이고, 날짜·"n번 틀림"·"단원 평가"·"확실했어요 ⚠"·지문 첫 줄·오개념 이름을 보여 줍니다. 못 맞힌 노트가 둘 이상이면 "못 맞힌 문제 n개 다시 풀기"(최대 10개).
- **노트 상세("풀이 다시 보기")**: 문제 → 내 답(최근 것, 이전 오답은 접어 둠, 시도 맥락·확신도·힌트 단계·당시 피드백·고른 답의 오개념) → 해설 → 정답 순서입니다. 정답은 학습자가 이미 본 경우에만 보이고(출처 문장 포함), 아니면 "정답은 다시 풀면서 확인해요"와 자물쇠입니다.
- **다시 풀기**는 그 문제 하나로 만든 세트를 세트 화면(`/review/session/:setId`, 제목 "다시 풀기")에서 풀고, 끝나면 "오답 노트로"를 보여 줍니다. 평가 전용 문항처럼 다시 풀 수 없는 노트에는 "비슷한 문제 풀기"(그 개념의 약점 집중 세트)만 둡니다. 원래 설계의 "비슷한 문제 풀기"(같은 개념·유형의 미사용 문제)는 약점 집중 세트가 대신합니다. **과거 풀이와 비교**(P1)는 아직 없습니다.
- **약점 집중**: 대시보드 카드(상위 5개)와 달리 최대 10개를 모두 보여 주고, 엔진 추천을 미리 고른 채 최대 5개까지 고릅니다(약점 집중 요청의 최대). 약한 선수 개념이 있으면 행 아래에 "선수 개념 ‘…’부터 확인해요"와 개념 상세 링크를 먼저 보여 줍니다. "왜 약점인가요?"는 숙련도·연속 오답·오개념 상태·선수 개념 상태와 "이 개념의 오답 보기"(오답 노트 개념 필터)입니다.
- **숙련도 변화**: 최근 8주 주별 막대(기준선 위 상승 jade, 아래 하락 회색. 하락을 빨강으로 칠하지 않음)와 "표로 보기", 최근 바뀐 개념 20개(↑/↓ + 단계 아이콘 + 개념 상세 링크)입니다. 막대는 위치·범례·화면 읽기용 문장으로도 방향을 알 수 있습니다.
- 빈 상태: 오답 노트 "아직 틀린 문제가 없어요"([연습하러 가기]), 필터 결과 없음 "조건에 맞는 오답이 없어요"([필터 지우기]), 약점 "아직 약점이 없어요"([오답 노트 보기]), 숙련도 변화 "아직 숙련 단계가 바뀐 개념이 없어요". 오늘의 복습 빈 상태에 "약점 집중" 링크를 더했습니다.

#### 설정

왼쪽 섹션 목록 + 오른쪽 내용의 2열 구성입니다.

AI 연결 섹션:

```text
│ AI         ┌ AI 튜터 연결 ─────────────────────────────────────────────┐ │
│ 학습 방식  │ ● 연결됨 · ChatGPT Pro (user@…)            [ 연결 해제 ]    │ │
│ 학습 목표  │ 제공자: Codex App Server  v0.xx  ✓ 지원 버전                 │ │
│ 화면       │                                                            │ │
│ 데이터     │ 모델   [ gpt-… (기본) ▾ ]   추론 강도 [ 보통 ▾ ]             │ │
│ 정보       │                                                            │ │
│            │ 사용량                                                      │ │
│            │ 5시간 한도   ████████░░░░  64%   14:30 초기화                 │ │
│            │ 주간 한도    ███░░░░░░░░░  27%   11/18 초기화                 │ │
│            │                                                            │ │
│            │ AI에 전송되는 정보 (P1)  [ 미리보기 ]                         │ │
│            └────────────────────────────────────────────────────────────┘ │
```

- 사용량 막대는 `account/rateLimits/read` 결과를 표시합니다([AI 시스템 설계](/docs/design/ai-system.md)). 80% 이상 amber, 100% red + 텍스트.
- 상태별 표현: 연결 안 됨(연결 버튼 + 설명), Codex CLI 미설치(설치 안내 링크와 명령), 지원하지 않는 버전(업데이트 안내), 로그인 진행 중(취소), 오류(오류 코드 + 다시 시도).
- **로그인 대화상자**: [연결]을 누르면 서버가 Codex 로그인(`chatgpt`)을 시작하고 브라우저 새 탭으로 ChatGPT 로그인 페이지를 엽니다. 대화상자는 "브라우저에서 로그인을 마쳐 주세요" + 진행 표시 + [취소]를 보여주고, 완료 이벤트(`GET /api/v1/ai/events`)를 받으면 닫힙니다. 새 탭이 열리지 않는 환경을 위해 "다른 방법으로 로그인"(기기 코드: 확인 URL과 코드 표시, 복사 버튼)을 제공합니다([AI 시스템 설계](/docs/design/ai-system.md)).
- 사용량 수치는 Codex가 알려준 값만 표시합니다. 80% 이상이면 "AI 문제 생성 등 백그라운드 작업은 잠시 미뤄요", 95% 이상이면 "튜터 대화만 쓸 수 있어요" 안내를 막대 아래에 붙입니다.
- **구현 메모 (v0.1)**: 계정 표시는 플랜 종류만입니다(`연결됨 · ChatGPT Pro`, 이메일 없음, [AI 시스템 설계](/docs/design/ai-system.md#구현-메모-v01)). 모델은 목록만 보여 주고 선택은 v0.2(`settings.ai.model`)입니다(v1.0에서 구현, 아래). 제공자 버전 행과 "다른 방법으로 로그인"(기기 코드)은 서버 계약에 아직 없어 v0.2로 미룹니다. 앱 전체가 `GET /ai/events`(fetch 스트림, 세션 토큰 헤더) 하나로 상태를 공유하고, 헤더 AIStatusIndicator는 그 스냅샷만 읽어 Codex를 시작하지 않습니다. 설정 AI 섹션을 열 때(그리고 튜터를 처음 쓸 때)만 `GET /ai/status`로 지연 시작합니다. `idle`은 "대기 중"(처음 질문할 때 연결)으로 보여 주고 AI 진입점을 막지 않습니다. 새 탭은 클릭 순간 `about:blank`로 열어 팝업 차단을 피하고 `opener`를 끊은 뒤 `http(s)` 주소일 때만 이동합니다.
- **구현 메모 (v0.3, [D-051](/docs/decisions.md))**: "AI에 전송되는 정보"의 설명(NFR-08)은 AI 연결 카드 아래의 별도 카드 "AI에 보내는 정보"입니다. 연결 상태와 관계없이 보여서 연결 전에 읽을 수 있습니다. 보내는 것(AI를 쓸 때만: 질문과 현재 레슨·문제, 내 코드·실행 결과(튜터 칩으로 뺄 수 있음), 관련 개념 숙련도·진행 중인 오개념·이 문제의 최근 풀이, 이전 대화와 요약, 이미 열어 본 만큼의 힌트·정답, 평가 중 AI 잠금), 보내지 않는 것(계정 정보, 다른 문제의 코드, 학습 목표·학습 시간, 설정, 백업), OpenAI 데이터 정책 안내를 적습니다. 마지막 호출의 맥락 섹션 미리보기는 P1으로 남깁니다.
- **구현 메모 (v1.0, [D-060](/docs/decisions.md))**: "모델"은 선택 상자 대신 라디오 그룹 "튜터와 AI 기능이 쓸 모델"입니다. 선택지마다 표시 이름(기본 모델은 "(기본)"), 설명과 지원 추론 강도("추론 강도 낮음·보통·높음")를 보여 줍니다. 고르면 바로 저장하고(기본 모델은 `null`), "바꾼 모델은 다음 질문부터 쓰여요"를 덧붙입니다. 저장한 모델이 목록에 없으면 위에 경고 상자(`role="status"`)로 "저장한 모델(…)을 더 이상 쓸 수 없어서 기본 모델(…)로 답해요. 다른 모델을 고르면 바뀌어요."를 보여 주고 기본 모델을 선택된 상태로 표시합니다. 추론 강도 선택은 아직 없습니다.

데이터 섹션:

```text
│            ┌ 자동 백업 ───────────────────────────────────────────────┐ │
│            │ ✓ 켜짐 · 마지막 백업 오늘 09:12 · 보관 일일 14개 + 주간 8개 │ │
│            │ 위치  ~/Library/Application Support/ProgInOne/backups [변경] │ │
│            │                                     [ 지금 백업 ]          │ │
│            │ 백업 목록                                                  │ │
│            │  11/13 09:12  일일   2.4MB                    [ 복원 ]     │ │
│            │  11/12 08:40  일일   2.3MB                    [ 복원 ]     │ │
│            │  11/10 21:02  업데이트 전  2.3MB              [ 복원 ]     │ │
│            └──────────────────────────────────────────────────────────┘ │
│            ┌ 내보내기·가져오기 (P1) ┐  ┌ 학습 데이터 초기화 ─────────────┐ │
```

- 복원은 AlertDialog로 확인합니다: "11/12 08:40 상태로 되돌려요. 그 이후 기록은 사라지지만, 복원 직전 상태를 따로 백업해 둘게요."
- 초기화는 "초기화"를 직접 입력해야 활성화되는 위험 버튼입니다.
- 백업 위치를 클라우드 동기화 폴더로 바꾸면 "백업에는 AI 대화 원문이 포함돼요" 안내([시스템 아키텍처 개인정보](/docs/design/system-architecture.md#개인정보)).
- **구현 메모 (v0.3, [D-045](/docs/decisions.md))**: 백업 목록 행은 시각 · 종류 배지 · `v앱 버전 · DB 스키마 번호` · 크기 · [복원]입니다. 복원 대화상자는 열리자마자 서버 검사(`GET /backups/:id/check`)를 보여 주고("파일을 확인했어요", 이전 버전 백업이면 "복원한 뒤 데이터 형식을 지금 버전에 맞게 바꿔요"), 손상·새 버전 백업이면 이유와 함께 [복원]을 끕니다. 위치 [변경]은 경로 입력 대화상자입니다(브라우저는 로컬 서버를 위한 폴더 선택 창을 열 수 없음): 현재 경로가 미리 채워지고, 입력이 클라우드 동기화 폴더처럼 보이면 저장 전에 대화 원문 안내를, 서버가 거부하면 이유를 입력란 오류로 보여 줍니다. 바꾼 뒤에는 "이전 위치의 백업은 그대로 남아 있어요: <경로>"를 표시합니다. 환경 변수로 고정된 위치는 [변경]이 `aria-disabled` + 툴팁입니다. 초기화 카드는 지우는 것(진도·풀이 기록·숙련도와 복습 일정·오개념·튜터 대화·학습 목표)과 남기는 것(화면·학습 방식 설정, 백업)을 적고, `"초기화"를 입력하세요` 입력란이 정확히 일치할 때만 위험 버튼이 켜집니다. 성공하면 "초기화 전 백업으로 남겨 두었어요" 토스트와 함께 온보딩으로 이동합니다.

학습 방식 섹션: 에디터 자동 완성(기본 끔, 초보자 근거 설명 포함), 확신도 입력(기본 켬), 튜터 선제 제안(기본 켬), 예측 후 실행 강제(기본 "권장": 건너뛰기 링크 제공), 레슨 본문 글자 크기.

- **구현 메모 (v0.3, [D-047](/docs/decisions.md))**: `/settings/learning`(학습 방식)은 카드 네 개입니다. 문제 풀이(확신도 묻기 체크박스, 힌트 정책 라디오 "기본"/"먼저 풀어 보기"), 코드 에디터(자동 완성), 레슨 예제(예측 후 실행 "권장"/"필수"), AI 튜터(선제 제안). 레슨 본문 글자 크기와 작업대 테마는 사이트맵대로 `/settings/appearance`(화면)에 둡니다(작게 16px·보통 17px·크게 19px, 작업대 밝게·어둡게). 바꾸면 저장 버튼 없이 바로 저장하고, 실패하면 토스트로 알립니다. 각 설정은 실제 기능에 연결됩니다: 확신도 끔 → 연습·복습·평가·본문 확인 문제가 "제출" 단일 버튼과 `confidence: null`, 자동 완성 → 실습 코드 에디터, 예측 "필수" → 예제의 "예측 건너뛰기" 숨김, 선제 제안 끔 → 재학습 카드의 튜터 배지 숨김, "먼저 풀어 보기" → 그 문항에 한 번 제출하기 전까지 힌트 사다리가 잠김("한 번 답을 제출해 본 뒤에 열려요", 서버도 `409 EXERCISE_TRY_FIRST`로 거부. 힌트 1단계를 스스로 여는 쉬운 재학습 문항은 예외), 글자 크기 → `--lesson-font-size`, 작업대 어둡게 → `<html data-workbench="dark">`.

모든 화면과 패널은 아래 상태를 정의합니다([FR-UI-03](/docs/product/prd.md#전역-ui-ui)).

| 상태 | 규칙 | 예 |
|---|---|---|
| 로딩 | 300ms 이내 응답은 표시 없음, 300ms 이후 스켈레톤, 3초 이후 진행 문구 | "문제를 준비하고 있어요…" |
| 빈 상태 | 이유 + 다음 행동 1개. 일러스트 대신 라인 아이콘 | 오답 노트: "아직 틀린 문제가 없어요. 문제를 풀면 여기에 모여요." [연습하러 가기] |
| 오류(인라인) | 필드·패널 안에서 원인과 해결 행동 | 실행 시간 초과: "코드가 3초 안에 끝나지 않았어요. 무한 반복이 있는지 확인해 보세요." [반복문 찾기 도움말] |
| 오류(페이지) | 페이지 전체 대체, 오류 코드 작게 | 서버 연결 실패, 콘텐츠 없음 |
| 오프라인·AI 불가 | AI 관련 요소만 비활성 + 이유 | 튜터 버튼 비활성 툴팁: "AI 연결이 필요해요" |
| 부분 성공 | 저장 실패 등 | "답안은 채점됐지만 기록 저장에 실패했어요. [다시 저장]" |

러너 관련 오류 문구는 [코드 실행 샌드박스 설계](/docs/design/code-execution-sandbox.md)의 종료 사유(`RunResult`)와 1:1로 매핑합니다.

### 학습 인터랙션 설계

#### 예측 후 실행

PRIMM의 Predict–Run 단계를 레슨 예제와 결과 예측 문제에 적용합니다.

1.  RunnableExample은 처음에 **실행 버튼이 "예측하고 실행"** 입니다. 출력 예측 입력란에 포커스가 갑니다.
1.  학습자가 예측을 입력하고 실행하면 실제 출력과 줄 단위로 비교합니다: 일치 줄 ✓, 불일치 줄은 "예측 / 실제"를 나란히.
1.  불일치가 있으면 "왜 다를까요?" 링크(튜터 질문 미리 채움)와 관련 섹션 링크를 보여줍니다(Investigate).
1.  "예측 없이 실행" 작은 링크를 제공합니다. 설정이 "필수"이면 숨깁니다.
1.  예제 코드는 실행 후 편집 가능해져 "바꿔서 실행해보기"를 유도합니다(Modify).

레슨 예제의 예측 결과는 숙련도에 반영하지 않고(학습 중 탐색이므로), 결과 예측 **문제** 만 반영합니다.

#### 확신도 입력 타이밍

- **답을 정한 뒤, 정답을 보기 전** 에 묻습니다. 정답 공개 후에 묻는 것은 의미가 없기 때문입니다.
- 별도 단계를 늘리지 않기 위해 **제출 버튼 자체를 확신도 버튼으로 나눕니다**:

```text
답을 골랐다면, 얼마나 확신하나요?
[ 확실해요  ⌘Enter ]   [ 애매해요 ]   [ 찍었어요 ]
```

- 키보드: ⌘Enter = 확실해요(가장 흔한 경로), 그 밖에는 Tab으로 이동. 객관식 번호 키(1~5)와 충돌하지 않도록 확신도에는 숫자 키를 쓰지 않습니다.
- 확신도는 개념 이해·코드 이해 문제(객관식, 예측, 순서 배열, 오류 찾기)에서 묻고, 테스트로 채점하는 실습 문제에서는 **첫 제출에만** 묻습니다.
- 설정에서 끄면 "제출" 단일 버튼으로 바뀌고 확신도는 기록하지 않습니다(학습 엔진은 확신도 없음을 중립으로 처리).
- 피드백은 확신도에 따라 다릅니다:

| 결과 \ 확신도 | 확실해요 | 애매해요 | 찍었어요 |
|---|---|---|---|
| 정답 | "정답이에요." 간결하게 | "정답이에요. 근거를 한 번 더 확인해볼까요?" + 해설 펼침 권유 | "맞혔지만 찍었다고 했죠. 해설을 꼭 확인해보세요." 해설 기본 펼침 |
| 오답 | **"확신했는데 아니었네요. 이런 순간이 가장 잘 기억에 남아요."** + 오개념 설명 기본 펼침 | "아쉬워요." + 힌트·재도전 | "괜찮아요. 해설부터 보고 다시 풀어봐요." |

#### 피드백 타이밍

| 상황 | 타이밍 | 근거 |
|---|---|---|
| 레슨 인라인 확인 문제 | 즉시 | 초보자, 개념 형성 단계 ([Shute 2008][shute2008]) |
| 연습 세트 | 문항별 즉시 | 어려운 과제·초보자에게 즉각 피드백이 유리 |
| 실습 문제의 "실행" | 즉시(테스트 결과 포함) | 실행–수정 반복은 프로그래밍 학습의 핵심 루프 |
| 단원 평가 | **세트 종료 후 일괄**. 평가 중 힌트 버튼·튜터 드로어·정답 보기는 잠금 상태(비활성 + "평가가 끝나면 열려요" 툴팁) | 평가 목적, 앞 문항 피드백이 뒤 문항의 단서가 되는 것 방지. 독립 증거 확보([D-023](/docs/decisions.md)) |
| 복습 세트 | 문항별 즉시(정오) + 종료 후 개념별 요약 | 인출 연습 후 교정 피드백 |

피드백 문구 구조는 Hattie & Timperley의 세 질문(어디로 가는가, 지금 어디인가, 다음은 무엇인가)을 따릅니다: **결과 → 이유 → 다음 행동**.

#### 힌트 사다리

```text
─ 힌트 ──────────────────────────────────────────
① 방향        음수도 짝수일 수 있어요. 짝수 판별 조건을 다시 볼까요?
② 핵심 개념    n % 2 === 0 은 음수에서도 동작해요. 지금 코드는 n > 0 조건이 있네요.
[ 힌트 3/3 보기 ]   ← 다음 단계 버튼 (한 번에 한 단계만)
                    힌트를 볼수록 이 문제의 숙련도 반영이 조금 줄어요.
[ 정답 보기 ]       ← 힌트 3단계 이후에만 활성 (D-010)
```

- 단계는 순서대로만 열립니다. 이미 연 힌트는 다시 접히지 않고 쌓입니다.
- 힌트 원문은 문제에 저작된 힌트를 우선 씁니다. AI 힌트는 "AI에게 다르게 물어보기"로 별도 진입하며, 같은 힌트 단계 정책을 따릅니다([AI 시스템 설계](/docs/design/ai-system.md)). v0.1에서는 힌트를 하나 이상 연 뒤 열린 힌트 아래에 "AI에게 이 단계 다시 설명받기"가 나타나고(`POST /exercises/:id/ai-hint`, 단계를 올리지 않음), AI 힌트는 violet 표식과 `AI` 배지, 확인 질문과 살펴볼 줄을 함께 보여 줍니다. 서버가 저작 힌트로 대신하면 그 이유("AI가 연결되지 않아 작성된 힌트를 다시 보여 드려요")와 함께 AI 표식 없이 보여 줍니다.
- 숙련도 감소 안내는 처벌이 아니라 정보로 표현합니다. 수치는 보여주지 않습니다.
- "정답 보기" 확인 대화: "정답을 보면 이 문제는 나중에 비슷한 문제로 다시 나와요. 볼까요?" [정답 보기] [조금 더 해볼게요].
- 정답을 본 뒤에는 **같은 문제를 다시 풀어보기** 를 권유합니다(정답을 보고 직접 다시 써보는 것이 그냥 읽는 것보다 낫기 때문).

#### 재학습 유도

학습 엔진의 재학습 신호([FR-LRN-05](/docs/product/prd.md#학습-엔진-lrn))를 받으면 문제 패널 상단에 비모달 카드를 띄웁니다.

```text
┌ 잠깐 쉬어가요 ──────────────────────────────────────────────┐
│ 화살표 함수 문제를 연속으로 2번 틀렸어요. 막힐 수 있는 부분이에요.  │
│ 먼저 ‘함수 반환값’을 3문제로 짧게 확인해볼까요?                   │
│ [ 선수 개념 확인하기 (약 3분) ]  [ 풀이 예제 보기 ]  [ 계속 풀기 ]  │
└──────────────────────────────────────────────────────────────┘
```

- 학습자를 막지 않습니다. 세 선택지 모두 동등한 버튼이며, "계속 풀기"도 존중합니다.
- 실패 원인을 학습자 탓으로 돌리지 않는 문구를 씁니다: "어려운 부분이에요", "막힐 수 있는 부분이에요".
- **단계적 풀이 예제** 화면은 완성된 풀이(주석 설명 포함) → 일부 줄이 빈칸인 풀이 → 원래 문제 순서로 진행하며, 상단에 3단계 진행 표시를 둡니다.

#### 단원 평가 화면

구현 메모 (v0.3, [D-043](/docs/decisions.md)): 평가 단원의 "평가" 모드(`/learn/:lessonId?mode=practice`)는 세 화면입니다.

```text
┌ 시작 ─────────────────────────────┐  ┌ 진행 ──────────────────────────────────┐
│ 📋 값과 변수 단원 평가              │  │ 값과 변수 단원 평가   ● ● ○  2 / 3      │
│ 문항 15 · 개념 18 · 통과 80% · 30분 │  │ 문제 3  객관식  L2   (개념 이름 없음)    │
│ 평가 규칙                          │  │ … 문제와 답 …                          │
│ 🔒 힌트·AI 튜터·정답 보기 없음       │  │ [확실해요][애매해요][찍었어요]          │
│ 🔒 문항마다 한 번만 제출             │  │ 힌트 🔒 평가가 끝나면 열려요            │
│ 🔒 정답·해설은 끝나면 한꺼번에       │  │ 제출 후: "제출했어요. 정답과 해설은     │
│ 🔒 확신도는 솔직하게 · 건너뜀=오답   │  │ 평가가 끝나면…" [다음 문제]             │
│        [요점 다시 보기] [평가 시작]  │  └────────────────────────────────────────┘
└────────────────────────────────────┘
┌ 종료 ──────────────────────────────────────────────────────────────┐
│ 단원 평가를 마쳤어요 · 15문항 중 11문항 정답 (73%) · [통과 기준 미달] │
│ 개념별 결과 (틀린 개념 굵게) · 🎯 틀린 개념 약점 집중 [약점 집중 시작] │
│ 문항별 정답과 해설: ▸ 문제 1 [✓ 정답] … ▾ 문제 4 [✗ 오답] 정답 · 해설 │

└────────────────────────────────────────────────────────────────────┘
```

- **시작 화면**: 문항 수·다루는 개념 수·통과 기준·예상 시간(`GET /lessons/:id`의 `assessment`)과 평가 규칙 다섯 가지를 보여 주고, "평가 시작"을 눌러야 세트를 만듭니다(진행 중인 평가가 있으면 이어서). 읽기 모드 본문의 `practice` 섹션 버튼은 "단원 평가 보기", 헤더의 모드 이름은 "평가"입니다.
- **진행 중**: 튜터를 아예 띄우지 않습니다(드로어·`⌘J`·선택해서 질문하기 없음). 헤더의 튜터 버튼은 `aria-disabled` + 자물쇠 + "평가가 끝나면 열려요"(툴팁과 화면 읽기용 설명)입니다. 힌트 사다리는 잠긴 상태(`locked`)로 보이고, AI 힌트·정답 보기·개념 이름·"다시 풀기"는 없습니다. 제출하면 정오 대신 "제출했어요" 안내와 "다음 문제"를 보여 주고, 진행 표시의 점은 회색 "제출함"입니다. 제출한 문항으로 돌아가면 답 입력 없이 "이미 제출한 문항이에요"만 보입니다. "건너뛰기"는 기록되며 오답으로 셉니다. 마지막 제출이 끝나면 바로 종료 화면으로 바뀝니다.
- **종료 화면**: 점수와 통과 여부(배지는 글자와 함께), 개념별 정답 수, 틀린 개념이 있으면 "약점 집중 시작"(그 개념들로 약점 집중 세트를 만들어 세트 화면으로), 문항별로 결과 배지(정답·오답·건너뜀, 아이콘+글자)·문제·정답(`SolutionView`)·고른 답의 오개념·해설. 틀린 문항은 펼친 채로 시작합니다. "다시 응시"(새 세트, 처음 보는 문항 우선), 통과했으면 "다음 단원". 튜터가 다시 열립니다.

#### 프로젝트 화면

구현 메모 (v0.3, [D-049](/docs/decisions.md)): 프로젝트 단원(`kind: project`)의 "프로젝트" 모드(`/learn/:lessonId?mode=practice`)는 연습 세트 없이 웹 실습 하나를 계속 다듬는 작업 공간입니다.

```text
┌ 과제 ───────────────────────────────┐ ┌ 작업 공간 (웹 실습과 같음) ──────────────┐
│ 🔨 최종 프로젝트: 할 일 목록 [응용 프로젝트] │ │ index.html 편집기 · 미리보기 · 체크 목록 │
│ 마일스톤 6개 · 약 1시간 30분 · 채점 4번 │ │ (체크 목록은 "1단계 · 제목"으로 묶음)   │
│ 과제 설명(문제 본문)                  │ │                                        │
│ "마지막으로 채점한 코드에서 이어서 해요" │ │                                        │
├ 마일스톤 ── 6개 중 2개 통과 ━━━──────┤ │                                        │
│ ✓ 1단계 · 입력창 만들기        통과   │ │                                        │
│ ○ 2단계 · 항목 추가하기        아직 ◀ │ │                                        │
│ – 3단계 · …                  채점 전  │ │                                        │
├─────────────────────────────────────┤ │                                        │
│ [채점하기] 몇 번이든 다시 채점할 수 있어요 │ │                                        │
│ ✓ 새로 통과: 항목 추가하기             │ │                                        │
│ 피드백(단계 N개 중 M개 완료 · 다음 단계) │ │                                        │
│ 힌트 사다리 · AI 힌트 · 정답 보기        │ │                                        │
└─────────────────────────────────────┘ └────────────────────────────────────────┘
```

- **진입**: 읽기 모드 본문(과제 소개)의 `practice` 섹션 버튼은 "프로젝트 열기", 헤더의 모드 이름은 "프로젝트"입니다. 오늘의 학습에서 진행 중인 프로젝트의 "이어서 학습"은 바로 프로젝트 모드로 갑니다. 과정 화면에는 "응용 프로젝트" 배지와 "프로젝트"(문제 수 대신)를 표시합니다.
- **마일스톤 목록**: 마지막 채점 결과로 단계마다 "통과"(체크 아이콘, 정답 색)·"아직"(빈 원)·"앞 단계 먼저"(위로 꺾인 화살표, 흐린 글자: 앞 단계가 실패해 `event` 체크가 닿지 못했을 수 있는 단계, 서버의 `blocked`)·"채점 전"(대시)을 글자와 함께 보여 주고, 다음에 할 단계에 `aria-current="step"`과 옅은 배경을 둡니다. 진행 막대는 `role="progressbar"`(통과 수/전체)입니다.
- **채점**: "채점하기"(`⌘Enter`)가 숨은 러너로 채점 계획을 실행해 `POST /lessons/:id/project/attempts`로 보냅니다. 확신도는 묻지 않습니다(한 프로젝트를 여러 번 채점하므로). 결과는 기존 피드백 배너(마일스톤 요약 포함)와 체크 목록에 표시하고, 이번에 새로 통과한 단계는 "새로 통과: …"로 보여 주며 `aria-live`로 알립니다. 채점 뒤에도 편집기는 잠그지 않습니다. 샌드박스 문제로 결과가 없으면 오류 문구와 함께 다시 채점하게 합니다.
- **준비 연습**: 단원에 준비 연습 문제가 있으면 마일스톤 아래에 "준비 연습" 카드("프로젝트에 쓰는 개념을 N문제로 먼저 연습해요")와 "준비 연습 하기"를 둡니다. 누르면 단원 연습 세트를 만들어 `?mode=practice&set=`로 일반 연습 화면을 엽니다(제목 "… 준비 연습"). 끝나면 요약에 "한 번 더 연습"과 "프로젝트로 돌아가기"가 있습니다. 준비 연습은 완료 조건이 아닙니다.
- **이어 하기**: 편집기는 초안(편집할 때마다 이 브라우저에 저장하고 2초 뒤 서버에도 저장, "저장됨 · 이 브라우저" → "저장됨". 브라우저와 서버 중 더 최근 편집) → 서버의 마지막 제출 코드 → 시작 코드 순서로 채웁니다. 초안이나 마지막 제출에서 시작하면 과제 카드에 그 사실을 한 줄로 알립니다("저장해 둔 작성 중인 코드에서 이어서 해요", 초안이 마지막 제출과 같으면 "마지막으로 채점한 코드에서 이어서 해요"). 채점 뒤에도 초안을 지우지 않습니다([D-063](/docs/decisions.md)).
- **도움**: 학습 맥락이므로 힌트 사다리·AI 힌트·정답 보기·튜터(프로젝트 문제 스레드, 현재 코드와 마지막 실행 첨부)를 모두 씁니다.
- **완성**: 모든 마일스톤을 통과하면 정답 색 카드("모든 마일스톤을 통과했어요!")와 "완성" 배지, 개념 변화, 해설(완성한 뒤에만 옴), "다음: 다음 단원" 링크를 보여 줍니다. 다시 와도 카드는 "이 프로젝트를 완성했어요."로 남고, 계속 다듬어 채점해도 완료는 유지됩니다.

#### 연습 세트 진행 표시

- 세트 진행은 **문항 수 기준** 으로 표시합니다("7 / 18"). 시간 제한이나 타이머는 표시하지 않습니다(불필요한 압박 방지, WCAG 2.2.1).
- 소요 시간은 기록하지만 화면에 보이지 않습니다. 통계에서만 확인합니다.
- 세트 중간(약 50%)에 한 번, 연속 오답이 없으면 "절반 왔어요" 정도의 짧은 문구를 헤더 옆에 2초간 표시합니다(모션 없음).

#### 목표 달성 표현

- 목표 달성은 **GoalRing이 꽉 차고 체크 표시** 로 바뀌는 것이 전부입니다.
- 주간 현황(WeekStrip)은 학습한 날을 채우고, 주간 목표 일수를 넘으면 strip 끝에 ✓.
- 연속 학습일은 "연속 6일"처럼 숫자로만 보여주며, 끊겨도 경고하지 않습니다. 쉬는 날 다음 첫 접속 문구는 "다시 오셨네요. 오늘은 복습부터 가볍게 시작해요."
- 목표 미달 주에 대해 부정적 문구를 쓰지 않습니다. 목표 설정 화면에서 "목표를 조정해볼까요?"를 제안할 뿐입니다(3주 연속 미달 시).

### 마이크로카피 원칙

1.  **해요체, 주어는 생략하거나 "우리"를 쓰지 않습니다.** "다음 단원으로 가요" (O), "우리 다음 단원으로 가볼까요?" (X, 과한 친근함).
1.  **비난하지 않되 사실은 분명하게.** "정답이 아니에요" (O), "틀렸습니다!" (X), "거의 맞았어요!" (오답인데 사실이 아니면 X).
1.  **다음 행동을 함께 씁니다.** 모든 오류·오답 문구는 행동으로 끝납니다.
1.  **기술 오류를 학습자 언어로.** `ReferenceError: x is not defined` 아래에 "`x`라는 이름을 찾을 수 없어요. 선언하기 전에 썼거나 철자가 다를 수 있어요."를 덧붙입니다(원문 오류는 그대로 함께 보여줘 실제 오류 메시지 읽는 법을 배우게 합니다).
1.  **숫자는 구체적으로.** "조금 남았어요" 대신 "2문제 남았어요".
1.  **용어는 용어집을 따릅니다.** 숙련 단계 이름(미학습·입문·연습 중·숙련·숙달)을 화면 어디서나 동일하게 씁니다.
1.  **버튼은 동사로.** "확인" 대신 "복습 시작", "정답 보기", "연결 해제".

#### 단축키

macOS 기준이며, Windows·Linux는 `⌘` 대신 `Ctrl`입니다. 단축키는 `?`로 여는 도움말 모달에서 전체를 볼 수 있습니다.

#### 포커스 관리

- 라우트 변경 시 새 페이지의 H1으로 포커스를 옮기고, 라이브 영역에 페이지 제목을 알립니다.
- 문제 전환 시 새 문제 지문 제목에 포커스.
- 제출 후 FeedbackBanner가 `role="status"`로 결과를 알리고, 포커스는 제출 버튼 위치에 남깁니다(다음 행동 버튼은 Tab 한 번으로 도달하도록 배치).
- 드로어·시트: 열 때 첫 상호작용 요소로 포커스, 닫을 때 트리거로 복귀. 튜터 드로어는 비모달이므로 포커스 트랩을 걸지 않고 `F6`으로 영역 간 이동을 지원합니다.
- 모달: 포커스 트랩 + Esc 닫기 + 트리거 복귀.
- 고정 헤더와 하단 행동 바가 포커스된 요소를 가리지 않도록 `scroll-padding`을 설정합니다(WCAG 2.4.11).

### 반응형과 패널 규칙

데스크톱 중심입니다. 브레이크포인트는 뷰포트 너비 기준입니다.

| 범위 | 이름 | 전역 화면 | 학습 화면 |
|---|---|---|---|
| ≥ 1920px | wide | 콘텐츠 최대 1200px 중앙, 여백 확대 | 레슨 보조 열 280px, 튜터 드로어 기본 480px, HTML/CSS 3분할 기본 |
| 1440~1919px | comfortable (기준) | 최대 1200px | 와이어프레임 기준 배치 |
| 1280~1439px | standard | 최대 1120px, 대시보드 2열 | 레슨 보조 열 표시, 튜터 드로어 열면 레일 자동 접힘 |
| 1024~1279px | compact | 대시보드 카드 1~2열 재배치 | 레일 기본 접힘, 레슨 보조 열 숨김(목차는 헤더 메뉴), 튜터 드로어는 **오버레이**, HTML/CSS는 에디터/미리보기 탭 전환 |
| < 1024px | narrow (지원 최소) | 1열 | 단일 패널 + 상단 탭(문제 / 코드 / 결과 / 튜터). 기능은 유지하되 최적화하지 않음. 상단에 "넓은 화면에서 더 편하게 쓸 수 있어요" 1회 안내 |

패널 리사이즈 규칙:

| 패널 | 최소 | 기본 | 최대 | 접기 |
|---|---|---|---|---|
| 커리큘럼 레일 | 56px(접힘) | 56px | 360px | `[` 토글, 280px 이하로 줄이면 접힘으로 스냅 |
| 문제 패널 (2열) | 320px | 40% | 55% | 불가 |
| 작업 패널 에디터/결과 분할(세로) | 결과 120px | 에디터 65% | 에디터 85% | 결과 영역 접기 가능(헤더만 남김) |
| 튜터 드로어 | 360px | 400px (wide 480px) | 560px | 닫기 |
| 미리보기 (3분할) | 320px | 33% | 50% | 탭 전환으로 대체(compact) |

- 패널 크기는 화면·유형별로 `localStorage`에 저장합니다([시스템 아키텍처 상태 관리](/docs/design/system-architecture.md#웹-앱-내부-구조)).
- 핸들은 8px 히트 영역(시각 2px 선), 호버 시 jade 강조, 더블클릭으로 기본값 복원.
- 창 크기 변경 시 최소값을 위반하면 가장 덜 중요한 패널부터 접습니다: 레슨 보조 열 → 레일 → 튜터 드로어(오버레이 전환).

### UI 품질 검증

화면이 렌더링된다고 완료가 아닙니다([PRD MVP 완료 정의](/docs/product/prd.md#mvp-완료-정의)).

#### 디자인 프로토타입 계획

구현 전에 **정적 HTML 프로토타입** 으로 시각 방향을 확정합니다. 실제 앱 코드와 분리된 일회성 산출물이며, 실제 콘텐츠(JS 기초 한 단원 분량의 실제 텍스트·코드)를 넣어 비교합니다.

대상 화면(4개): 대시보드, 과정 상세(커리큘럼 아코디언), 학습 읽기 모드, 실습 모드(코드 구현 + 튜터 드로어 열림). 각 라이트·다크.

비교안(3개, 모두 인프런 방향 안에서의 변형):

| 안 | 이름 | 특징 | 확인할 질문 |
|---|---|---|---|
| A | 밝은 교실 | 전 화면 라이트, 에디터도 라이트 테마, 넓은 여백 | 실습 모드에서 코드 영역이 충분히 구분되는가 |
| B | 밝은 교실 + 어두운 작업대 | 셸·레슨은 라이트, 실습 모드 작업 패널(에디터·콘솔)만 다크 | 라이트 모드에서 명암 대비가 피로하지 않은가, 한 제품처럼 보이는가 |
| C | 차분한 교실 | 캔버스를 연한 뉴트럴(`neutral-25`~`50`)로 깔고 카드만 흰색, 밀도 약간 높게 | 장시간 학습 피로, 정보 밀도 |

평가 방법:

1.  세 안을 같은 콘텐츠로 만들고 1440·1280·1024px에서 스크린샷을 찍습니다.
1.  각 안으로 실제 단원 하나(읽기 → 5문제)를 20분간 학습해보는 **시나리오 점검** 을 합니다.
1.  아래 체크리스트로 점수를 매기고, 결정을 [결정 기록](/docs/decisions.md)에 추가합니다.
1.  인프런 실제 화면(과정 상세, 수강 화면, 내 학습)을 직접 관찰해 레퍼런스 분석 표를 보정합니다.
1.  로고 2~3안도 이 단계에서 함께 결정합니다.

#### M2 결과 (2026-11-14)

- 세 안과 로고 3안을 [디자인 프로토타입](/design/prototypes/README.md)으로 만들어 비교했습니다. 4개 화면 × 3안 × 2테마 24조합 모두 axe-core WCAG 2.2 A/AA 위반 0건입니다.
- **채택: C 차분한 교실**. 캔버스 `neutral-50` 위에 흰 카드를 두고 레슨 본문도 카드에 담아, 대시보드·과정 상세의 위계와 읽기 영역이 가장 분명했습니다. 카드 패딩·간격은 A보다 약 15% 좁힙니다(`--card-pad: space-5`, `--section-gap: space-6`, `--grid-gap: space-4`).
- 에디터는 라이트 기본, 로고는 1안, 토큰 수정 3건(`jade-600`, `neutral-550`, `--color-border-input`)을 반영했습니다. 결정: [D-024](/docs/decisions.md).

#### 디자인 리뷰 체크리스트

각 화면을 머지하기 전에 확인합니다.

- [ ] 화면의 primary 행동이 하나인가
- [ ] 3초 안에 "지금 어디이고 다음에 무엇을 하는지" 알 수 있는가
- [ ] 의미 토큰만 사용했는가 (임의의 색·간격 값 없음)
- [ ] 타입 스케일 밖의 글자 크기가 없는가
- [ ] 빈·로딩·오류 상태가 디자인되었는가
- [ ] 정오·상태를 색만으로 전달하지 않는가
- [ ] 키보드만으로 화면의 모든 행동을 할 수 있는가, 포커스 링이 보이는가
- [ ] 다크 모드에서 대비·표면 단계가 자연스러운가
- [ ] 1024px에서 깨지지 않는가, 1920px에서 휑하지 않은가
- [ ] 한글 줄바꿈(`keep-all`)이 어색한 곳이 없는가
- [ ] 마이크로카피가 원칙(해요체, 다음 행동, 비난 없음)을 따르는가
- [ ] 애니메이션이 320ms 이하이고 reduced-motion에서 꺼지는가
- [ ] AI 생성 콘텐츠가 표식으로 구분되는가

#### 실제 학습 흐름 사용성 점검

마일스톤마다 다음 시나리오를 실제로 수행하고 마찰 지점을 기록합니다. 개발자 관점이 아니라 **처음 배우는 학습자 관점** 으로 진행합니다.

1.  첫 실행 → 목표 설정 → 첫 단원 읽기 → 인라인 문제 → 연습 5문제.
1.  코드 문제에서 일부러 무한 반복을 작성 → 시간 초과 메시지 → 수정 → 통과.
1.  같은 연습 세트에서 같은 개념 오답 2연속(학습 엔진의 재학습 발동 조건) → 재학습 제안 → 풀이 예제.
1.  다음 날(시간 조작) 복습 세트 → 종료 요약 → 숙련 단계 변화 확인.
1.  AI 미연결 상태로 전체 흐름 → AI 연결 → 튜터 질문 → 한도 도달 시뮬레이션.
1.  백업 → 기록 추가 → 복원.

각 점검 결과는 이슈로 등록하고, 같은 마찰이 두 번 나오면 우선순위를 올립니다.

| 하이브리드 (읽기는 Editorial, 실습은 Studio) | 단계별 최적 밀도 | 두 세계의 일관성 유지가 어렵고, 1차 보고서 단계의 추상적 방향 | 인프런 방향으로 구체화하며 흡수 |
| **인프런 방향 재해석 (밝은 교실, 정돈된 작업대)** (채택) | 한국 학습자에게 익숙한 톤, 밝고 신뢰감 있는 화면, 커리큘럼·진도 패턴이 검증됨 | 흔한 교육 사이트처럼 보일 위험 | 채택 ([D-011](/docs/decisions.md)). 개념 지도, 숙련 아이콘 체계, 힌트 사다리, AI 구분 색으로 차별화 |

## 교차 관심사

### 보안

- AI 튜터 응답과 AI 생성 문제 본문은 마크다운으로 렌더링하되 원시 HTML을 비활성화합니다([NFR-07](/docs/product/prd.md#비기능-요구사항)). 링크는 `rel="noopener noreferrer"`로 새 창에서 열고, `javascript:` 스킴을 차단합니다.
- 미리보기와 실행 결과는 항상 샌드박스 iframe 안에만 렌더링합니다. 콘솔 출력 문자열은 텍스트로만 렌더링합니다.
- "에디터에 적용"(튜터가 제안한 코드를 에디터에 넣기, P1)은 diff 미리보기와 확인을 거칩니다.

### 개인정보

- 튜터 드로어의 ContextChip이 AI로 전송되는 맥락을 보여줍니다. 칩을 제거하면 해당 정보는 전송되지 않습니다.
- 설정의 계정 표시는 이메일 일부를 가립니다.

### 성능

- 레슨 본문은 빌드 시 컴파일된 결과를 렌더링합니다. RunnableExample의 에디터는 화면에 들어올 때 지연 생성합니다.
- 개념 지도는 개념 수백 개에서도 60fps 스크롤을 유지하도록 가상화를 고려합니다(모듈 단위 지연 렌더링으로 먼저 시도).
- 폰트는 `font-display: swap` + 프리로드(본문 400·600, 코드 400).
- 레이아웃 이동(CLS) 방지: 스켈레톤은 최종 레이아웃과 같은 크기.

### 관측성

- 클라이언트 오류는 [시스템 아키텍처 관측성](/docs/design/system-architecture.md#관측성)에 따라 서버로 보고합니다.
- UX 개선을 위해 로컬에만 다음 이벤트를 기록합니다: 힌트 단계 열람, 정답 보기, 재학습 제안 수락/거절, 튜터 맥락 진입점 사용. 외부 전송은 없습니다.

### 테스트

- 컴포넌트 상호작용(키보드 조작, ARIA 상태): Vitest + Testing Library.
- 시각 회귀·접근성: 위 [시각 회귀 매트릭스](#시각-회귀-매트릭스).
- 디자인 토큰 대비 검증 스크립트: 의미 토큰 쌍(텍스트/배경)의 대비를 계산해 목표 미달 시 CI 실패.

## UI-UX 미결 사항

- 성공 색과 브랜드 색 공유가 실제로 혼동을 일으키는지. 혼동되면 성공 색을 별도 녹색(hue 145)으로 분리.
- 진단 평가(P1) 화면 설계는 [학습 엔진 설계](/docs/design/learning-engine.md)의 진단 알고리즘이 정해진 뒤 추가.
- 레슨 본문의 인라인 확인 문제가 숙련도에 반영되는 가중치 표현 방식(학습자에게 보여줄지).
- 인프런 실제 수강 화면 관찰 결과에 따라 레퍼런스 분석 표 보정.
