<Section kind="objectives">
- `a` 요소와 `href` 속성으로 원하는 주소로 이동하는 링크를 만들 수 있어요.
- 폴더 구조를 보고 지금 문서에서 다른 파일까지의 상대 경로를 쓸 수 있어요.
- `img` 요소에 그림의 내용을 전하는 `alt`를 쓰고, 꾸미기용 그림과 구분할 수 있어요.
</Section>

<Section kind="prerequisites" />

<Section kind="intro">
웹(Web)은 "거미줄"이라는 뜻이에요. 수많은 페이지가 **링크**로 거미줄처럼 이어져 있어서 붙은 이름이에요. 링크가 없다면 페이지마다 주소를 일일이 입력해야 할 거예요.

그런데 링크와 이미지를 넣다 보면 이런 문제를 만나요.

- 내 사이트의 다른 페이지로 가는 링크를 만들었는데, 눌러 보니 "페이지를 찾을 수 없음"이 떠요.
- 이미지를 넣었는데 내 컴퓨터에서는 보이고, 다른 폴더에 둔 페이지에서는 안 보여요.
- 사진이 잘 보이는데 왜 `alt`를 써야 하는지 모르겠어요.

이 단원에서는 링크와 이미지를 만드는 요소, 파일 위치를 적는 **경로**, 그리고 그림을 볼 수 없는 사람에게도 내용을 전하는 `alt`를 배워요.
</Section>

<Section kind="principle">
### 링크: a 요소와 href

링크는 `a` 요소로 만들어요. 이동할 주소는 `href` 속성에 쓰고, 태그 사이의 내용은 화면에 보이는 **링크 글자**예요.

```html
<a href="https://developer.mozilla.org">MDN 웹 문서</a>
```

- 화면에는 밑줄 그어진 "MDN 웹 문서"가 보여요.
- 누르면 `href`에 적힌 `https://developer.mozilla.org`로 이동해요.

링크 글자와 이동할 주소는 서로 관계가 없어요. 링크 글자는 "어디로 가는 링크인지" 사람이 알 수 있게 쓰는 설명이에요. 그래서 "여기"보다 "MDN 웹 문서"처럼 목적지를 알려 주는 글자가 좋아요.

### 경로: 파일이 어디에 있는지 적기

`href`나 뒤에 나올 `img`의 `src`에는 파일의 위치, 즉 **경로**를 써요. 경로는 두 가지가 있어요.

| 종류 | 생김새 | 기준 | 언제 |
|---|---|---|---|
| 절대 경로 | `https://example.com/about.html` | 인터넷 전체에서의 전체 주소 | 다른 사이트로 갈 때 |
| 상대 경로 | `about.html`, `images/cat.jpg`, `../index.html` | **지금 문서가 있는 폴더** | 내 사이트 안의 파일을 가리킬 때 |

상대 경로는 지금 문서가 있는 폴더에서 출발해 길을 안내하는 것과 같아요. 아래 폴더 구조로 예를 들어 볼게요.

```text
my-site/
├── index.html
├── about.html
├── images/
│   └── logo.png
└── blog/
    └── first-post.html
```

| 지금 문서 | 가리킬 파일 | 상대 경로 | 읽는 법 |
|---|---|---|---|
| `index.html` | `about.html` | `about.html` | 같은 폴더에 있는 about.html |
| `index.html` | `logo.png` | `images/logo.png` | images 폴더로 들어가서 logo.png |
| `blog/first-post.html` | `index.html` | `../index.html` | 한 단계 위 폴더(`..`)로 나가서 index.html |
| `blog/first-post.html` | `logo.png` | `../images/logo.png` | 위 폴더로 나간 다음 images 폴더로 들어가서 logo.png |

- 폴더 이름 뒤의 `/`는 "그 폴더 안으로 들어간다"는 뜻이에요.
- `..`은 "한 단계 위 폴더"예요. 두 단계 위는 `../../`예요.

### 이미지: img 요소와 alt

이미지는 `img` 요소로 넣어요. `img`는 내용이 없는 **빈 요소**라서 닫는 태그를 쓰지 않아요.

```html
<img src="images/logo.png" alt="동네 빵집 로고" />
```

- `src`: 그림 파일의 경로
- `alt`: 그림을 볼 수 없을 때 그림 대신 전할 **대체 텍스트**

끝의 ` />`는 써도 되고 `>`로 끝내도 돼요. 둘 다 같은 뜻이에요.

`alt`는 장식이 아니라 그림의 **내용을 대신 전하는** 속성이에요.

- 화면 낭독기를 쓰는 시각 장애인에게는 `alt`의 글자를 읽어 줘요.
- 인터넷이 느리거나 파일 경로가 틀려 그림이 열리지 않으면 그림 자리에 `alt`가 보여요.
- 검색 엔진도 `alt`로 그림의 내용을 파악해요.

좋은 `alt`는 그림을 보지 않고도 페이지 내용을 이해할 수 있게 써요. "사진", "이미지"처럼 쓰는 것은 도움이 되지 않아요. 반대로 줄무늬 구분선처럼 **꾸미기만 하는 그림**은 `alt=""`로 비워 둬요. 비워 두면 화면 낭독기가 그 그림을 건너뛰어요. `alt` 속성 자체를 빼면 화면 낭독기가 파일 이름을 읽어 버릴 수 있으니, 꾸미기용이라도 `alt=""`는 써야 해요.
</Section>

<Section kind="examples">
첫 번째 예제는 절대 경로와 상대 경로로 만든 링크예요. 링크 글자와 주소가 어떻게 다른지 보세요.

<RunnableExample id="links" lang="html" concepts={["html.content.links", "html.content.paths"]}>
```html
<p>
  <a href="https://developer.mozilla.org">MDN 웹 문서</a>에서
  HTML을 더 찾아볼 수 있어요.
</p>
<p>
  <a href="about.html">우리 동아리 소개</a> 페이지도 읽어 보세요.
</p>
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
- 화면에는 "MDN 웹 문서"와 "우리 동아리 소개"가 링크 글자로 보이고, 주소는 보이지 않아요. 주소는 `href` 속성 안에 있으니까요.
- 첫 링크의 `href`는 `https://`로 시작하는 절대 경로라서 어디에서 눌러도 같은 사이트로 가요.
- 둘째 링크의 `about.html`은 상대 경로예요. 이 문서와 **같은 폴더**에 있는 `about.html`로 가요.

이 앱의 미리보기는 안전을 위해 다른 페이지로 이동하지 않아요. 링크를 누른 뒤 미리보기 모양이 바뀌면 **다시 실행**을 누르세요. 여기서는 링크가 어떻게 보이는지만 확인하면 돼요.
</Section>

<Section kind="examples">
두 번째 예제에는 이미지 두 개가 있어요. 이 미리보기에는 `cat.jpg` 파일이 없어요. 실행하기 전에, 그림 파일이 없을 때 화면에 무엇이 보일지 예측해 보세요.

<RunnableExample id="alt-text" lang="html" predict predictKind="value" concepts={["html.content.images"]}>
```html
<p>첫째 그림 (alt 있음):</p>
<img src="cat.jpg" alt="창가에 앉아 졸고 있는 회색 고양이" />

<p>둘째 그림 (alt 없음):</p>
<img src="cat.jpg" />
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
- 첫째 그림 자리에는 깨진 그림 표시와 함께 `alt`의 글자 "창가에 앉아 졸고 있는 회색 고양이"가 보여요. 그림은 없어도 무엇이 있었는지는 알 수 있어요.
- 둘째 그림 자리에는 깨진 그림 표시만 남아요. 무엇이 있었는지 전혀 알 수 없어요.

그림이 열리지 않은 이 상황은, 화면을 볼 수 없는 사람이 늘 겪는 상황과 같아요. `alt`가 있으면 그림을 볼 수 없어도 내용이 전해져요.

이제 링크와 그림을 직접 써 볼 차례예요. 경로는 지금 문서가 있는 폴더에서 출발해요.

<Section kind="pitfalls">
<Pitfall misconception="html.mc.link-text-is-address">
<Wrong>`<a href="https://a.com">https://b.com</a>`을 누르면 링크 글자에 적힌 b.com으로 간다.</Wrong>
<Actual>a.com으로 가요. 링크 글자는 화면에 보이는 설명일 뿐이에요.</Actual>
<Right>이동할 주소는 `href` 속성이 정해요. 링크 글자는 목적지를 사람에게 알려 주는 설명이라 목적지와 맞게 써요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.relative-path-base">
<Wrong>`blog/first-post.html`에서 로고를 넣을 때도 사이트 맨 위 폴더 기준으로 `images/logo.png`라고 쓴다.</Wrong>
<Actual>브라우저는 지금 문서가 있는 `blog` 폴더 안에서 `images` 폴더를 찾아요. 그런 폴더가 없으니 그림이 열리지 않아요.</Actual>
<Right>상대 경로의 출발점은 지금 문서가 있는 폴더예요. 위 폴더로 나가야 하면 `../images/logo.png`처럼 `../`를 써요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.alt-optional">
<Wrong>그림이 잘 보이니까 `alt`는 없어도 된다.</Wrong>
<Actual>화면 낭독기 사용자나 그림이 열리지 않은 사람에게는 그림의 내용이 전혀 전해지지 않아요.</Actual>
<Right>뜻이 있는 그림에는 내용을 설명하는 `alt`를 쓰고, 꾸미기만 하는 그림에는 `alt=""`를 써요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.img-has-content">
<Wrong>`<img src="cat.jpg">고양이 사진</img>`처럼 태그 사이에 설명을 쓴다.</Wrong>
<Actual>`img`는 빈 요소라서 닫는 태그가 없어요. 브라우저는 `</img>`를 무시하고, "고양이 사진"은 그림 옆에 그냥 글자로 보여요.</Actual>
<Right>그림의 설명은 `alt` 속성에 써요. `<img src="cat.jpg" alt="고양이 사진" />`처럼요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
실제 웹 사이트의 맨 위 메뉴는 대부분 링크 여러 개로 만들어요. 로고 그림을 누르면 첫 페이지로 가는 것도 흔해요. 이럴 때는 `a` 안에 `img`를 넣어요.

```html
<a href="index.html">
  <img src="images/logo.png" alt="동네 빵집 첫 페이지" />
</a>
```

링크 안에 그림만 있으면 그림의 `alt`가 곧 링크의 이름이 돼요. 그래서 이때의 `alt`는 그림 모양("빵 모양 로고")보다 링크의 목적지("동네 빵집 첫 페이지")를 알려 주는 것이 좋아요.

<Callout kind="tip" title="경로가 틀렸는지 확인하기">
그림이 안 보이면 개발자 도구(<Key>F12</Key>)의 **Console**이나 **Network** 탭을 보세요. 찾지 못한 파일이 빨간색으로 표시되고, 브라우저가 실제로 어떤 주소에서 파일을 찾았는지 알 수 있어요.
</Callout>

<Section kind="summary">
- 링크는 `a` 요소로 만들고, 이동할 주소는 `href`에, 화면에 보일 링크 글자는 태그 사이에 써요.
- 절대 경로는 `https://`로 시작하는 전체 주소이고, 상대 경로는 지금 문서가 있는 폴더를 기준으로 적어요.
- 상대 경로에서 `폴더/`는 그 폴더로 들어가기, `../`는 한 단계 위 폴더로 나가기예요.
- `img`는 빈 요소예요. 그림 파일은 `src`에, 그림을 볼 수 없을 때 전할 설명은 `alt`에 써요.
- 뜻이 있는 그림에는 내용을 설명하는 `alt`를, 꾸미기만 하는 그림에는 `alt=""`를 써요.
</Section>
