- 주소를 입력했을 때 브라우저와 서버 사이에 오가는 요청과 응답을 순서대로 설명할 수 있어요.
- 웹 페이지에서 하려는 일이 HTML·CSS·JavaScript 중 어느 것의 몫인지 고를 수 있어요.
- 브라우저가 HTML 코드를 받아 태그를 해석하고 내용을 그린다는 것을 예측에 활용할 수 있어요.
</Section>

<Section kind="intro">
매일 쓰는 웹 페이지는 어디에서 오는 걸까요? 주소창에 주소를 입력하고 <Key>Enter</Key>를 누르면 몇 초 안에 글자와 그림, 버튼이 나타나요. 그런데 이런 질문에는 답하기 어려워요.

- 처음 가 보는 사이트인데, 내 컴퓨터는 그 페이지를 어떻게 알고 보여 줄까요?
- 웹 페이지를 만드는 코드는 어떻게 생겼고, 왜 화면에는 코드가 보이지 않을까요?
- 웹 개발을 배운다고 하면 왜 HTML, CSS, JavaScript 세 가지를 배울까요?

이 단원에서는 브라우저가 웹 페이지를 가져와서 화면에 그리기까지의 흐름을 따라가요. 이 흐름을 알면 앞으로 쓰는 코드가 "누구에게, 어떤 일을 시키는 것인지" 알 수 있어요.
</Section>

<Section kind="principle">
### 요청과 응답: 브라우저와 서버

웹 페이지 파일은 내 컴퓨터가 아니라 인터넷 어딘가의 컴퓨터에 저장되어 있어요. 이렇게 파일을 가지고 있다가 달라는 곳에 보내 주는 컴퓨터를 **서버**라고 해요. 그리고 서버에 파일을 달라고 하는 쪽, 즉 우리가 쓰는 브라우저(Chrome, Edge, Safari 등)를 **클라이언트**라고 해요.

주소를 입력하면 이런 일이 차례로 일어나요.

```text
[Browser]  --- 1. request: "please send index.html" --->  [Server]
[Browser]  <-- 2. response: the index.html file ---------  [Server]
[Browser]  3. reads the HTML and draws the page
```

1. **요청(request)**: 브라우저가 주소를 보고 그 주소의 서버에 "이 파일을 보내 주세요"라고 요청해요.
1. **응답(response)**: 서버가 요청받은 파일(HTML 문서)을 브라우저에 보내 줘요.
1. **그리기**: 브라우저가 받은 HTML을 읽고 화면에 페이지를 그려요. HTML 안에 그림이나 CSS 파일이 적혀 있으면, 그 파일들도 같은 방법으로 다시 요청해요.

음식점에 비유하면 브라우저는 손님, 서버는 주방이에요. 손님이 메뉴(주소)를 골라 주문(요청)하면 주방이 음식(파일)을 내어 줘요(응답).

### 세 언어의 역할 분담

브라우저가 받는 파일에는 세 가지 언어가 쓰여요. 한 페이지를 집에 비유하면 이래요.

| 언어 | 맡은 일 | 집에 비유하면 | 예 |
|---|---|---|---|
| HTML | 내용과 구조 | 뼈대와 방 구분 | "이건 제목, 이건 문단, 여기엔 사진" |
| CSS | 모양 | 벽지와 가구 배치 | 글자 색, 크기, 여백, 배치 |
| JavaScript | 동작 | 전기와 수도 | 버튼을 누르면 숫자가 바뀜, 계산 |

HTML은 **표시(마크업) 언어**예요. 내용에 "이건 제목이에요", "이건 링크예요"처럼 뜻을 붙이는 일만 하고, 계산을 하거나 버튼을 누를 때 무언가를 바꾸지는 못해요. 그런 동작은 JavaScript가 맡아요.

### 렌더링: 코드를 그림으로

HTML은 내용을 **태그**로 감싸서 뜻을 표시해요. 예를 들어 `<h1>오늘의 날씨</h1>`에서 `<h1>`과 `</h1>`이 태그이고, "이 글자는 가장 큰 제목이에요"라는 뜻이에요.

브라우저는 받은 HTML을 위에서부터 읽으면서 태그의 뜻을 해석하고, **태그는 감춘 채 내용만** 그 뜻에 맞게 그려요. 제목은 크고 굵게, 문단은 한 덩어리의 글로 그리는 식이에요. 이렇게 코드를 읽어 화면에 그리는 과정을 **렌더링(rendering)** 이라고 해요.
</Section>

<Section kind="examples">
첫 번째 예제는 HTML 코드예요. 실행하기 전에 화면에 무엇이 어떻게 보일지 먼저 적어 보세요. 태그가 보일까요?

<RunnableExample id="first-render" lang="html" predict predictKind="value" concepts={["html.web.rendering"]}>
```html
<h1>오늘의 날씨</h1>
<p>서울은 하루 종일 맑아요.</p>
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
- 화면에는 `<h1>`이나 `<p>` 같은 태그가 보이지 않아요. 브라우저가 태그를 읽고 감췄기 때문이에요.
- "오늘의 날씨"는 `h1`(가장 큰 제목)이라서 크고 굵게 그려져요.
- "서울은 하루 종일 맑아요."는 `p`(문단)라서 보통 크기의 글로 그려져요.

태그는 사람에게 보여 줄 글자가 아니라 **브라우저에게 주는 표시**예요.
</Section>

<Section kind="examples">
두 번째 예제는 세 언어를 모두 쓴 작은 페이지예요. `<style>` 안은 CSS, `<script>` 안은 JavaScript예요. 실행하고 버튼을 몇 번 눌러 보세요.

<RunnableExample id="three-languages" lang="web" concepts={["html.web.three-languages"]}>
```html
<style>
  h1 {
    color: #2563eb;
  }
</style>

<h1>방문 기록</h1>
<p>버튼을 누른 횟수: <span id="count">0</span></p>
<button id="add">눌러 보세요</button>

<script>
  let count = 0;
  document.querySelector("#add").addEventListener("click", () => {
    count = count + 1;
    document.querySelector("#count").textContent = count;
  });
</script>
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
코드를 세 부분으로 나눠 보면 각 언어가 맡은 일이 보여요.

| 부분 | 언어 | 하는 일 |
|---|---|---|
| `<h1>`, `<p>`, `<button>` | HTML | 제목, 문단, 버튼이 **있다**고 알려 줘요 |
| `<style>` 안의 `color: #2563eb;` | CSS | 제목을 파란색으로 **보이게** 해요 |
| `<script>` 안의 코드 | JavaScript | 버튼을 누르면 숫자를 1 늘리는 **동작**을 해요 |

`<style>`과 `<script>`를 지우고 다시 실행해 보세요. 제목과 버튼은 그대로 있지만 색이 사라지고, 버튼을 눌러도 숫자가 바뀌지 않아요. HTML만으로는 동작을 만들 수 없다는 뜻이에요. JavaScript 코드는 지금 이해하지 않아도 괜찮아요. JavaScript 기초 과정에서 하나씩 배워요.
</Section>

<Section kind="pitfalls">
<Pitfall misconception="html.mc.page-lives-in-browser">
<Wrong>브라우저 프로그램 안에 웹 페이지가 미리 들어 있어서, 주소를 입력하면 그걸 꺼내 보여 준다.</Wrong>
<Actual>웹 페이지 파일은 서버에 있어요. 그래서 인터넷이 끊기면 처음 가 보는 사이트는 열리지 않아요.</Actual>
<Right>브라우저는 주소를 보고 서버에 파일을 **요청**하고, 서버가 보낸 **응답**을 받아 화면에 그려요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.html-is-programming">
<Wrong>HTML로 버튼을 누르면 숫자가 늘어나게 만들 수 있다.</Wrong>
<Actual>HTML은 "여기에 버튼이 있다"까지만 표시해요. 누르면 무엇을 할지는 HTML로 정할 수 없어요.</Actual>
<Right>HTML은 내용과 구조, CSS는 모양, JavaScript는 동작을 맡아요. 계산이나 반응이 필요하면 JavaScript의 몫이에요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.code-shown-as-is">
<Wrong>`<h1>안녕</h1>`을 브라우저로 열면 화면에 `<h1>안녕</h1>`이 그대로 나온다.</Wrong>
<Actual>화면에는 크고 굵은 "안녕"만 보여요. 태그는 보이지 않아요.</Actual>
<Right>브라우저는 태그를 해석해서 뜻에 맞게 그리고, 태그 자체는 감춰요. 이 과정이 렌더링이에요.</Right>
</Pitfall>
</Section>

<Section kind="summary">
- 웹 페이지 파일은 서버에 있고, 브라우저(클라이언트)가 주소를 보고 요청하면 서버가 응답으로 보내 줘요.
- HTML은 내용과 구조, CSS는 모양, JavaScript는 동작을 맡아요.
- HTML은 계산이나 동작을 하지 않는 표시(마크업) 언어예요.
- 브라우저는 태그의 뜻을 해석해 내용을 그리고, 태그 자체는 화면에 보여 주지 않아요. 이 과정을 렌더링이라고 해요.
