<Section kind="objectives">
- HTML 코드에서 여는 태그·닫는 태그·내용·요소·속성을 각각 가리킬 수 있어요.
- 요소를 올바른 순서로 중첩하고, 엇갈린 태그를 찾을 수 있어요.
- `<!doctype html>`·`html`·`head`·`body`로 이루어진 문서의 뼈대를 쓰고, `head`와 `body`에 들어갈 내용을 구분할 수 있어요.
- HTML 코드를 보고 DOM 트리에서 요소 사이의 부모·자식 관계를 말할 수 있어요.
</Section>

<Section kind="prerequisites" />

<Section kind="intro">
앞 단원에서 브라우저가 태그를 해석해 화면을 그린다는 것을 봤어요. 그런데 HTML을 직접 쓰기 시작하면 금방 이런 고민이 생겨요.

- 링크에 이동할 주소는 어디에 적어야 할까요? 글자 사이에 쓰면 화면에 보일 텐데요.
- 태그 안에 태그를 넣을 때, 어느 쪽을 먼저 닫아야 할까요?
- 브라우저 탭에 보이는 페이지 이름은 어디서 정할까요?

이 단원에서는 HTML을 이루는 기본 부품(태그, 요소, 속성)과 부품을 조립하는 규칙(중첩), 그리고 모든 HTML 문서가 갖는 뼈대를 배워요. 마지막으로 브라우저가 이 코드를 읽어 만드는 **DOM 트리**를 살펴봐요. DOM 트리는 나중에 JavaScript로 화면을 바꿀 때 다루는 대상이에요.
</Section>

<Section kind="principle">
### 태그와 요소

`<p>안녕하세요</p>`를 부분별로 나눠 보면 이래요.

| 부분 | 코드 | 설명 |
|---|---|---|
| 여는 태그 | `<p>` | 요소가 시작되는 곳. 꺾쇠 안에 요소 이름을 써요 |
| 내용 | `안녕하세요` | 화면에 보일 글자(또는 다른 요소) |
| 닫는 태그 | `</p>` | 요소가 끝나는 곳. 이름 앞에 `/`를 붙여요 |
| **요소** | `<p>안녕하세요</p>` | 여는 태그 + 내용 + 닫는 태그 **전체** |

**태그**는 꺾쇠로 감싼 표시 하나하나이고, **요소**는 그 태그들이 감싼 내용까지 합친 전체예요. "문단 요소"라고 하면 `<p>`부터 `</p>`까지 전부를 가리켜요.

`<img>`(그림)나 `<br>`(줄바꿈)처럼 내용이 없어서 닫는 태그를 쓰지 않는 요소도 있어요. 이런 요소를 **빈 요소**라고 하고, 여는 태그 하나가 곧 요소 전체예요.

이 단원의 예제에는 `strong`(중요한 내용), `em`(말의 강세), `a`(링크) 같은 요소가 나와요. 각 요소의 뜻은 뒤 단원에서 자세히 배우니, 지금은 부품과 조립 규칙에만 집중하세요.

### 속성

**속성**은 요소에 추가 정보를 주는 방법이에요. 여는 태그 안, 요소 이름 뒤에 `이름="값"` 형태로 써요. 여러 개면 공백으로 나눠요.

```html
<a href="https://developer.mozilla.org" title="웹 개발 문서">MDN</a>
```

- `href="..."`: 링크가 이동할 주소
- `title="..."`: 마우스를 올렸을 때 보여 줄 설명

속성은 **여는 태그 안에만** 써요. 닫는 태그에는 쓰지 않아요. 그리고 속성 값은 화면에 글자로 나오지 않아요. 화면에 나오는 글자는 태그 사이의 내용(`MDN`)이에요.

### 중첩: 상자 안의 상자

요소 안에 다른 요소를 넣을 수 있어요. 이것을 **중첩**이라고 해요. 중첩은 상자 안에 작은 상자를 넣는 것과 같아서, **나중에 연 요소를 먼저 닫아야** 해요.

<CompareTable columns={["올바른 중첩", "엇갈린 태그 (잘못)"]}>
<Row label="코드">`<p><strong>꼭</strong> 지켜요</p>` | `<p><strong>꼭 지켜요</p></strong>`</Row>
<Row label="닫는 순서">strong을 닫고 → p를 닫음 | p를 먼저 닫음 (strong이 아직 열려 있음)</Row>
</CompareTable>

여는 태그와 닫는 태그를 선으로 이어 봤을 때 선이 서로 엇갈리지 않아야 해요.

### 문서의 뼈대

웹 페이지 하나가 되는 HTML 문서는 항상 같은 뼈대를 가져요.

```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="utf-8" />
    <title>탭에 보이는 이름</title>
  </head>
  <body>
    <h1>화면에 보이는 제목</h1>
  </body>
</html>
```

| 부분 | 하는 일 |
|---|---|
| `<!doctype html>` | "이 문서는 최신 HTML 규칙을 따른다"는 선언. 요소가 아니라 맨 첫 줄의 약속이에요 |
| `<html lang="ko">` | 문서 전체를 감싸는 가장 바깥 요소. `lang="ko"`는 문서가 한국어라는 뜻이에요 |
| `<head>` | **화면에 그리지 않는** 문서 정보. 글자 인코딩(`meta charset`), 탭 이름(`title`), CSS 연결 등 |
| `<body>` | **화면에 보일** 모든 내용 |

`title`의 글자는 페이지 본문이 아니라 브라우저 탭과 즐겨찾기 이름으로 쓰여요.

### DOM 트리

브라우저는 HTML 글자를 읽으면서 요소들을 **부모·자식 관계로 이어진 나무 구조**로 만들어요. 이 구조를 **DOM 트리**(Document Object Model)라고 해요. 위의 뼈대에 안에 `strong`이 든 문단 하나를 더하면 DOM 트리는 이렇게 생겨요.

```text
html
├── head
│   ├── meta
│   └── title
└── body
    ├── h1
    └── p
        └── strong
```

- 어떤 요소를 바로 감싸는 요소가 **부모**, 바로 안에 든 요소가 **자식**이에요. `body`의 자식은 `h1`과 `p`이고, `strong`은 `p`의 자식이에요.
- `strong`은 `body` 안에 있지만 `body`의 자식이 아니라 **자손**(자식의 자식)이에요.
- `h1`과 `p`처럼 같은 부모를 둔 요소끼리는 **형제**라고 해요. `head`와 `body`도 `html`을 부모로 둔 형제예요.

DOM 트리는 내가 쓴 글자를 그대로 복사한 것이 아니에요. 브라우저는 규칙에 따라 구조를 **새로 만들고**, 빠진 부분은 스스로 채워요. 예를 들어 `<html>`, `<head>`, `<body>`를 빠뜨려도 DOM 트리에는 항상 이 세 요소가 생겨요.
</Section>

<Section kind="examples">
첫 번째 예제에는 속성이 두 개 있어요. 실행하기 전에, 화면에 어떤 글자가 보일지 예측해 보세요. `title`의 값도 보일까요?

<RunnableExample id="attributes" lang="html" predict predictKind="value" concepts={["html.doc.elements", "html.doc.attributes"]}>
```html
<p lang="ko" title="마우스를 올리면 보이는 설명">
  저는 <strong>HTML</strong>을 배우고 있어요.
</p>
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
- 화면에는 "저는 **HTML**을 배우고 있어요."만 보여요. `lang="ko"`의 `ko`나 `title`의 설명은 보이지 않아요.
- 문장 위에 마우스를 잠시 올려 두면 `title`의 설명이 작은 상자로 나타나요. 속성은 브라우저에게 주는 정보이고, 브라우저가 그 정보를 어떻게 쓸지 정해요.
- `strong` 요소는 `p` 요소 안에 중첩되어 있어요. `</strong>`을 먼저 닫고 `</p>`를 나중에 닫았어요.
</Section>

<Section kind="examples">
두 번째 예제는 닫는 태그 `</p>`를 일부러 빠뜨렸어요. 문단마다 테두리를 그리는 CSS를 넣었으니, 실행해서 문단이 몇 개로 그려지는지 보세요.

<RunnableExample id="dom-repair" lang="web" concepts={["html.doc.dom-tree"]}>
```html
<style>
  p {
    border: 2px solid #2563eb;
    padding: 4px;
  }
</style>

<p>첫째 문단이에요.
<p>둘째 문단이에요.
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
테두리가 그려진 문단이 **두 개** 보여요. 브라우저는 `<p>` 안에서 새 `<p>`를 만나면 "문단 안에 문단은 들어갈 수 없다"는 규칙에 따라 앞 문단을 거기서 닫아요. 그래서 DOM 트리는 이렇게 만들어져요.

```text
body
├── p   (first paragraph)
└── p   (second paragraph)
```

코드에는 `</p>`도, `<html>`·`<head>`·`<body>`도 없지만, DOM 트리에는 모두 있어요. 브라우저가 HTML을 읽어 구조를 새로 만들면서 채웠기 때문이에요. 다만 브라우저가 늘 내 의도대로 고쳐 주지는 않으니, 닫는 태그는 직접 쓰는 습관을 들이세요.
</Section>

<Section kind="pitfalls">
<Pitfall misconception="html.mc.tag-is-element">
<Wrong>`<p>`가 문단 요소다. 요소와 태그는 같은 말이다.</Wrong>
<Actual>`<p>`는 여는 태그일 뿐이에요. 문단 요소는 `<p>`부터 내용, `</p>`까지 전체예요.</Actual>
<Right>요소 = 여는 태그 + 내용 + 닫는 태그예요. 단, `<img>` 같은 빈 요소는 여는 태그 하나가 요소 전체예요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.attribute-shown-on-page">
<Wrong>`<p title="설명">안녕</p>`을 열면 화면에 "설명"도 함께 보인다.</Wrong>
<Actual>화면에는 "안녕"만 보여요. 속성 값은 화면에 글자로 그려지지 않아요.</Actual>
<Right>속성은 브라우저에게 주는 추가 정보예요. 화면에 보일 글자는 여는 태그와 닫는 태그 사이에 써요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.overlapping-tags">
<Wrong>`<p><strong>꼭 지켜요</p></strong>`도 화면이 비슷하게 나오니 괜찮다.</Wrong>
<Actual>엇갈린 태그는 잘못된 HTML이에요. 브라우저가 추측해서 구조를 고치는데, 그 결과가 내 의도와 다를 수 있어요.</Actual>
<Right>나중에 연 요소를 먼저 닫아요. `<p><strong>꼭 지켜요</strong></p>`처럼 안쪽부터 닫으면 돼요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.head-is-visible">
<Wrong>`<head>` 안의 `<title>` 글자가 페이지 맨 위에 큰 제목으로 나온다.</Wrong>
<Actual>`title`은 브라우저 탭에만 보이고 페이지 본문에는 나오지 않아요.</Actual>
<Right>`head`에는 화면에 그리지 않는 문서 정보를, `body`에는 화면에 보일 내용을 넣어요. 본문의 큰 제목은 `body` 안의 `h1`으로 써요.</Right>
</Pitfall>

<Pitfall misconception="html.mc.dom-is-source">
<Wrong>DOM 트리는 내가 쓴 HTML과 글자 하나까지 똑같고, 빠뜨린 태그는 빠진 채로 남는다.</Wrong>
<Actual>브라우저는 HTML을 읽어 구조를 새로 만들면서 빠진 `html`·`head`·`body`나 닫지 않은 `</p>`를 채워 넣어요.</Actual>
<Right>DOM 트리는 브라우저가 만든 구조예요. 코드와 다를 수 있으니, 의도한 구조를 정확히 쓰는 것이 좋아요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
브라우저의 개발자 도구(<Key>F12</Key>)를 열고 **Elements**(요소) 탭을 보면, 지금 페이지의 DOM 트리를 접었다 펼쳤다 하며 볼 수 있어요. "페이지 소스 보기"는 서버가 보낸 HTML 글자 그대로이고, Elements 탭은 브라우저가 만든 DOM 트리라서 둘이 조금 다를 때가 있어요. 화면이 이상할 때 웹 개발자는 Elements 탭에서 실제 구조가 의도와 같은지 먼저 확인해요.

새 HTML 파일을 만들 때는 위의 뼈대를 그대로 복사해 시작하는 경우가 많아요. 코드 편집기 대부분은 `!`를 입력하고 <Key>Tab</Key>을 누르면 이 뼈대를 자동으로 써 줘요.
</Section>

<Section kind="summary">
- 요소는 여는 태그 + 내용 + 닫는 태그 전체예요. `img` 같은 빈 요소는 여는 태그만 써요.
- 속성은 여는 태그 안에 `이름="값"`으로 쓰고, 속성 값은 화면에 글자로 나오지 않아요.
- 요소는 상자 안의 상자처럼 중첩하고, 나중에 연 요소를 먼저 닫아요.
- 문서의 뼈대는 `<!doctype html>`, `html`, `head`(화면에 안 보이는 정보), `body`(화면에 보일 내용)예요.
- 브라우저는 HTML을 읽어 부모·자식으로 이어진 DOM 트리를 만들고, 빠진 부분은 스스로 채워요.
</Section>
