<Section kind="objectives">
- 대괄호로 배열을 만들고, `arr[i]`로 원하는 위치의 요소를 읽을 수 있어요.
- 범위 밖 인덱스와 음수 인덱스가 오류가 아니라 `undefined`가 된다는 것을 알고, 그 결과를 예측할 수 있어요.
- `length`로 요소의 개수와 마지막 요소(`arr[arr.length - 1]`)를 구하고, 반복의 범위를 맞게 정할 수 있어요.
- 인덱스에 대입해 요소를 바꾸고, `const`로 만든 배열도 요소는 바꿀 수 있다는 것을 설명할 수 있어요.
</Section>

<Section kind="intro">
반 학생 다섯 명의 시험 점수를 프로그램에 저장한다고 해 봐요. 지금까지 배운 방법이라면 변수를 다섯 개 만들어야 해요.

```js
const score1 = 72;
const score2 = 95;
const score3 = 88;
const score4 = 64;
const score5 = 91;
```

평균을 구하려면 `score1 + score2 + ...`를 일일이 써야 하고, 학생이 30명으로 늘면 변수도 30개가 돼요. 반복문으로 "모든 점수"를 차례로 볼 방법도 없어요. 변수 이름은 `score1`, `score2`처럼 비슷해도 프로그램에게는 서로 관계없는 이름이기 때문이에요.

이럴 때 쓰는 것이 **배열**(array)이에요. 배열은 여러 값을 **순서대로 담는 목록** 하나예요. 모듈 7에서 `split`이 돌려준 "조각들의 목록"이 바로 배열이었어요. 이 단원에서는 배열을 직접 만들고, 요소를 읽고, 개수를 세고, 바꾸는 법을 배워요.
</Section>

<Section kind="principle">
### 배열 만들기

배열은 대괄호 `[]` 안에 값을 쉼표로 나열해서 만들어요. 배열에 든 값 하나하나를 **요소**(element)라고 해요.

```js
const scores = [72, 95, 88, 64, 91];
const fruits = ["사과", "배", "귤"];
const empty = [];
```

- 요소는 적은 순서 그대로 저장돼요.
- `[]`는 요소가 하나도 없는 **빈 배열**이에요.
- 한 배열에 숫자와 문자열처럼 서로 다른 자료형을 섞어 담아도 돼요. 다만 보통은 같은 종류의 값을 담아요. 그래야 반복으로 같은 처리를 하기 쉬워요.

### 인덱스로 요소 읽기

배열의 요소는 문자열의 글자처럼 **0부터 시작하는 번호**(인덱스)를 가져요. `배열[인덱스]`로 요소 하나를 읽어요.

| 인덱스 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 요소 | 72 | 95 | 88 | 64 | 91 |

```js
console.log(scores[0]); // 72 (첫 번째 요소)
console.log(scores[3]); // 64 (네 번째 요소)
```

인덱스를 이해하는 방법은 두 가지예요.

1. **사물함 번호로 보기**: 배열은 사물함이 한 줄로 붙어 있는 것이고, 인덱스는 사물함 번호예요. 번호가 0번부터 붙어 있어서 "네 번째 사물함"은 3번이에요.
1. **앞에서 떨어진 거리로 보기**: 인덱스는 "맨 앞에서 몇 칸 떨어졌나"예요. 첫 요소는 0칸 떨어져 있으니 0, 두 번째 요소는 1칸 떨어져 있으니 1이에요.

인덱스 자리에는 숫자뿐 아니라 변수나 식도 쓸 수 있어요. `scores[i]`, `scores[i + 1]`처럼 쓸 수 있어서 반복문과 함께 쓰기 좋아요.

없는 인덱스를 읽으면 어떻게 될까요? 요소가 5개인 배열의 `scores[10]`이나 `scores[-1]`은 **오류가 나지 않고 `undefined`**가 나와요. "그 자리에 아무것도 없다"는 뜻이에요. 문자열의 범위 밖 인덱스와 같은 규칙이에요.

### length: 요소의 개수

`배열.length`는 요소의 **개수**예요. 괄호 없이 써요.

```js
console.log(scores.length); // 5
console.log(empty.length);  // 0
```

인덱스가 0부터 시작하므로 **마지막 요소의 인덱스는 `length - 1`**이에요. 요소가 5개면 인덱스는 0~4예요. 그래서 배열의 길이가 얼마든 마지막 요소는 이렇게 읽어요.

```js
console.log(scores[scores.length - 1]); // 91
```

반복문으로 모든 요소를 볼 때도 `length`를 써요. `i`가 0부터 `length - 1`까지 가야 하므로 조건은 `i < scores.length`예요.

```js
let sum = 0;
for (let i = 0; i < scores.length; i++) {
  sum += scores[i];
}
console.log(sum / scores.length); // 82
```

학생이 30명으로 늘어도 이 반복은 고칠 필요가 없어요. 도입부의 "변수 다섯 개" 문제가 이렇게 풀려요.

### 요소 바꾸기

여기서 배열이 문자열과 크게 다른 점이 나와요. 문자열은 바꿀 수 없었지만, **배열은 바꿀 수 있어요.** 인덱스에 대입하면 그 자리의 요소가 바뀌어요.

```js
const fruits = ["사과", "배", "귤"];
fruits[1] = "포도";
console.log(fruits); // ["사과", "포도", "귤"]
```

<CompareTable columns={["문자열", "배열"]}>
<Row label="만들기">`"abc"` | `["a", "b", "c"]`</Row>
<Row label="인덱스로 읽기">`str[0]` | `arr[0]`</Row>
<Row label="개수">`str.length` (글자 수) | `arr.length` (요소 수)</Row>
<Row label="범위 밖 읽기">`undefined` | `undefined`</Row>
<Row label="인덱스로 바꾸기">불가능 (엄격 모드에서 `TypeError`) | 가능</Row>
</CompareTable>

`fruits`를 `const`로 만들었는데도 요소를 바꿀 수 있었어요. `const`는 **변수에 다른 값을 다시 대입하는 것**만 막아요. `fruits = ["딸기"];`처럼 변수 자체에 새 배열을 대입하면 `TypeError`가 나지만, 배열 안의 요소를 바꾸는 것은 막지 않아요. 왜 그런지는 모듈 9 "참조와 복사"에서 자세히 배워요.

인덱스에 대입할 때 지금 `length`보다 큰 인덱스를 쓰면 배열이 그만큼 늘어나요. 이건 흔한 실수의 원인이라 아래 "흔한 실수"에서 다시 봐요.
</Section>

    best = scores[i];
  }

<Section kind="pitfalls">
<Pitfall misconception="js.mc.array-out-of-range-throws">
<Wrong>요소가 3개인 배열에서 `colors[3]`을 읽으면 오류가 나서 프로그램이 멈춘다.</Wrong>
<Actual>첫 번째 예제에서 `colors[3]`은 `undefined`였고, 다음 줄도 그대로 실행됐어요. 범위 밖 인덱스는 오류가 아니에요.</Actual>
<Right>오류가 나지 않기 때문에 오히려 조심해야 해요. 인덱스를 잘못 계산하면 `undefined`가 조용히 섞여 들어가 엉뚱한 결과(`NaN` 등)가 나와요. 결과에 `undefined`가 보이면 인덱스 범위부터 확인해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-negative-index-last">
<Wrong>`scores[-1]`은 뒤에서 첫 번째, 즉 마지막 요소다.</Wrong>
<Actual>

`-1`이라는 인덱스에는 요소가 없어서 `undefined`예요.

```js
const scores = [72, 95, 88];
console.log(scores[-1]); // undefined
```
</Actual>
<Right>마지막 요소는 `scores[scores.length - 1]`로 읽어요. 음수가 "뒤에서부터"라는 뜻이 되는 것은 모듈 7의 `slice` 같은 메서드 안에서뿐이에요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-same-type-only">
<Wrong>배열에는 같은 자료형만 담을 수 있어서 `["민지", 17, true]`처럼 섞으면 오류가 난다.</Wrong>
<Actual>오류 없이 만들어져요. `["민지", 17, true][1]`은 숫자 `17`이에요.</Actual>
<Right>섞어 담을 수는 있지만, 보통은 같은 종류의 값만 담아요. 점수 목록이면 숫자만, 이름 목록이면 문자열만 담아야 반복으로 같은 계산을 할 수 있어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-last-index-is-length">
<Wrong>요소가 4개인 배열의 마지막 요소는 `scores[scores.length]`, 즉 `scores[4]`다.</Wrong>
<Actual>두 번째 예제에서 `scores[scores.length]`는 `undefined`였어요. 반복 조건을 `i <= scores.length`로 쓰면 마지막에 `scores[4]`(`undefined`)까지 더해서 합계가 `NaN`이 돼요.</Actual>
<Right>인덱스는 0부터라 마지막 인덱스는 `length - 1`이에요. 마지막 요소는 `scores[scores.length - 1]`, 반복 조건은 `i < scores.length`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-length-counts-filled">
<Wrong>요소가 3개인 배열에 `arr[9] = 1;`을 하면 요소가 하나 늘었으니 `length`는 4다.</Wrong>
<Actual>

`length`는 10이 돼요. `length`는 "들어 있는 값의 개수"가 아니라 "가장 큰 인덱스 + 1"이에요. 값을 넣지 않은 3~8번 자리는 비어 있고, 읽으면 `undefined`예요.

```js
const arr = [5, 6, 7];
arr[9] = 1;
console.log(arr.length); // 10
console.log(arr[5]);     // undefined
```
</Actual>
<Right>끝에 하나를 덧붙이고 싶다면 인덱스를 어림하지 말고 `arr[arr.length] = 값`처럼 정확히 `length`번 자리에 넣어요. 다음 단원에서는 이 일을 해 주는 `push` 메서드를 배워요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-immutable-like-string">
<Wrong>문자열에서 `str[0] = "A"`가 안 되었으니, 배열도 `arr[0] = 10`으로 요소를 바꿀 수 없다. 특히 `const` 배열은 절대 못 바꾼다.</Wrong>
<Actual>세 번째 예제에서 `const`로 만든 `seats`의 요소를 두 번이나 바꿨어요. 오류가 난 것은 네 번째 예제처럼 변수 자체에 새 배열을 대입했을 때뿐이에요.</Actual>
<Right>배열은 바꿀 수 있는 값이에요. 글자를 바꾸고 싶은 문자열은 `split("")`으로 배열로 만든 뒤 요소를 바꾸고 `join("")`으로 다시 합치는 방법도 있어요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
웹 페이지의 이미지 슬라이드(캐러셀)는 이미지 주소를 배열에 담고, "지금 보는 번호"를 인덱스로 기억해요.

```js
const slides = ["sea.jpg", "mountain.jpg", "city.jpg"];
let current = 0;

function next() {
  current = current + 1;
  if (current > slides.length - 1) {
    current = 0; // 마지막 다음은 처음으로
  }
  console.log("지금 보이는 사진: " + slides[current]);
}

next(); // mountain.jpg
next(); // city.jpg
next(); // sea.jpg
```

- 마지막 인덱스는 `slides.length - 1`이라서, 그보다 커지면 0으로 돌아가요. 이 확인이 없으면 `slides[3]`을 읽어 `undefined`가 보여요.
- 사진을 추가해도 `length`를 쓰는 코드는 고칠 필요가 없어요.
- 장바구니의 상품 목록, 채팅 메시지 목록, 게임의 점수 기록처럼 "같은 종류의 값 여러 개"는 거의 모두 배열에 담아요.

<Section kind="summary">
- 배열은 여러 값을 순서대로 담는 목록이에요. `[값, 값, 값]`처럼 대괄호와 쉼표로 만들어요.
- 요소는 0부터 시작하는 인덱스로 `arr[i]`처럼 읽어요. 인덱스 자리에 변수나 식도 쓸 수 있어요.
- 범위 밖 인덱스와 음수 인덱스는 오류가 아니라 `undefined`예요.
- `arr.length`는 요소 개수이고, 마지막 요소는 `arr[arr.length - 1]`이에요. 모든 요소를 보는 반복 조건은 `i < arr.length`예요.
- 배열은 바꿀 수 있어요. `arr[i] = 값`으로 요소를 바꾸고, `const` 배열도 요소는 바꿀 수 있어요. 변수에 새 배열을 다시 대입하는 것만 막혀요.
</Section>
