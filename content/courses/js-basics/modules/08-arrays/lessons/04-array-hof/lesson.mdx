<Section kind="objectives">
- `map`으로 요소마다 바꾼 같은 길이의 새 배열을 만들고, 콜백이 값을 **돌려줘야** 한다는 것을 알고 쓸 수 있어요.
- `filter`·`find`·`some`·`every` 중 요구사항에 맞는 메서드를 골라, 각각이 돌려주는 값(배열·요소 하나·`true`/`false`)을 예측할 수 있어요.
- `reduce`로 합계·개수·최댓값처럼 값 하나를 모으고, 초기값과 누적값 반환의 역할을 설명할 수 있어요.
- `filter`·`map`·`reduce`를 이어 써서 여러 단계의 목록 처리를 하고, 순서에 따라 결과가 달라지는 것을 예측할 수 있어요.
</Section>

<Section kind="intro">
장바구니에 상품 가격이 `[8000, 3500, 12000, 5000, 2000]`처럼 담겨 있어요. 쇼핑몰 화면에는 이런 일이 한꺼번에 필요해요.

- 가격마다 배송비 500원을 더한 목록 보여 주기
- 5000원 이상인 상품만 골라 "할인 대상"으로 표시하기
- 3만 원이 넘는 상품이 하나라도 있는지 확인하기
- 전체 합계 구하기

앞 단원에서 배운 `for...of`로도 모두 만들 수 있어요. 그런데 매번 빈 배열이나 누적 변수를 만들고, 반복을 쓰고, `push`하거나 더하는 코드를 되풀이해야 해요. 코드가 길어질수록 "이 반복이 무슨 일을 하는지"가 잘 안 보이고, 누적 변수를 반복 안에서 초기화하는 것 같은 실수도 생겨요.

배열에는 이런 흔한 일을 이름으로 부를 수 있는 메서드가 있어요. 바꾸기는 `map`, 고르기는 `filter`, 첫 하나 찾기는 `find`, 확인하기는 `some`·`every`, 하나로 모으기는 `reduce`예요. 이 단원에서는 이 메서드들을 배우고, 이어 써서 위의 일들을 한두 줄로 해결해 봐요.
</Section>

<Section kind="principle">
### 반복은 메서드가, 요소마다 할 일은 콜백이

모듈 6에서 함수를 다른 함수에 넘기면, 받은 함수가 알맞은 때에 불러 준다는 것(콜백)을 배웠어요. 앞 단원의 `forEach`도 요소마다 콜백을 불러 줬죠. 이처럼 **함수를 인수로 받는 함수**를 고차 함수라고 해요.

이 단원의 메서드들은 모두 같은 방식으로 일해요.

1. 메서드가 배열을 처음부터 끝까지 반복해요.
1. 요소마다 콜백을 `(요소, 인덱스)` 인수로 불러요. 인덱스가 필요 없으면 매개변수를 하나만 써요.
1. 콜백이 **돌려준 값**을 보고, 메서드마다 정해진 방식으로 결과를 만들어요.

그래서 우리가 쓰는 것은 "요소 하나에 무엇을 할지"뿐이에요. 메서드마다 콜백이 돌려줘야 하는 것과 메서드가 돌려주는 것을 표로 정리하면 이래요.

| 메서드 | 하는 일 | 콜백이 돌려줄 것 | 메서드가 돌려주는 값 |
|---|---|---|---|
| `map` | 바꾸기 | 그 자리에 들어갈 새 값 | 같은 길이의 **새 배열** |
| `filter` | 고르기 | 남길지(참) 뺄지(거짓) | 고른 요소의 **새 배열**, 없으면 `[]` |
| `find` | 첫 하나 찾기 | 찾는 요소인지(참·거짓) | 첫 요소 **하나**, 없으면 `undefined` |
| `findIndex` | 첫 위치 찾기 | 찾는 요소인지(참·거짓) | 첫 요소의 **인덱스**, 없으면 `-1` |
| `some` | 하나라도? | 조건에 맞는지(참·거짓) | `true` 또는 `false` |
| `every` | 모두? | 조건에 맞는지(참·거짓) | `true` 또는 `false` |
| `reduce` | 하나로 모으기 | **다음 누적값** | 마지막 누적값 하나 |

`forEach`와 마찬가지로 이 메서드들은 **원래 배열을 바꾸지 않아요.** 결과를 쓰려면 변수에 담거나 바로 써야 해요.

### map: for 반복과 나란히 보기

`map`이 하는 일을 앞 단원의 반복으로 쓰면 다음과 같아요. 두 코드는 같은 결과를 내요.

```js
const prices = [3000, 12000, 4500];

// for...of로 쓴 코드
const withFee1 = [];
for (const p of prices) {
  withFee1.push(p + 500);
}

// map으로 쓴 코드
const withFee2 = prices.map((p) => p + 500);
```

빈 배열 만들기, 반복, `push`를 `map`이 대신해 줘요. 우리는 "요소 `p`를 `p + 500`으로 바꾼다"만 콜백으로 넘겨요. 콜백이 돌려준 값이 같은 자리에 들어가므로 결과는 **항상 원래 배열과 길이가 같아요.**

콜백의 반환값이 중요하다는 점을 기억하세요. 화살표 함수에 중괄호를 쓰면 `return`을 써야 값을 돌려줘요(모듈 6). `prices.map((p) => { p + 500; })`처럼 쓰면 콜백이 `undefined`를 돌려줘서 결과는 `[undefined, undefined, undefined]`예요.

### filter, find, some, every: 콜백은 참·거짓을 돌려줘요

네 메서드의 콜백은 모두 "이 요소가 조건에 맞나?"에 참·거짓으로 답해요. 차이는 그 답을 모아 **무엇을 돌려주느냐**예요.

```js
const temps = [18, 23, 31, 27];
temps.filter((t) => t > 25);    // [31, 27]  맞는 것 모두 (배열)
temps.find((t) => t > 25);      // 31        맞는 첫 요소 하나
temps.findIndex((t) => t > 25); // 2         맞는 첫 요소의 인덱스
temps.some((t) => t > 25);      // true      하나라도 맞나?
temps.every((t) => t > 25);     // false     모두 맞나?
```

- `filter`는 콜백이 참을 돌려준 요소를 **남겨요.** 조건에 맞는 것을 지우는 게 아니에요.
- `find`·`findIndex`·`some`·`every`는 결과가 정해지면 바로 멈춰요. `find`는 처음 맞는 요소를 찾자마자, `every`는 처음 틀린 요소를 만나자마자 끝나요.

### reduce: 누적 패턴을 메서드로

모듈 5의 누적 패턴은 "반복 전에 누적 변수를 정하고, 요소마다 누적 변수를 새 값으로 바꾸는" 코드였어요. `reduce`는 이것을 메서드로 만든 거예요.

```js
const cart = [3000, 12000, 4500];
const total = cart.reduce((acc, price) => acc + price, 0);
//                        ─────────────────────────  ─
//                        콜백: 다음 누적값을 돌려줌   초기값
```

- 두 번째 인수 `0`이 **초기값**, 즉 처음 누적값이에요.
- 콜백의 첫 번째 매개변수가 **누적값**(`acc`, accumulator), 두 번째가 **현재 요소**예요. 순서가 뜻을 정해요.
- 콜백이 돌려준 값이 **다음 누적값**이 되고, 마지막 요소까지 끝났을 때의 누적값이 `reduce`의 결과예요.

| 단계 | `acc` (들어온 누적값) | `price` | 콜백이 돌려준 값 |
|---|---|---|---|
| 1 | 0 (초기값) | 3000 | 3000 |
| 2 | 3000 | 12000 | 15000 |
| 3 | 15000 | 4500 | 19500 → 결과 |

초기값을 생략하면 **첫 요소가 초기값**이 되고 콜백은 두 번째 요소부터 불려요. 합계는 우연히 같지만, 빈 배열에서는 `TypeError`가 나고, 요소를 가공하는 콜백에서는 첫 요소만 가공되지 않아요. 그래서 이 과정에서는 **초기값을 항상 적어요.**

### 이어 쓰기

`map`과 `filter`는 새 배열을 돌려주므로, 돌려받은 배열에 바로 다음 메서드를 붙일 수 있어요. 문자열 메서드를 이어 쓴 것과 같아요(모듈 7). 왼쪽부터 차례로 실행되고, 각 메서드는 **바로 앞 메서드가 돌려준 배열**을 받아요.

```js
const total = prices
  .filter((p) => p >= 5000)  // 고르고
  .map((p) => p - 1000)      // 바꾸고
  .reduce((acc, p) => acc + p, 0); // 모으기
```

줄 앞에 점을 찍어 메서드마다 한 줄씩 쓰면 단계가 잘 보여요.
</Section>

<Section kind="pitfalls">
<Pitfall misconception="js.mc.map-mutates-original">
<Wrong>`nums.map((n) => n * 2);`만 실행하면 `nums`의 요소가 두 배로 바뀐다.</Wrong>
<Actual>첫 번째 예제에서 `map`을 부른 뒤에도 `prices`는 `[3000, 12000, 4500]` 그대로였어요. `map`은 새 배열을 돌려줄 뿐이에요.</Actual>
<Right>결과를 `const doubled = nums.map((n) => n * 2);`처럼 변수에 담아 써요. 원래 배열을 그대로 두는 성질 덕분에 원본과 바꾼 결과를 함께 쓸 수 있어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.map-callback-no-return">
<Wrong>`nums.map((n) => { n * 2; })`처럼 중괄호 안에 식만 써도 두 배가 된 배열이 나온다.</Wrong>
<Actual>

중괄호 본문에 `return`이 없으면 콜백은 `undefined`를 돌려줘요. `map`은 그 `undefined`를 그대로 담아요.

```js
const nums = [1, 2, 3];
const doubled = nums.map((n) => { n * 2; });
console.log(doubled); // [undefined, undefined, undefined]
```
</Actual>
<Right>중괄호를 빼고 `(n) => n * 2`로 쓰거나, 중괄호를 쓸 때는 `return n * 2;`를 써요. 모듈 6에서 배운 화살표 함수 규칙과 같아요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.map-can-skip-items">
<Wrong>`map` 콜백에서 조건에 맞지 않는 요소는 아무것도 돌려주지 않으면 결과에서 빠진다.</Wrong>
<Actual>

`map`의 결과는 항상 원래 배열과 길이가 같아요. 아무것도 돌려주지 않은 자리에는 `undefined`가 들어가요.

```js
const scores = [72, 58, 90];
const passed = scores.map((s) => {
  if (s >= 60) {
    return s + "점";
  }
});
console.log(passed); // ["72점", undefined, "90점"]
```
</Actual>
<Right>요소를 고르는 일은 `filter`가 해요. 고른 뒤 바꾸려면 `scores.filter((s) => s >= 60).map((s) => s + "점")`처럼 이어 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.filter-removes-matching">
<Wrong>`scores.filter((s) => s >= 60)`은 60점 이상을 걸러 내서(지워서) 60점 미만만 남긴다.</Wrong>
<Actual>두 번째 예제에서 결과는 `[72, 95, 88, 60]`이었어요. 콜백이 참을 돌려준 요소가 **남아요.**</Actual>
<Right>`filter`의 콜백에는 "남길 조건"을 써요. 빼고 싶은 것이 있으면 반대 조건을 써요. 예를 들어 빈 문자열을 빼려면 `words.filter((w) => w !== "")`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.filter-returns-first">
<Wrong>조건에 맞는 요소가 하나뿐이면 `filter`가 그 요소 자체를 돌려준다.</Wrong>
<Actual>두 번째 예제의 `scores.filter((s) => s === 95)`는 `95`가 아니라 `[95]`였어요. 그래서 `result + 5`는 `100`이 아니라 문자열 `"955"`가 돼요.</Actual>
<Right>`filter`는 항상 배열을 돌려줘요. 맞는 요소 하나가 필요하면 `find`를 쓰거나 결과의 `[0]`을 읽어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.filter-empty-is-undefined">
<Wrong>`filter`로 고를 요소가 없으면 결과가 `undefined`나 `null`이라서 `if (result)`로 찾았는지 확인할 수 있다.</Wrong>
<Actual>

고를 요소가 없으면 빈 배열 `[]`이에요. 모듈 3에서 배운 대로 빈 배열은 truthy라서 `if` 블록이 늘 실행돼요.

```js
const result = [72, 95].filter((s) => s > 100);
if (result) {
  console.log("찾았어요"); // 하나도 없는데 실행돼요
}
```
</Actual>
<Right>결과가 있는지는 `result.length > 0`으로 확인해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.find-returns-all">
<Wrong>`temps.find((t) => t > 25)`는 25보다 큰 온도를 모두 담은 배열을 돌려준다.</Wrong>
<Actual>세 번째 예제에서 `find`는 `31` 하나만 돌려줬어요. 31과 27이 모두 맞지만, 처음 맞는 31을 찾자마자 멈춰요.</Actual>
<Right>맞는 것을 모두 원하면 `filter`, 첫 하나만 원하면 `find`를 써요. 이름을 "찾기 하나(find)"와 "거르기(filter)"로 기억하면 쉬워요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.find-not-found-minus-one">
<Wrong>`indexOf`처럼 `find`도 못 찾으면 `-1`을 돌려주니 `if (found !== -1)`로 확인한다.</Wrong>
<Actual>세 번째 예제에서 못 찾은 `find`는 `undefined`였어요. `undefined !== -1`은 항상 참이라 못 찾아도 "찾았다"고 처리하게 돼요.</Actual>
<Right>`find`의 결과는 `found !== undefined`로 확인해요. `-1`을 돌려주는 것은 인덱스를 돌려주는 `findIndex`와 `indexOf`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.every-empty-false">
<Wrong>`[].every((t) => t >= 20)`은 확인할 요소가 없으니 `false`다.</Wrong>
<Actual>세 번째 예제의 마지막 줄은 `true`였어요. `every`는 조건에 맞지 않는 요소를 찾으면 `false`인데, 빈 배열에는 그런 요소가 없어요.</Actual>
<Right>"빈 목록은 통과가 아니다" 같은 요구사항이 있으면 `list.length > 0 && list.every(...)`처럼 길이를 먼저 확인해요. `some`은 반대로 빈 배열에서 `false`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.some-returns-element">
<Wrong>`temps.some((t) => t >= 30)`은 처음 찾은 30 이상의 온도를 돌려준다.</Wrong>
<Actual>세 번째 예제에서 결과는 `31`이 아니라 `true`였어요.</Actual>
<Right>`some`과 `every`는 항상 `true`나 `false`만 돌려줘요. 찾은 요소가 필요하면 `find`를 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.reduce-initial-optional-safe">
<Wrong>`reduce`의 초기값은 생략해도 0부터 시작한 것과 늘 같다.</Wrong>
<Actual>

초기값을 생략하면 첫 요소가 초기값이 되고, 콜백은 두 번째 요소부터 불려요.

```js
const nums = [1, 2, 3];
// 초기값 0: 2 + 4 + 6
console.log(nums.reduce((acc, n) => acc + n * 2, 0)); // 12
// 초기값 생략: 첫 요소 1은 두 배가 안 됨
console.log(nums.reduce((acc, n) => acc + n * 2)); // 11
// 빈 배열 + 초기값 생략
[].reduce((acc, n) => acc + n);
// TypeError: Reduce of empty array with no initial value
```
</Actual>
<Right>초기값을 항상 적어요. 합계는 `0`, 개수 세기는 `0`, 문자열 이어 붙이기는 `""`처럼 "아직 아무것도 모으지 않은 상태"를 초기값으로 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.reduce-callback-no-return">
<Wrong>콜백 안에서 `acc + price`를 계산하거나 `acc`에 대입하기만 하면 누적값이 알아서 다음으로 이어진다.</Wrong>
<Actual>`reduce`는 콜백이 **돌려준 값**을 다음 `acc`로 써요. `(acc, price) => { acc + price; }`는 `undefined`를 돌려주므로 두 번째 호출의 `acc`는 `undefined`가 되고, `[3000, 12000, 4500]`의 결과는 `undefined`예요.</Actual>
<Right>네 번째 예제처럼 중괄호 본문에서는 `return acc + price;`를 써요. 본문이 식 하나면 `(acc, price) => acc + price`처럼 중괄호 없이 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.reduce-params-swapped">
<Wrong>`reduce((price, total) => ...)`처럼 첫 번째 매개변수가 현재 요소, 두 번째가 누적값이다.</Wrong>
<Actual>매개변수 이름은 아무 뜻이 없어요. 첫 번째 자리에 무조건 누적값이 들어와요. 이름을 거꾸로 지으면 `price`에 합계가, `total`에 가격이 들어와서 코드를 읽는 사람도 헷갈려요.</Actual>
<Right>`(acc, item)`, `(sum, price)`, `(count, word)`처럼 **누적값을 먼저** 쓰는 이름을 붙여요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.chain-order-irrelevant">
<Wrong>`map`과 `filter`를 이어 쓸 때 순서를 바꿔도 결과는 같다.</Wrong>
<Actual>다섯 번째 예제에서 순서만 바꿨는데 22000과 18000으로 달랐어요. 뒤의 `filter`는 앞의 `map`이 바꾼 값을 검사해요.</Actual>
<Right>요구사항을 단계로 나눠 "무엇을 기준으로 고르는가(원래 값? 바꾼 값?)"를 먼저 정하고, 그 순서대로 이어 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.chain-after-foreach">
<Wrong>`forEach` 뒤에도 `filter`나 `map`을 이어 쓸 수 있다.</Wrong>
<Actual>

`forEach`는 `undefined`를 돌려줘요(앞 단원). 그래서 뒤에 메서드를 이으면 `undefined`에서 메서드를 찾다가 오류가 나요.

```js
[1, 2, 3].forEach((n) => n * 2).filter((n) => n > 2);
// TypeError: Cannot read properties of undefined (reading 'filter')
```
</Actual>
<Right>이어 쓸 수 있는 것은 새 배열을 돌려주는 `map`·`filter`예요. 바꾼 값으로 이어 가려면 `forEach` 대신 `map`을 써요.</Right>
</Pitfall>

<Section kind="in-practice">
쇼핑몰 검색창은 입력한 글자가 들어 있는 상품만 보여 줘요. 대소문자와 앞뒤 공백을 무시하려면 검색어와 상품 이름을 같은 모양으로 맞춘 뒤 `filter`로 골라요.

```js
const products = ["Apple Juice", "Grape Jam", "apple pie", "Milk"];
const keyword = "  APPLE ";

const word = keyword.trim().toLowerCase();
const results = products.filter((name) => name.toLowerCase().includes(word));

if (results.length > 0) {
  console.log(`검색 결과 ${results.length}개: ${results.join(", ")}`);
} else {
  console.log("검색 결과가 없어요");
}
// 검색 결과 2개: Apple Juice, apple pie
```

- 결과가 있는지는 `results.length > 0`으로 확인해요. 빈 배열 `[]`도 truthy라서 `if (results)`는 항상 참이에요.
- 화면에 목록을 그릴 때는 `map`으로 상품 이름마다 표시할 문자열(나중에는 HTML 요소)을 만들고, 장바구니 합계는 `reduce`로 구해요. "있는지 확인"(`some`), "모두 체크했는지"(`every`), "주문 번호로 하나 찾기"(`find`)도 화면 코드에서 자주 써요.
</Section>

<Section kind="summary">
- 고차 함수는 함수를 인수로 받는 함수예요. 배열 메서드가 반복을 맡고, 우리는 요소마다 할 일을 콜백으로 넘겨요. 콜백은 `(요소, 인덱스)`를 받아요.
- `map`은 콜백이 돌려준 값으로 같은 길이의 새 배열을 만들어요. 중괄호 본문이면 `return`이 꼭 필요해요.
- `filter`는 콜백이 참을 돌려준 요소를 남긴 새 배열을 만들고, 맞는 요소가 없으면 `[]`예요. 결과가 있는지는 `length`로 확인해요.
- `find`는 맞는 첫 요소 하나(없으면 `undefined`)를, `some`·`every`는 `true`/`false`를 돌려줘요. 빈 배열에서 `every`는 `true`, `some`은 `false`예요.
- `reduce((acc, item) => 다음 누적값, 초기값)`은 값 하나로 모아요. 콜백은 다음 누적값을 돌려주고, 초기값은 항상 적어요.
- `map`·`filter`·`reduce`는 원래 배열을 바꾸지 않아요. 이어 쓰면 왼쪽부터 실행되므로 순서에 따라 결과가 달라질 수 있어요.
</Section>
