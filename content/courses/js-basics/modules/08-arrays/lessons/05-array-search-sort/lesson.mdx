<Section kind="objectives">
- `includes`·`indexOf`로 배열에 값이 있는지와 위치를 찾고, 요소 **전체**가 자료형까지 같아야 찾는다는 것을 설명할 수 있어요.
- `sort()`가 기본으로 요소를 **문자열로 바꿔 사전순**으로 정렬한다는 것을 알고, 비교 함수로 숫자를 오름차순·내림차순으로 정렬할 수 있어요.
- `sort`가 원래 배열을 바꾸고 같은 배열을 돌려준다는 것을 알고, `slice()`로 복사한 뒤 정렬해 원본을 지킬 수 있어요.
- `slice`와 `concat`으로 원래 배열을 바꾸지 않고 일부를 복사하거나 두 배열을 이을 수 있어요.
</Section>

<Section kind="intro">
게임 점수판을 만든다고 해 볼게요. 점수가 `[70, 100, 85, 9]`처럼 들어온 순서대로 쌓여 있어요. 점수판에 보여 주려면 할 일이 세 가지예요.

1. 방금 입력한 점수가 이미 기록에 **있는지** 확인하기
1. 높은 점수부터 **정렬**하기
1. 정렬한 목록에서 **위의 3개만 잘라** 보여 주기. 단, 들어온 순서의 원래 기록은 그대로 남겨 두기

앞 단원들에서 배운 반복과 `filter`로도 할 수는 있지만, 배열에는 이런 일을 위한 메서드가 따로 있어요. 문자열에서 배운 `includes`·`indexOf`·`slice`와 이름이 같은 메서드도 있어서 익숙할 거예요. 다만 **이름이 같아도 동작이 조금 다른 곳**과, 숫자를 정렬할 때 많은 사람이 빠지는 함정을 이 단원에서 함께 짚어요.
</Section>

<Section kind="principle">
### 찾기: includes와 indexOf

| 메서드 | 돌려주는 값 | `["사과", "배", "귤", "배"]`에 쓴 예 |
|---|---|---|
| `includes(값)` | 같은 요소가 있으면 `true`, 없으면 `false` | `includes("배")` → `true` |
| `indexOf(값)` | 같은 요소가 **처음** 나오는 인덱스, 없으면 `-1` | `indexOf("배")` → `1`, `indexOf("감")` → `-1` |

문자열의 `includes`·`indexOf`와 쓰는 법은 같지만, **무엇을 같다고 보는지**가 달라요.

- 문자열의 `includes`는 글자의 **일부**를 찾아요. `"banana".includes("nan")`은 `true`예요.
- 배열의 `includes`는 **요소 하나와 통째로** 비교해요. `["banana"].includes("nan")`은 `false`예요. `"nan"`이라는 요소가 없으니까요.
- 비교는 `===`처럼 **자료형까지** 봐요. `[1, 2, 3].includes("2")`는 `false`예요. 문자열 `"2"`와 숫자 `2`는 다른 값이에요.

`indexOf`가 못 찾았을 때의 `-1`은 문자열 단원과 같아요. 0은 "맨 앞에서 찾았다"는 뜻이라서, 있는지 확인할 때는 `includes`를 쓰거나 `indexOf(값) !== -1`로 비교해요.

### 정렬: sort

`arr.sort()`는 배열의 요소를 순서대로 정렬해요. 꼭 알아야 할 성질이 두 가지예요.

1. **원래 배열을 직접 바꿔요.** 앞 단원에서 배운 "원본을 바꾸는 메서드" 쪽이에요. 돌려주는 값도 새 배열이 아니라 **바로 그 배열**이에요.
1. **비교 함수 없이 부르면 요소를 문자열로 바꿔 사전순으로** 정렬해요.

두 번째 성질 때문에 숫자 정렬에서 이상한 일이 생겨요. 사전에서 단어를 찾을 때처럼 첫 글자부터 비교하므로 `"100"`은 `"9"`보다 앞이에요. 첫 글자 `1`이 `9`보다 앞이니까요.

| 숫자 | 문자열로 보면 | 사전순 위치 |
|---|---|---|
| 1 | `"1"` | 1번째 |
| 10 | `"10"` | 2번째 (`"1"` 다음에 글자가 더 있음) |
| 100 | `"100"` | 3번째 |
| 9 | `"9"` | 4번째 (첫 글자 `9`가 가장 뒤) |

그래서 `[10, 9, 1, 100].sort()`는 `[1, 10, 100, 9]`예요. 영어 단어도 대문자가 소문자보다 앞에 와요(`"Cherry"`가 `"apple"`보다 앞).

### 비교 함수로 원하는 순서 정하기

숫자를 크기 순으로 정렬하려면 `sort`에 **비교 함수**를 콜백으로 넘겨요. `sort`는 정렬하는 동안 요소 두 개 `a`, `b`를 골라 비교 함수에 넣고, 돌려받은 **숫자의 부호**로 순서를 정해요.

| 비교 함수가 돌려준 값 | 뜻 |
|---|---|
| 음수 | `a`를 `b`보다 앞에 |
| 양수 | `b`를 `a`보다 앞에 |
| 0 | 순서를 바꾸지 않음 |

`(a, b) => a - b`를 생각해 볼게요. `a`가 작으면 `a - b`가 음수라서 `a`가 앞으로 가요. 그래서 **작은 수부터**(오름차순)예요. 반대로 `(a, b) => b - a`는 **큰 수부터**(내림차순)예요.

두 가지 방법으로 기억할 수 있어요.

1. **부호로 보기**: "음수면 `a`가 먼저". `a - b`는 `a`가 작을 때 음수예요.
1. **모양으로 보기**: 매개변수 순서 그대로 `a - b`면 오름차순, 뒤집어 `b - a`면 내림차순이에요.

비교 함수는 `true`·`false`가 아니라 **음수·0·양수**를 돌려줘야 해요. `(a, b) => a > b`처럼 쓰면 음수가 나오지 않아서, 정렬 결과를 믿을 수 없어요.

### 새 배열 만들기: slice와 concat

| 메서드 | 하는 일 | 원본 |
|---|---|---|
| `slice(시작, 끝)` | 시작부터 끝 인덱스 **바로 앞까지**를 복사한 새 배열 | 그대로 |
| `slice()` | 인수 없이 부르면 배열 전체를 복사한 새 배열 | 그대로 |
| `concat(다른 배열)` | 두 배열의 요소를 이은 새 배열 | 그대로 |

- `slice`의 규칙은 문자열의 `slice`와 같아요. 끝 인덱스는 들어가지 않고, 끝을 생략하면 마지막까지, 음수는 뒤에서부터 센 위치예요. `[1, 2, 3, 4, 5].slice(-2)`는 `[4, 5]`예요.
- 이름이 비슷한 `splice`는 원본에서 요소를 **지우는** 메서드였어요. `slice`는 복사만 해요.
- `concat`은 넘긴 배열의 요소를 **풀어서** 이어요. `[1, 2].concat([3, 4])`는 `[1, 2, 3, 4]`예요. 반면 `push([3, 4])`는 배열 자체를 요소 하나로 넣어요.

`sort`는 원본을 바꾸므로, 원래 순서를 지켜야 할 때는 `slice()`로 먼저 복사하고 복사본을 정렬해요.

```js
const sortedCopy = scores.slice().sort((a, b) => b - a);
```
</Section>

<Section kind="pitfalls">
<Pitfall misconception="js.mc.array-includes-partial">
<Wrong>`["apple", "banana"].includes("app")`는 `true`다. `"apple"`에 `app`이 들어 있으니까.</Wrong>
<Actual>첫 번째 예제에서 `fruits.includes("ban")`은 `false`였어요. 배열의 `includes`는 요소 하나와 통째로 비교해요.</Actual>
<Right>글자의 일부를 찾는 것은 문자열의 `includes`예요. 요소 안의 글자를 찾고 싶다면 `fruits.some((f) => f.includes("app"))`처럼 요소마다 문자열 `includes`를 불러요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.includes-loose-match">
<Wrong>`[1, 2, 3].includes("2")`는 `true`다. 둘 다 2니까.</Wrong>
<Actual>첫 번째 예제에서 `seats.includes("2")`는 `false`였어요. `indexOf("2")`도 `-1`이에요. 자료형까지 같아야 같은 요소로 봐요.</Actual>
<Right>입력이 문자열로 들어오면(예: `split`의 결과) `Number()`로 바꾼 뒤 찾아요. `seats.includes(Number("2"))`는 `true`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.sort-numeric-default">
<Wrong>`[10, 9, 1, 100].sort()`는 `[1, 9, 10, 100]`이다.</Wrong>
<Actual>결과는 `[1, 10, 100, 9]`예요. 두 번째 예제처럼 비교 함수가 없으면 숫자를 문자열로 바꿔 사전순으로 놓아요.</Actual>
<Right>숫자는 항상 비교 함수를 넘겨요. 작은 수부터는 `sort((a, b) => a - b)`, 큰 수부터는 `sort((a, b) => b - a)`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.sort-returns-new-array">
<Wrong>`const sorted = arr.sort();`라고 쓰면 정렬된 새 배열이 `sorted`에 담기고, `arr`은 원래 순서 그대로다.</Wrong>
<Actual>네 번째 예제에서 `original`도 정렬되었고, `sorted === original`은 `true`였어요. `sort`는 원래 배열을 바꾸고 그 배열을 돌려줘요.</Actual>
<Right>원래 순서를 지켜야 하면 `arr.slice().sort(...)`처럼 복사본을 정렬해요. 특히 함수가 받은 배열을 그대로 `sort`하면 함수를 부른 쪽의 배열까지 바뀌어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.sort-compare-boolean">
<Wrong>비교 함수는 `(a, b) => a > b`처럼 "앞이 더 크면 참"을 돌려주면 된다.</Wrong>
<Actual>

`true`·`false`는 숫자로 `1`·`0`이 되어 음수가 나오지 않아요. 두 수를 직접 넣어 보면 차이가 보여요.

```js
const wrong = (a, b) => a > b;
const right = (a, b) => a - b;
console.log(wrong(1, 5)); // false → 0: "순서를 바꾸지 않음"
console.log(right(1, 5)); // -4: "1을 5보다 앞에"
```

`1`이 `5`보다 작은데도 `wrong`은 "앞에 놓아라"(음수)라고 말할 방법이 없어요. 그래서 이런 비교 함수로 정렬한 결과는 브라우저와 배열에 따라 그대로이거나, 일부만 정렬되거나, 우연히 제대로 정렬되기도 해서 믿을 수 없어요.
</Actual>
<Right>비교 함수는 음수·0·양수를 돌려줘야 해요. 숫자는 `a - b`(오름차순)나 `b - a`(내림차순)로 빼기를 돌려줘요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.array-slice-mutates">
<Wrong>`week.slice(0, 5)`를 실행하면 앞의 다섯 요소가 `week`에서 빠진다.</Wrong>
<Actual>다섯 번째 예제에서 두 번 잘라 낸 뒤에도 `week.length`는 7이었어요. `slice`는 복사만 해요.</Actual>
<Right>원본에서 지우는 것은 `splice`예요. `slice`의 결과는 변수에 담아 써야 하고, 담지 않으면 버려져요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.concat-adds-nested">
<Wrong>`["국어", "수학"].concat(["체육", "음악"])`은 배열이 요소 하나로 들어간 3개짜리 배열이다.</Wrong>
<Actual>다섯 번째 예제에서 `concat`의 결과는 요소 4개 `["국어", "수학", "체육", "음악"]`이었어요. 배열 자체가 요소 하나로 들어간 것은 `push`를 쓴 쪽(길이 3)이에요.</Actual>
<Right>두 배열의 요소를 이어 새 배열을 만들 때는 `concat`, 기존 배열 끝에 값 하나를 넣을 때는 `push`를 써요. `concat`은 원본을 바꾸지 않으니 결과를 변수에 담아요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
처음의 점수판을 이 단원의 메서드로 만들어 볼게요. 들어온 순서의 기록은 그대로 두고, 새 점수가 처음 나온 점수인지 확인한 뒤, 높은 점수 3개를 보여 줘요.

```js
const records = [70, 100, 85, 9, 92];
const newScore = 85;

if (records.includes(newScore)) {
  console.log(`${newScore}점은 이미 기록에 있어요`);
}

const top3 = records.slice().sort((a, b) => b - a).slice(0, 3);
console.log("TOP 3:", top3.join(", "));
console.log("전체 기록:", records.join(", "));
// 85점은 이미 기록에 있어요
// TOP 3: 100, 92, 85
// 전체 기록: 70, 100, 85, 9, 92
```

- `records.slice()`로 복사한 뒤 정렬해서 `records`는 들어온 순서 그대로예요.
- 쇼핑몰의 "낮은 가격순" 정렬, 검색어 목록에 이미 있는 단어인지 확인하기, 게시판에서 한 페이지 분량만 잘라 보여 주기(`slice((쪽 - 1) * 개수, 쪽 * 개수)`)도 모두 이 단원의 메서드로 만들어요.
</Section>

<Section kind="summary">
- 배열의 `includes`는 같은 요소가 있는지를 `true`·`false`로, `indexOf`는 처음 나오는 인덱스를 돌려주고 없으면 `-1`이에요.
- 배열에서 찾을 때는 요소 **전체**가 자료형까지 같아야 해요. 글자 일부를 찾는 문자열 `includes`와 달라요.
- `sort()`는 비교 함수가 없으면 요소를 문자열로 바꿔 사전순으로 정렬해요. 숫자는 `(a, b) => a - b`(오름차순)나 `(a, b) => b - a`(내림차순)를 넘겨요.
- 비교 함수는 음수·0·양수를 돌려줘야 해요. `true`·`false`를 돌려주면 정렬 결과를 믿을 수 없어요.
- `sort`는 원래 배열을 바꾸고 같은 배열을 돌려줘요. 원본을 지키려면 `slice()`로 복사한 뒤 정렬해요.
- `slice`는 일부를, `concat`은 두 배열을 이은 결과를 새 배열로 돌려주고 원본은 바꾸지 않아요.
</Section>
