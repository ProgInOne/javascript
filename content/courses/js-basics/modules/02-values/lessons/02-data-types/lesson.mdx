<Section kind="objectives">
- `"5"`와 `5`처럼 겉모습이 비슷한 값의 자료형을 구별하고, 자료형에 따라 결과가 달라지는 코드를 예측할 수 있어요.
- 숫자·문자열·불리언 값을 규칙에 맞게 쓰고, 값을 잘못 써서 생긴 오류를 고칠 수 있어요.
- `typeof`로 값의 자료형을 확인하고, `typeof null`을 포함한 결과를 예측할 수 있어요.
</Section>

<Section kind="prerequisites" />

<Section kind="intro">
쇼핑몰 장바구니에 상품이 2개 담겨 있고, 하나를 더 담는 프로그램을 만들었어요.

```js
let count = "2";
count = count + 1;
console.log(count);
```

콘솔에는 `3`이 나와야 할 것 같지만, 실제로는 **`21`이** 나와요. 무엇이 잘못됐을까요?

범인은 첫 줄의 따옴표예요. `"2"`는 숫자 2가 아니라 **글자** `2`예요. 글자에 `+ 1`을 하면 더하기 대신 글자를 이어 붙여서 `"2"`와 `1`이 나란히 붙은 `21`이 돼요.

이처럼 값에는 **종류**가 있고, 종류에 따라 같은 코드도 다르게 동작해요. 이 값의 종류를 **자료형**(data type)이라고 해요. 자료형을 구별하지 못하면 오류 메시지도 없이 엉뚱한 결과가 나오는 버그를 만나게 돼요. 이 단원에서는 가장 기본이 되는 자료형과, 값의 자료형을 확인하는 `typeof`를 배워요.
</Section>

<Section kind="principle">
### 값에는 종류(자료형)가 있어요

JavaScript의 기본 값은 아래 일곱 가지 자료형 중 하나예요. 더 쪼갤 수 없는 기본 값이라서 **원시 자료형**(primitive type)이라고 불러요.

| 자료형 | 무엇인가요 | 값의 예 | 어디서 배우나요 |
|---|---|---|---|
| number | 숫자 | `42`, `-7`, `3.14` | 이 단원 |
| string | 문자열(글자) | `"안녕"`, `'5'`, `""` | 이 단원 |
| boolean | 참/거짓 | `true`, `false` | 이 단원 |
| undefined | 아직 값이 정해지지 않음 | `undefined` | 다음 단원 "비어 있는 값" |
| null | 일부러 비워 둔 값 | `null` | 다음 단원 "비어 있는 값" |
| bigint | 아주 큰 정수 | `12n` | 거의 쓰지 않아요 |
| symbol | 고유한 표식 | `Symbol()` | 거의 쓰지 않아요 |

이 단원에서는 가장 많이 쓰는 number, string, boolean을 자세히 다뤄요. bigint와 symbol은 이런 것이 있다는 것만 알아 두면 충분해요.

원시 자료형 말고도 여러 값을 하나로 묶는 **객체**(object)라는 자료형이 있어요. 객체는 모듈 8 "배열"과 모듈 9 "객체"에서 배워요.

### 두 가지 관점으로 보기

**값 관점: 자료형은 값에 붙어 있어요.** 모든 값에는 "나는 숫자예요", "나는 문자열이에요" 같은 꼬리표가 붙어 있다고 생각해 보세요. 변수는 값을 담는 이름표일 뿐이라 꼬리표가 없어요. 그래서 숫자를 담았던 변수에 문자열을 다시 대입해도 괜찮고, 그러면 변수 안 값의 자료형이 바뀌어요.

| 실행한 줄 | `box`의 값 | 그 값의 자료형 |
|---|---|---|
| `let box = 10;` | 10 | number |
| `box = "열";` | 열 | string |
| `box = true;` | true | boolean |

**동작 관점: 자료형이 다르면 같은 연산도 다르게 동작해요.** 같은 `+`라도 두 값이 모두 숫자면 더하고, 한쪽이 문자열이면 글자를 이어 붙여요.

| 코드 | 결과 | 이유 |
|---|---|---|
| `5 + 1` | `6` | 숫자 + 숫자 → 덧셈 |
| `"5" + 1` | `"51"` | 문자열이 끼면 → 이어 붙이기 |

`+`가 언제 더하고 언제 이어 붙이는지, `"5" * 2`처럼 다른 연산은 어떻게 되는지는 모듈 3 "연산자와 형 변환"에서 자세히 배워요. 지금은 **"자료형이 다르면 결과가 달라진다"는** 것만 기억해요.

### number: 숫자

정수, 소수, 음수가 모두 같은 **number** 자료형이에요. 정수 전용 자료형이 따로 있지 않아요.

```js
let age = 20;          // number
let height = 172.5;    // number
let temperature = -3;  // number
```

숫자를 쓸 때 지킬 규칙은 두 가지예요.

- **따옴표를 붙이지 않아요.** `"20"`이라고 쓰면 숫자가 아니라 문자열이 돼요.
- **쉼표로 자릿수를 나누지 않아요.** 코드에서 쉼표는 "값과 값을 나누는" 기호예요. `console.log(1,500)`은 `1`과 `500` 두 값을 출력해서 `1 500`이 나오고, `let price = 1,500;`은 `SyntaxError`예요. 숫자는 `1500`처럼 붙여 써요.

<Reveal title="큰 숫자를 읽기 쉽게 쓰고 싶다면">
쉼표 대신 밑줄(`_`)을 쓸 수 있어요. `1_000_000`은 `1000000`과 똑같은 숫자예요. 밑줄은 사람이 읽기 쉽게 하는 표시일 뿐이라 출력하면 `1000000`이 나와요.
</Reveal>

### string: 문자열

따옴표로 감싼 글자를 **문자열**(string)이라고 해요. 따옴표는 세 종류가 있어요.

```js
let a = "사과";   // 큰따옴표
let b = '사과';   // 작은따옴표
let c = `사과`;   // 백틱(키보드 숫자 1 왼쪽의 키)
```

세 줄이 만드는 문자열은 **모두 똑같아요.** 따옴표는 "여기서부터 여기까지가 글자예요"라고 표시할 뿐이고, 값의 일부가 아니에요. 백틱은 글자 안에 값을 끼워 넣는 특별한 기능이 있는데, 모듈 7 "문자열"에서 배워요.

규칙은 하나예요. **연 따옴표와 같은 종류의 따옴표를 만나면 문자열이 끝나요.**

- `"안녕'`처럼 종류를 섞으면 끝을 찾지 못해 `SyntaxError`가 나요.
- 큰따옴표 문자열 안에 큰따옴표를 넣으면 거기서 문자열이 끝나 버려요. 글자 안에 큰따옴표가 필요하면 바깥을 작은따옴표로 감싸요: `'그가 "안녕"이라고 했어요'`. 반대로 작은따옴표가 필요하면 바깥을 큰따옴표로 감싸요: `"It's OK"`.

따옴표 사이에 아무것도 없는 `""`도 문자열이에요. 글자가 하나도 없는 **빈 문자열**이에요.

### boolean: 참과 거짓

**불리언**(boolean)은 `true`(참)와 `false`(거짓) 딱 두 값만 있는 자료형이에요. "로그인했나요?", "문이 열려 있나요?"처럼 예/아니요로 답하는 상태를 담아요.

```js
let isLoggedIn = false;
let isOpen = true;
```

- **소문자**로 써요. `True`, `TRUE`는 불리언이 아니라 그냥 이름으로 읽혀서 `ReferenceError: True is not defined`가 나요.
- **따옴표를 붙이지 않아요.** `"true"`는 네 글자로 된 문자열이에요.
- 불리언 변수 이름은 `isOpen`, `hasCoupon`처럼 `is`, `has`로 시작하면 무엇을 담는지 알기 쉬워요.

불리언은 모듈 4 "조건문"에서 "참이면 이것, 거짓이면 저것"을 실행할 때 본격적으로 쓰여요.

### typeof: 자료형 확인하기

값의 자료형이 궁금하면 `typeof`를 앞에 붙여요. 결과로 자료형의 이름을 알려 줘요.

| 코드 | 결과 |
|---|---|
| `typeof 42` | `"number"` |
| `typeof 3.14` | `"number"` |
| `typeof "42"` | `"string"` |
| `typeof true` | `"boolean"` |
| `typeof "true"` | `"string"` |
| `typeof undefined` | `"undefined"` |
| `typeof null` | `"object"` (주의!) |

세 가지를 기억해요.

1. **`typeof`는 내용이 아니라 자료형을 봐요.** `"42"`는 안의 글자가 숫자처럼 생겼어도 따옴표로 감쌌으니 문자열이에요.
1. **결과는 문자열이에요.** `typeof 42`의 결과는 `"number"`라는 문자열이라서, `typeof typeof 42`는 `"string"`이에요.
1. **`typeof null`은 `"object"`예요.** JavaScript를 처음 만들 때의 설계 실수인데, 이미 많은 웹사이트가 이 동작에 기대고 있어서 고치지 못하고 남았어요. `null`이 객체라는 뜻은 아니에요.

<Callout kind="note" title="콘솔은 문자열의 따옴표를 보여 주지 않아요">
`console.log("5")`와 `console.log(5)`는 둘 다 콘솔에 `5`라고 보여요. 콘솔은 문자열을 출력할 때 따옴표를 빼고 글자만 보여 주기 때문이에요. `typeof`의 결과도 문자열이라 `number`처럼 따옴표 없이 보여요. 그래서 **출력 모양만 보고 자료형을 판단하면 안 돼요.** 자료형이 궁금하면 `typeof`로 확인해요. (Chrome 개발자 도구는 숫자와 문자열을 다른 색으로 보여 줘서 조금 구별할 수 있어요.)
</Callout>
</Section>

<Section kind="pitfalls">
<Pitfall misconception="js.mc.quoted-number-is-number">
<Wrong>`"5"`와 `5`는 같은 값이다. 따옴표는 꾸밈일 뿐이다.</Wrong>
<Actual>`"5"`는 문자열, `5`는 숫자예요. `"5" + 1`은 `51`, `5 + 1`은 `6`처럼 결과가 달라요.</Actual>
<Right>계산할 값은 따옴표 없이 숫자로 써요. 따옴표가 있으면 안의 내용이 무엇이든 문자열이에요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.same-output-same-type">
<Wrong>`console.log`로 출력했을 때 둘 다 `5`로 보이니 같은 자료형이다.</Wrong>
<Actual>콘솔은 문자열의 따옴표를 빼고 보여 줘서, 숫자 `5`와 문자열 `"5"`가 똑같이 `5`로 보여요.</Actual>
<Right>출력 모양으로 자료형을 판단하지 말고 `typeof`로 확인해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.type-belongs-to-variable">
<Wrong>`let age = 10;`으로 만든 변수에는 앞으로 숫자만 넣을 수 있다.</Wrong>
<Actual>`age = "열 살";`처럼 문자열을 대입해도 오류가 나지 않아요. 그 뒤로 `typeof age`는 `"string"`이에요.</Actual>
<Right>자료형은 변수가 아니라 값에 붙어 있어요. 변수는 지금 들어 있는 값의 자료형을 따라가요. 그래도 헷갈리지 않게 한 변수에는 한 가지 자료형만 담는 것이 좋아요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.decimal-separate-type">
<Wrong>`3`은 정수 자료형, `3.5`는 소수 자료형이다.</Wrong>
<Actual>`typeof 3`과 `typeof 3.5`는 둘 다 `"number"`예요.</Actual>
<Right>JavaScript에는 정수 전용 자료형이 없어요. 정수, 소수, 음수 모두 number 하나예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.number-with-comma">
<Wrong>`1,500`처럼 쉼표로 자릿수를 나눠서 숫자를 쓴다.</Wrong>
<Actual>`console.log(1,500)`은 `1 500`을 출력하고, `let price = 1,500;`은 `SyntaxError: Unexpected number`가 나요.</Actual>
<Right>코드에서 쉼표는 값을 나누는 기호예요. 숫자는 `1500`처럼 붙여 쓰고, 꼭 나누고 싶으면 `1_500`처럼 밑줄을 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.quote-kinds-differ">
<Wrong>`'사과'`와 `"사과"`는 따옴표가 다르니 다른 값이다.</Wrong>
<Actual>두 문자열은 완전히 같아요. `typeof`도 둘 다 `"string"`이에요.</Actual>
<Right>따옴표는 문자열의 시작과 끝을 표시할 뿐 값의 일부가 아니에요. 큰따옴표와 작은따옴표 중 편한 것을 쓰되, 한 프로그램 안에서는 하나로 통일해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.quotes-mismatch">
<Wrong>`"안녕'`처럼 큰따옴표로 열고 작은따옴표로 닫아도 되고, 큰따옴표 문자열 안에 큰따옴표를 그대로 넣어도 된다.</Wrong>
<Actual>둘 다 `SyntaxError`예요. 따옴표 종류를 섞으면 문자열의 끝을 찾지 못하고(`Invalid or unexpected token`), 안에 같은 따옴표를 넣으면 거기서 문자열이 끝나 버려요.</Actual>
<Right>연 따옴표와 같은 따옴표로 닫아요. 글자 안에 큰따옴표가 필요하면 바깥을 작은따옴표로, 작은따옴표가 필요하면 바깥을 큰따옴표로 감싸요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.quoted-boolean">
<Wrong>`"true"`와 `true`는 같은 값이다.</Wrong>
<Actual>`"true"`는 네 글자로 된 문자열이에요. `typeof "true"`는 `"string"`, `typeof true`는 `"boolean"`이에요.</Actual>
<Right>참/거짓을 담을 때는 따옴표 없이 `true`, `false`라고 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.boolean-capitalized">
<Wrong>`True`, `TRUE`, `False`처럼 대문자로 써도 불리언이다.</Wrong>
<Actual>`let isOn = True;`는 `ReferenceError: True is not defined`가 나요. `True`를 변수 이름으로 읽었는데 그런 변수가 없기 때문이에요.</Actual>
<Right>불리언은 소문자 `true`, `false`뿐이에요. 다른 프로그래밍 언어(예: Python)에서는 `True`라고 쓰니 헷갈리지 않게 조심해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.typeof-reads-content">
<Wrong>`typeof "42"`는 안의 글자가 숫자니까 `"number"`다.</Wrong>
<Actual>`typeof "42"`는 `"string"`이에요.</Actual>
<Right>`typeof`는 내용이 아니라 자료형을 봐요. 따옴표로 감싼 값은 무엇이 들어 있든 문자열이에요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.typeof-null-is-null">
<Wrong>`typeof null`의 결과는 `"null"`이다.</Wrong>
<Actual>`typeof null`은 `"object"`예요.</Actual>
<Right>JavaScript 초기의 설계 실수가 그대로 남은 거예요. 외워 두고, `null`이 객체라고 오해하지 않아요. `null`은 다음 단원에서 자세히 배워요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.typeof-result-not-string">
<Wrong>`typeof 42`의 결과는 따옴표 없는 `number`라는 특별한 표시라서, `typeof typeof 42`도 `"number"`다.</Wrong>
<Actual>`typeof 42`의 결과는 문자열 `"number"`예요. 그래서 `typeof typeof 42`는 `"string"`이에요.</Actual>
<Right>`typeof`는 언제나 자료형 이름을 **문자열**로 돌려줘요. 콘솔이 따옴표 없이 보여 줄 뿐이에요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
웹 서비스의 데이터는 자료형이 섞여 있어요. 예를 들어 쇼핑몰의 상품 하나는 이런 값들로 이루어져요.

```js
const productName = "무선 마우스";   // 상품 이름: string
const price = 25000;                // 가격: number (계산해야 하니까 숫자로)
const isSoldOut = false;            // 품절 여부: boolean

console.log(productName, price, isSoldOut);
console.log(typeof price);
```

- 가격처럼 **계산할 값**은 number로 담아요. `"25000"`으로 담으면 수량을 곱하거나 배송비를 더할 때 엉뚱한 결과가 나와요.
- 품절 여부처럼 **예/아니요로 답하는 값**은 `"yes"`, `"no"` 같은 문자열 대신 불리언으로 담아요.
- 사용자가 입력창에 적은 값은 숫자처럼 보여도 **문자열**로 들어와요(모듈 10 "브라우저 JS 입문"에서 직접 만나요). 실무에서 생기는 `"2" + 1 → "21"` 같은 버그는 대부분 여기서 시작돼요. 문자열을 숫자로 바꾸는 방법은 모듈 3 "명시적 형 변환"에서 배워요.

계산 결과가 이상하면 가장 먼저 `console.log(typeof 값)`으로 자료형을 확인해 보세요. 실무 개발자들도 매일 쓰는 디버깅 방법이에요.
</Section>

<Section kind="summary">
- 모든 값에는 자료형이 있어요. 가장 많이 쓰는 것은 number(숫자), string(문자열), boolean(참/거짓)이에요.
- 자료형이 다르면 같은 연산도 다르게 동작해요. `5 + 1`은 `6`, `"5" + 1`은 `"51"`이에요.
- 자료형은 변수가 아니라 값에 붙어 있어요. 변수에 다른 자료형의 값을 대입하면 `typeof` 결과도 바뀌어요.
- 숫자는 따옴표와 쉼표 없이 써요. 정수와 소수는 모두 number예요.
- 문자열은 같은 종류의 따옴표로 열고 닫아요. 안에 큰따옴표가 필요하면 바깥을 작은따옴표로 감싸요.
- 불리언은 소문자 `true`, `false`뿐이고 따옴표를 붙이지 않아요.
- `typeof`는 자료형 이름을 문자열로 알려 줘요. 콘솔 출력 모양으로 자료형을 판단하지 말고 `typeof`로 확인해요. `typeof null`은 `"object"`예요.
</Section>
