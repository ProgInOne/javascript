<Section kind="objectives">
- `let`으로 변수를 만들고, 변수 이름으로 저장한 값을 꺼내 쓸 수 있어요.
- 대입(`=`)이 오른쪽 값을 계산해 왼쪽 변수에 넣는 과정을 한 줄씩 추적해 결과를 예측할 수 있어요.
- 바뀌지 않는 값은 `const`, 바뀌는 값은 `let`으로 골라 쓰고, `const` 재할당 오류를 고칠 수 있어요.
- 이름 규칙에 맞는 변수 이름을 짓고, 이름 때문에 생긴 오류를 고칠 수 있어요.
</Section>

<Section kind="intro">
게임 점수를 계산하는 프로그램을 만든다고 해 봐요. 지금까지 배운 방법으로는 이렇게 써야 해요.

```js
console.log("현재 점수:", 0);
console.log("코인을 먹은 뒤:", 0 + 10);
console.log("한 번 더 먹은 뒤:", 0 + 10 + 10);
```

문제가 보이나요? 프로그램은 지금 점수가 얼마인지 **기억하지 못해요.** 그래서 매번 처음부터 계산식을 다시 써야 하고, 시작 점수가 바뀌면 모든 줄을 고쳐야 해요. 지난 단원에서 봤듯이 `console.log`는 보여 주기만 할 뿐 값을 저장하지 않으니까요.

**변수**는 값에 이름을 붙여 저장해 두는 방법이에요. `score`라는 이름에 점수를 넣어 두면, 언제든 그 이름으로 지금 점수를 꺼내 쓰고 새 점수로 바꿀 수 있어요. 거의 모든 프로그램이 변수로 시작해요.
</Section>

<Section kind="principle">
### let: 이름 붙은 상자 만들기

```js
let score = 0;
```

이 한 줄은 세 가지 일을 해요.

1. `let`: "새 변수를 만들어요"라는 선언이에요.
1. `score`: 변수의 이름이에요.
1. `= 0`: 처음 넣을 값이에요.

만든 다음에는 이름만 쓰면 그 값을 꺼내요. `console.log(score)`는 `0`을 출력해요. 이때 이름에 따옴표를 붙이면 안 돼요. `console.log("score")`는 변수와 상관없는 글자 `score`를 출력해요. **따옴표가 있으면 글자, 없으면 이름**이에요.

`let answer;`처럼 값 없이 만들 수도 있어요. 그러면 변수에는 "아직 값이 없음"을 뜻하는 `undefined`가 들어 있어요(`undefined`는 "비어 있는 값" 단원에서 자세히 배워요).

반대로 `let`을 빼고 `score = 0;`처럼 대입부터 쓰면 `ReferenceError: score is not defined`가 나요. 만든 적 없는 변수에는 값을 넣을 수 없다는 뜻이에요. 아주 오래된 방식의 JavaScript는 이때 몰래 변수를 만들어 주기도 하지만, ProgInOne은 요즘 JavaScript 규칙(엄격 모드)으로 실행하기 때문에 오류로 알려 줘요. 변수는 꼭 `let`(또는 뒤에서 배울 `const`)으로 먼저 만들어요.

### 대입: 오른쪽을 계산해서 왼쪽에 넣기

변수에 새 값을 넣는 것을 **대입**이라고 해요. 대입에는 `let`을 다시 쓰지 않아요. `let`은 처음 만들 때 **한 번만** 써요.

```js
let score = 0;
score = 10;          // score에 10을 넣어요 (원래 있던 0은 사라져요)
score = score + 5;   // 지금 score(10)에 5를 더한 15를 score에 넣어요
```

`=`는 수학의 "같다"가 아니에요. 컴퓨터는 대입을 항상 이 순서로 처리해요.

1. **오른쪽**을 먼저 계산해요. 이때 변수 이름은 그 순간의 값으로 바뀌어요. (`score + 5` → `10 + 5` → `15`)
1. 계산한 값을 **왼쪽** 변수에 넣어요. 원래 값은 덮어써져요.

그래서 `score = score + 5`는 수학으로는 말이 안 되지만, 프로그래밍에서는 "점수에 5를 더해라"라는 아주 흔한 문장이에요. `=`를 "같다" 대신 **"넣는다"**, 또는 화살표 `score ← score + 5`로 읽으면 헷갈리지 않아요. 왼쪽에는 값을 받을 변수가 와야 하므로 `15 = score`처럼 거꾸로 쓸 수는 없어요.

### 두 가지 관점으로 보기

**상자 관점**: 변수는 이름표가 붙은 상자예요. 상자에는 값이 하나만 들어가고, 새 값을 넣으면 이전 값은 버려져요.

**표 관점**: 프로그램은 "이름 → 지금 값" 표를 들고 있어요. 문장을 하나 실행할 때마다 표가 바뀌어요. 결과를 예측할 때는 이 표를 직접 그려 가며 한 줄씩 따라가면 정확해요.

| 실행한 줄 | `score`의 값 |
|---|---|
| `let score = 0;` | 0 |
| `score = 10;` | 10 |
| `score = score + 5;` | 15 |

### 대입은 "그 순간의 값"을 복사해요

```js
let price = 1000;
let count = 2;
let total = price * count;   // 이 순간 계산한 2000이 total에 들어가요
count = 5;                   // count만 바뀌어요. total은 여전히 2000
```

`total`에는 식(`price * count`)이 아니라 **계산 결과 2000**이 들어가요. 스프레드시트처럼 `count`가 바뀔 때 다시 계산되지 않아요. `let b = a;`도 마찬가지로 그 순간 `a`의 값을 `b`에 복사할 뿐, 두 변수를 연결하지 않아요.

### const: 다시 대입할 수 없는 상수

```js
const birthYear = 2000;
```

`const`로 만든 이름에는 **다른 값을 다시 대입할 수 없어요.** 시도하면 `TypeError: Assignment to constant variable.`이 나고 프로그램이 멈춰요. 그리고 다시 대입할 수 없으니, 만드는 그 자리에서 **반드시 값을 넣어야** 해요. `const birthYear;`라고만 쓰면 실행 전에 `SyntaxError`가 나요. Chrome에서는 `Missing initializer in const declaration`(const 선언에 초기값이 없어요)이라고 알려 줘요.

<CompareTable columns={["let", "const"]}>
<Row label="다시 대입">할 수 있어요 | 할 수 없어요 (TypeError)</Row>
<Row label="값 없이 만들기">할 수 있어요 (undefined) | 할 수 없어요 (SyntaxError)</Row>
<Row label="이럴 때 써요">점수, 개수, 현재 상태처럼 바뀌는 값 | 생년, 세금 비율, 최대 레벨처럼 바뀌지 않는 값</Row>
</CompareTable>

어느 쪽을 쓸지 모르겠다면 **먼저 `const`로 쓰고, 다시 대입해야 할 때만 `let`으로 바꿔요.** 바뀌면 안 되는 값을 실수로 바꾸는 버그를 JavaScript가 대신 잡아 줘요.

### 이름 짓기 규칙

| 규칙 | 되는 예 | 안 되는 예 |
|---|---|---|
| 글자, 숫자, `_`, `$`만 써요 | `user_name`, `$price` | `total-price` (하이픈은 빼기로 읽혀요), `my name` (공백) |
| 숫자로 시작할 수 없어요 | `player1` | `1player` |
| 예약어는 쓸 수 없어요 | `className` | `let`, `const`, `class`, `if`, `return` |
| 대문자와 소문자는 다른 글자예요 | `score`와 `Score`는 다른 이름 | |

규칙은 아니지만 꼭 지키는 관례도 있어요.

- 여러 단어는 두 번째 단어부터 첫 글자를 대문자로 이어 써요: `totalPrice`, `itemCount`, `isLoggedIn` (낙타 등 같다고 해서 camelCase라고 불러요).
- `a`, `x`보다 `score`, `userName`처럼 **무엇이 들어 있는지 알 수 있는 이름**을 써요.
- 한글 이름도 문법상 쓸 수 있지만, 실무에서는 영어 이름을 써요.
</Section>

- 1번 줄: `greeting`이라는 변수를 만들고 글자 `반가워요`를 넣어요. 이 줄은 아무것도 출력하지 않아요.
- 2번 줄: 따옴표 없는 `greeting`은 **이름**이에요. 변수에 들어 있는 `반가워요`가 출력돼요.
- 3번 줄: 따옴표로 감싼 `"greeting"`은 **글자**예요. 변수와 상관없이 글자 그대로 `greeting`이 출력돼요.

<Section kind="examples">
두 번째 예제는 같은 변수에 여러 번 대입해요. 마지막에 출력되는 값을 예측해 보세요. 머릿속으로 "이름 → 값" 표를 그려 가며 따라가면 쉬워요.

<RunnableExample id="reassign-trace" lang="js" predict predictKind="console" concepts={["js.values.assignment"]}>
```js
let coins = 3;
coins = coins + 2;
coins = coins * 2;
console.log(coins);
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
출력은 `10`이에요. 대입마다 **오른쪽을 먼저 계산하고**, 그 결과를 왼쪽에 넣어요.

| 실행한 줄 | 오른쪽 계산 | 대입 후 `coins` |
|---|---|---|
| `let coins = 3;` | 3 | 3 |
| `coins = coins + 2;` | 3 + 2 = 5 | 5 |
| `coins = coins * 2;` | 5 × 2 = 10 | 10 |
| `console.log(coins);` | | 10 출력 |

`coins = coins * 2`를 계산할 때 쓰는 `coins`는 처음 값 3이 아니라 **바로 앞 줄까지 반영된 지금 값** 5예요.
</Section>

<Section kind="examples">
세 번째 예제예요. `b`에 `a`를 대입한 뒤 `a`를 바꾸면 `b`는 어떻게 될까요?

<RunnableExample id="copy-not-link" lang="js" predict predictKind="console" concepts={["js.values.assignment"]}>
```js
let a = 10;
let b = a;
a = 99;
console.log(a, b);
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
출력은 `99 10`이에요.

| 실행한 줄 | `a` | `b` |
|---|---|---|
| `let a = 10;` | 10 | (아직 없음) |
| `let b = a;` | 10 | 10 |
| `a = 99;` | 99 | 10 |

`let b = a;`는 "b는 앞으로 a와 같다"가 아니라 "**지금** a의 값(10)을 b에 넣어라"예요. 그 뒤에 `a`를 바꿔도 `b`의 상자에는 10이 그대로 있어요.
</Section>

<Section kind="examples">
네 번째 예제는 `const`에 다시 대입해요. 마지막 줄은 실행될까요?

<RunnableExample id="const-reassign" lang="js" expectError concepts={["js.values.const"]}>
```js
const maxLevel = 10;
console.log("최대 레벨:", maxLevel);
maxLevel = 11;
console.log("여기까지 올까요?");
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
```text
최대 레벨: 10
TypeError: Assignment to constant variable. (3번째 줄)
```

1~2번 줄은 정상 실행돼요. 3번 줄에서 `const`로 만든 `maxLevel`에 다시 대입하려 하자 `TypeError`가 나고, 지난 단원에서 배운 대로 프로그램이 거기서 멈춰서 4번 줄은 실행되지 않아요. 레벨을 올려야 하는 프로그램이라면 `maxLevel`을 `let`으로 만들었어야 해요.
</Section>

<Section kind="examples">

<RunnableExample id="name-case" lang="js" expectError concepts={["js.values.identifiers"]}>
```js

```
</RunnableExample>

```text

```

오류는 3번 줄을 가리키지만, 3번 줄만 봐서는 무엇이 틀렸는지 잘 안 보여요. 1번 줄에서 만든 이름은 `itemPrice`(대문자 P)인데, 3번 줄에서는 `itemprice`(소문자 p)라고 썼어요. 대소문자가 다르면 다른 이름이라, 그런 변수는 없다는 `ReferenceError`가 났어요. 이처럼 변수 오류는 **이름을 만든 줄**과 비교해 봐야 원인이 보이는 경우가 많아요.
</Section>

<Section kind="pitfalls">
<Pitfall misconception="js.mc.assign-is-equality">
<Wrong>`=`는 "같다"라는 뜻이다. 그래서 `x = x + 1`은 말이 안 되는 문장이다.</Wrong>
<Actual>`x = x + 1`은 지금 `x`에 1을 더한 값을 다시 `x`에 넣는 정상적인 문장이에요.</Actual>
<Right>`=`는 오른쪽을 계산해 왼쪽에 넣는 대입이에요. "넣는다" 또는 `←`로 읽어요. (값이 같은지 비교하는 연산자는 "비교 연산" 단원에서 따로 배워요.)</Right>
</Pitfall>

<Pitfall misconception="js.mc.variable-remembers-formula">
<Wrong>`total = price * count;` 뒤에 `count`를 바꾸면 `total`도 저절로 다시 계산된다. `b = a;` 뒤에 `a`를 바꾸면 `b`도 바뀐다.</Wrong>
<Actual>`total`과 `b`에는 대입하던 **그 순간의 값**이 들어가요. 나중에 `count`나 `a`를 바꿔도 그대로예요.</Actual>
<Right>대입은 값을 복사할 뿐 식이나 다른 변수를 기억하지 않아요. 새 값이 필요하면 `total = price * count;`를 다시 실행해야 해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.assign-direction">
<Wrong>`90 = score;`라고 써도 score에 90이 들어간다.</Wrong>
<Actual>실행 전에 `SyntaxError`가 나요. Chrome에서는 `Invalid left-hand side in assignment`(대입의 왼쪽이 잘못됐어요)라고 알려 줘요.</Actual>
<Right>대입은 항상 오른쪽 → 왼쪽이에요. 값을 받을 변수를 왼쪽에 써서 `score = 90;`이라고 해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.let-again-to-change">
<Wrong>값을 바꿀 때도 `let score = 20;`처럼 `let`을 다시 쓴다.</Wrong>
<Actual>같은 이름으로 `let`을 두 번 쓰면 실행 전에 `SyntaxError: Identifier 'score' has already been declared`가 나요.</Actual>
<Right>`let`은 처음 만들 때 한 번만 써요. 바꿀 때는 `score = 20;`처럼 대입만 해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.variable-name-in-quotes">
<Wrong>변수 값을 출력하려고 `console.log("score")`라고 쓴다.</Wrong>
<Actual>변수와 상관없는 글자 `score`가 출력돼요.</Actual>
<Right>변수 이름에는 따옴표를 붙이지 않아요. `console.log(score)`라고 써야 들어 있는 값이 나와요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.let-needs-initial-value">
<Wrong>`let answer;`처럼 값 없이 변수를 만들면 오류가 난다.</Wrong>
<Actual>오류가 나지 않아요. `answer`에는 "아직 값이 없음"을 뜻하는 `undefined`가 들어 있어요.</Actual>
<Right>`let`은 값 없이 만들고 나중에 대입해도 돼요. 값 없이 만들 수 없는 것은 `const`예요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.const-can-reassign">
<Wrong>`const`에 새 값을 대입하면 바뀌거나, 적어도 오류 없이 무시된다.</Wrong>
<Actual>실행 중에 `TypeError: Assignment to constant variable.`이 나고 프로그램이 멈춰요.</Actual>
<Right>다시 대입해야 하는 값은 처음부터 `let`으로 만들어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.const-declare-later">
<Wrong>`const birthday;`로 먼저 만들고, 다음 줄에서 한 번만 값을 넣으면 된다.</Wrong>
<Actual>값이 없는 `const`는 실행 전에 `SyntaxError`가 나요(Chrome의 설명은 `Missing initializer in const declaration`). 첫 줄도 실행되지 않아요.</Actual>
<Right>`const`는 만드는 문장에서 바로 값을 넣어요: `const birthday = "5월 5일";`</Right>
</Pitfall>

<Pitfall misconception="js.mc.const-is-immutable">
<Wrong>`const`로 만든 값은 어떤 방법으로도 절대 바뀌지 않는다.</Wrong>
<Actual>`const`가 막는 것은 이름에 **다른 값을 다시 대입하는 것**(재할당)뿐이에요.</Actual>
<Right>숫자나 글자처럼 지금까지 배운 값은 재할당만 막으면 바뀔 일이 없어요. 하지만 나중에 배울 배열과 객체는 `const`로 만들어도 안의 내용을 바꿀 수 있어요. 이 차이는 "참조와 복사" 단원에서 다시 다뤄요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.identifier-case-insensitive">
<Wrong>`itemPrice`로 만들고 `itemprice`로 써도 같은 변수다.</Wrong>
<Actual>대소문자가 다르면 다른 이름이라 `ReferenceError: itemprice is not defined`가 나요.</Actual>
<Right>변수를 쓸 때는 만든 이름과 대소문자까지 똑같이 써요. 에디터의 자동 완성을 쓰면 이런 실수가 줄어요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.identifier-invalid-chars">
<Wrong>`total-price`, `my name`, `1st`도 변수 이름으로 쓸 수 있다.</Wrong>
<Actual>하이픈은 빼기 기호로, 공백은 이름의 끝으로 읽혀서 `SyntaxError`가 나요. 숫자로 시작하는 이름도 `SyntaxError`예요.</Actual>
<Right>여러 단어는 `totalPrice`처럼 camelCase로 이어 쓰고, 숫자는 `first`, `player1`처럼 뒤에 붙이거나 글자로 바꿔요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
실제 웹 서비스의 코드도 변수로 가득해요. 예를 들어 쇼핑몰 장바구니는 이런 식으로 값을 관리해요.

```js
const shippingFee = 3000;      // 배송비: 바뀌지 않는 값 → const
let itemCount = 0;             // 담은 상품 수: 바뀌는 값 → let
let totalPrice = 0;

itemCount = itemCount + 1;     // 상품을 하나 담았어요
totalPrice = totalPrice + 12000;

console.log("상품 수:", itemCount);
console.log("결제 금액:", totalPrice + shippingFee);
```

- 바뀌지 않는 설정값(배송비, 세율, 최대 개수)은 `const`로 만들어 실수로 바꾸지 못하게 해요.
- 사용자의 행동에 따라 바뀌는 값(상품 수, 합계, 로그인 여부)은 `let`으로 만들어요.
- `shippingFee`, `itemCount`처럼 이름만 봐도 무엇인지 알 수 있게 지어요. 코드는 쓰는 시간보다 읽는 시간이 훨씬 길어요.

실무에서는 대부분의 변수를 `const`로 만들고, 정말 바뀌어야 하는 것만 `let`으로 만들어요.
</Section>

<Section kind="summary">
- `let 이름 = 값;`으로 변수를 만들고, 따옴표 없이 이름을 쓰면 들어 있는 값을 꺼내요.
- `=`는 대입이에요. 오른쪽을 먼저 계산하고, 그 값을 왼쪽 변수에 넣어요. 이전 값은 덮어써져요.
- 대입은 그 순간의 값을 복사할 뿐, 식이나 다른 변수와 연결되지 않아요.
- `let`은 처음 만들 때 한 번만 써요. 값을 바꿀 때는 대입만 해요.
- `const`는 다시 대입할 수 없고(TypeError), 만들 때 반드시 값을 넣어야 해요(SyntaxError). 먼저 `const`로 쓰고, 바뀌어야 하는 값만 `let`으로 써요.
- 이름에는 글자·숫자·`_`·`$`만 쓰고 숫자로 시작하지 않아요. 대소문자를 구분하고, 여러 단어는 camelCase로 이어 써요.
</Section>
