<Section kind="objectives">
- 인수를 덜 넘기면 매개변수가 `undefined`가 된다는 것을 알고, 기본값 매개변수로 빠진 인수를 채울 수 있어요.
- 기본값이 `undefined`일 때만 쓰이고 `null`이나 `0`을 넘기면 쓰이지 않는다는 것을 예측할 수 있어요.
- 나머지 매개변수로 개수가 정해지지 않은 인수를 모으고, `length`와 위치 번호로 하나씩 꺼내 계산할 수 있어요.
</Section>

<Section kind="prerequisites" />

<Section kind="intro">
분식집 주문 금액을 계산하는 함수를 만들었다고 해 볼게요.

```js
function orderPrice(price, count) {
  return price * count;
}
```

손님 대부분은 하나만 시켜요. 그런데 매번 `orderPrice(4500, 1)`처럼 `1`을 꼭 써야 할까요? 깜빡하고 `orderPrice(4500)`만 쓰면 어떻게 될까요? 오류가 날까요, 아니면 이상한 값이 나올까요?

반대 상황도 있어요. "합계 구하기" 함수에 숫자를 2개 넘길 때도, 5개 넘길 때도 있다면 매개변수를 몇 개 만들어야 할까요?

이 단원에서는 두 가지 도구를 배워요. 인수가 빠졌을 때 쓸 값을 미리 정해 두는 **기본값 매개변수**, 그리고 개수가 정해지지 않은 인수를 한데 모으는 **나머지 매개변수**예요.
</Section>

<Section kind="principle">
### 인수가 모자라면: 남는 매개변수는 undefined

<ConceptLink to="js.fn.params-args">매개변수와 인수</ConceptLink>에서 인수는 순서대로 매개변수에 들어간다고 배웠어요. 그런데 인수가 매개변수보다 적으면 어떻게 될까요?

JavaScript는 인수 개수를 검사하지 않아요. **오류 없이** 함수를 실행하고, 짝이 없는 매개변수에는 `undefined`가 들어가요.

```js
function orderPrice(price, count) {
  return price * count;
}
console.log(orderPrice(4500)); // NaN
```

`price`는 `4500`, `count`는 `undefined`예요. `4500 * undefined`는 `NaN`이라 결과가 `NaN`이에요. 오류가 나지 않아서 오히려 알아차리기 어려워요. 반대로 인수가 더 많으면 남는 인수는 그냥 쓰이지 않아요.

### 기본값 매개변수

매개변수 이름 뒤에 `= 값`을 붙이면, 그 매개변수가 `undefined`일 때 대신 쓸 값을 정할 수 있어요.

```js
function orderPrice(price, count = 1) {
  return price * count;
}
console.log(orderPrice(4500));    // 4500 (count는 기본값 1)
console.log(orderPrice(4500, 3)); // 13500 (count는 넘긴 3)
```

규칙은 하나예요. **매개변수 값이 `undefined`일 때만** 기본값을 써요.

| 호출 | `count`에 들어가는 값 | 이유 |
|---|---|---|
| `orderPrice(4500)` | `1` | 인수가 없어 `undefined` → 기본값 |
| `orderPrice(4500, undefined)` | `1` | `undefined`를 넘김 → 기본값 |
| `orderPrice(4500, 3)` | `3` | 넘긴 값 그대로 |
| `orderPrice(4500, 0)` | `0` | `0`은 `undefined`가 아님 |
| `orderPrice(4500, null)` | `null` | `null`도 `undefined`가 아님 |

`0`, `null`, 빈 문자열 `""`은 "값이 없다"처럼 보이지만, 넘긴 이상 그 값이 그대로 들어가요. 그래서 "0원이면 무료"처럼 `0`이 뜻 있는 값일 때 기본값 매개변수가 잘 맞아요. 모듈 3에서 배운 `count || 1`은 `0`도 falsy라서 `1`로 바꿔 버리지만, 기본값 매개변수는 `0`을 지켜 줘요.

### 나머지 매개변수

매개변수 앞에 점 세 개 `...`를 붙이면, **남은 인수를 모두 한 묶음으로** 모아요.

```js
function countMenus(name, ...menus) {
  console.log(name + "님 주문: " + menus.length + "개");
  console.log("첫 메뉴: " + menus[0]);
}
countMenus("민수", "김밥", "라면", "떡볶이");
```

```text
민수님 주문: 3개
첫 메뉴: 김밥
```

`name`이 첫 인수 `"민수"`를 먼저 받고, `menus`는 **그 뒤에 남은** 세 값을 모아요. 이 묶음은 모듈 8에서 자세히 배울 **배열**이에요. 지금은 두 가지만 알면 돼요.

| 쓰는 법 | 뜻 | 위 예에서 |
|---|---|---|
| `menus.length` | 담긴 값의 개수 | `3` |
| `menus[0]`, `menus[1]`, … | 위치 번호(0부터)로 값 꺼내기 | `"김밥"`, `"라면"` |

위치 번호는 0부터 시작하므로 마지막 값의 번호는 `length - 1`이에요. 그래서 모든 값을 하나씩 보려면 모듈 5의 `for`를 `i = 0; i < menus.length`로 써요. 인수를 하나도 남기지 않으면 `menus.length`는 `0`이고 반복은 한 번도 돌지 않아요.

나머지 매개변수는 "남은 것 전부"를 모으기 때문에 **맨 끝에 하나만** 둘 수 있어요.
</Section>

<Section kind="examples">
첫 번째 예제는 인수를 덜 넘긴 함수와 기본값을 둔 함수를 비교해요. 세 줄이 각각 무엇을 출력할까요?

<RunnableExample id="missing-and-default" lang="js" predict predictKind="console" concepts={["js.fn.default-params"]}>
```js
function greet(name, mark) {
  return "안녕, " + name + mark;
}
function greetDefault(name, mark = "!") {
  return "안녕, " + name + mark;
}

console.log(greet("하나"));
console.log(greetDefault("하나"));
console.log(greetDefault("하나", "?"));
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
```text
안녕, 하나undefined
안녕, 하나!
안녕, 하나?
```

- 8번 줄: `greet`에는 인수가 하나뿐이라 `mark`가 `undefined`예요. 오류는 나지 않고, 문자열에 이어 붙으면서 `undefined`라는 글자가 그대로 붙어요.
- 9번 줄: `greetDefault`의 `mark`도 처음에는 `undefined`지만 기본값 `"!"`로 바뀌어요.
- 10번 줄: `"?"`를 넘겼으니 기본값은 쓰이지 않아요.
</Section>

<Section kind="examples">
두 번째 예제는 기본값이 언제 쓰이고 언제 안 쓰이는지 보여 줘요. 넷째 줄과 다섯째 줄을 특히 잘 예측해 보세요.

<RunnableExample id="default-when" lang="js" predict predictKind="console" concepts={["js.fn.default-params"]}>
```js
function deliveryFee(fee = 3000) {
  return "배달비: " + fee;
}

console.log(deliveryFee());
console.log(deliveryFee(2000));
console.log(deliveryFee(undefined));
console.log(deliveryFee(0));
console.log(deliveryFee(null));
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
```text
배달비: 3000
배달비: 2000
배달비: 3000
배달비: 0
배달비: null
```

- 인수가 없거나(`deliveryFee()`) `undefined`를 넘기면 기본값 `3000`이 쓰여요.
- `0`과 `null`은 `undefined`가 아니라서 넘긴 값 그대로예요. "무료 배달(0원)"을 표현할 수 있는 것도 이 덕분이에요.
</Section>

<Section kind="examples">
세 번째 예제는 나머지 매개변수로 개수와 상관없이 합계를 구해요. `for`가 몇 번 도는지 생각하며 예측해 보세요.

<RunnableExample id="rest-sum" lang="js" predict predictKind="console" concepts={["js.fn.rest-params"]}>
```js
function total(label, ...prices) {
  let sum = 0;
  for (let i = 0; i < prices.length; i++) {
    sum += prices[i];
  }
  return label + " " + prices.length + "개, " + sum + "원";
}

console.log(total("점심", 4500, 3000, 5000));
console.log(total("간식", 1500));
console.log(total("없음"));
```
</RunnableExample>
</Section>

<Section kind="walkthrough">
```text
점심 3개, 12500원
간식 1개, 1500원
없음 0개, 0원
```

| 호출 | `label` | `prices.length` | `prices`에 담긴 값 |
|---|---|---|---|
| `total("점심", 4500, 3000, 5000)` | `"점심"` | 3 | 4500, 3000, 5000 |
| `total("간식", 1500)` | `"간식"` | 1 | 1500 |
| `total("없음")` | `"없음"` | 0 | (없음) |

- 첫 인수는 항상 `label`이 받고, `prices`는 남은 것만 모아요.
- `i`가 0부터 `prices.length - 1`까지 가면서 `prices[i]`로 값을 하나씩 꺼내 누적해요(<ConceptLink to="js.loops.accumulator-pattern">누적 패턴</ConceptLink>).
- 남은 인수가 없으면 `prices.length`는 0이라 반복이 한 번도 돌지 않고 `sum`은 0 그대로예요.
</Section>

<Section kind="pitfalls">
<Pitfall misconception="js.mc.missing-arg-error">
<Wrong>매개변수가 두 개인 함수에 인수를 하나만 넘기면 오류가 나서 실행되지 않는다.</Wrong>
<Actual>첫 번째 예제의 `greet("하나")`는 오류 없이 `안녕, 하나undefined`를 출력했어요. 짝이 없는 매개변수는 `undefined`가 될 뿐이에요. 계산에 쓰면 `NaN`이 나오기도 해요.</Actual>
<Right>JavaScript는 인수 개수를 검사하지 않아요. 빠질 수 있는 인수에는 기본값을 정해 두고, 결과에 `undefined`나 `NaN`이 보이면 인수를 빠뜨리지 않았는지 확인해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.default-on-null">
<Wrong>`deliveryFee(null)`이나 `deliveryFee(0)`도 "값이 없다"는 뜻이니 기본값 `3000`이 쓰인다.</Wrong>
<Actual>두 번째 예제에서 `deliveryFee(0)`은 `배달비: 0`, `deliveryFee(null)`은 `배달비: null`이었어요.</Actual>
<Right>기본값은 매개변수가 `undefined`일 때(인수가 없거나 `undefined`를 넘길 때)만 쓰여요. 기본값을 쓰고 싶다면 그 인수를 아예 빼고 호출해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.rest-not-last">
<Wrong>`function label(...items, title)`처럼 나머지 매개변수 뒤에 다른 매개변수를 둘 수 있다.</Wrong>
<Actual>

나머지 매개변수가 남은 인수를 모두 가져가면 뒤의 매개변수가 받을 것이 없어요. 그래서 이 코드는 실행 전에 문법 오류가 나요.

```text
SyntaxError: Rest parameter must be last formal parameter
```
</Actual>
<Right>나머지 매개변수는 맨 끝에 하나만 둬요. 꼭 받아야 하는 값은 앞에 일반 매개변수로 두고 `function label(title, ...items)`처럼 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.rest-includes-named">
<Wrong>`function order(name, ...menus)`를 `order("민수", "김밥", "라면")`으로 부르면 `menus`에 세 값이 모두 들어간다.</Wrong>
<Actual>`name`이 `"민수"`를 먼저 받고, `menus`에는 남은 `"김밥"`, `"라면"` 두 값만 들어가요. `menus.length`는 2예요.</Actual>
<Right>인수는 앞에서부터 일반 매개변수가 하나씩 받고, 나머지 매개변수는 그 뒤에 **남은 것만** 모아요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
웹 개발에서 기본값 매개변수는 "대부분은 같은 값, 가끔 다른 값"인 설정에 많이 써요. 예를 들어 알림 문구를 만드는 함수는 보통 "안내" 종류로 쓰고, 필요할 때만 "경고"를 넘겨요.

```js
function makeNotice(message, kind = "안내") {
  return "[" + kind + "] " + message;
}
console.log(makeNotice("저장했어요"));           // [안내] 저장했어요
console.log(makeNotice("입력이 비었어요", "경고")); // [경고] 입력이 비었어요
```

나머지 매개변수는 "몇 개가 올지 모르는 값"을 받을 때 써요. 여러 점수의 최고점을 구하거나, 여러 단어를 이어 붙이는 함수처럼요. 실제로 JavaScript에 들어 있는 `Math.max(3, 9, 4)`나 `console.log("a", "b", "c")`도 인수를 몇 개든 받을 수 있는 함수예요.
</Section>

<Section kind="summary">
- 인수를 덜 넘겨도 오류는 나지 않아요. 짝이 없는 매개변수는 `undefined`가 돼요.
- `function f(count = 1)`처럼 기본값을 정하면, 매개변수가 `undefined`일 때 그 값을 써요.
- `0`, `null`, `""`을 넘기면 기본값을 쓰지 않고 넘긴 값 그대로예요.
- `function f(first, ...rest)`의 나머지 매개변수는 앞 매개변수가 받고 **남은** 인수를 모두 한 묶음(배열)으로 모아요.
- 묶음의 개수는 `rest.length`, 값은 `rest[0]`처럼 0부터 시작하는 위치 번호로 꺼내요. `for (let i = 0; i < rest.length; i++)`로 하나씩 볼 수 있어요.
- 나머지 매개변수는 맨 끝에 하나만 둘 수 있어요.
</Section>
