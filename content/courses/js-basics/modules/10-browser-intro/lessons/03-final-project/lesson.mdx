<Section kind="intro">
JavaScript 기초의 마지막 단원이에요. 지금까지 배운 함수, 조건문, 문자열, 그리고 이 모듈의 DOM과 이벤트를 모두 써서 **할 일 목록**을 만들어요.

완성하면 이런 일을 할 수 있어요.

- 할 일을 쓰고 **추가**를 누르거나 Enter 키를 누르면 목록 끝에 붙어요.
- 할 일 글자를 누르면 줄이 그어지고(완료), 다시 누르면 돌아와요.
- **삭제** 버튼으로 할 일을 지워요.
- 위쪽에 "남은 할 일 2개"처럼 완료하지 않은 할 일 수가 보이고, 목록이 비면 "할 일이 없어요"가 보여요.

한 번에 다 만들려고 하면 어디서 틀렸는지 찾기 어려워요. 그래서 이 프로젝트는 **여섯 단계**로 나뉘어 있어요. 프로젝트 문제의 체크가 단계별로 묶여 있으니, 한 단계를 만들 때마다 실행해서 그 단계의 체크가 통과하는지 확인하고 다음으로 넘어가요.

| 단계 | 만드는 것 | 주로 쓰는 것 |
|---|---|---|
| 1 | 제출하면 할 일 추가 | `submit`, `preventDefault`, `createElement`, `append` |
| 2 | 입력창 비우기, 공백 정리, 빈 입력 무시 | `value`, `trim`, `return` |
| 3 | 남은 할 일 개수 | `querySelectorAll`, `length`, `textContent` |
| 4 | 눌러서 완료 표시 | `addEventListener`, `classList.toggle` |
| 5 | 삭제 버튼 | `remove()` |
| 6 | 빈 목록 안내 | `classList.add`·`remove` |

연습 세트에는 큰 프로젝트 문제 하나와, 그 앞뒤로 설계를 확인하는 문제, 기능을 더하는 문제, 버그를 고치는 문제가 함께 있어요.
</Section>

<Section kind="principle">
### 설계의 세 가지 원칙

코드를 쓰기 전에 세 가지를 정해 두면 단계가 쉬워져요.

**1. 추가는 폼의 submit 한곳에서 해요.** 버튼을 누르든 Enter 키를 누르든 폼에서 `submit`이 일어나요. 함수의 첫 줄에서 `event.preventDefault()`로 페이지가 새로 열리는 것을 막고, 입력창의 글자는 함수 안에서 읽어요.

**2. 이벤트는 요소를 만드는 자리에서 등록해요.** 할 일의 글자와 삭제 버튼은 사용자가 추가할 때 만들어져요. 페이지가 열릴 때는 아직 없으니 `querySelectorAll`로 찾아 등록할 수 없어요. 그래서 할 일 하나를 만드는 함수 안에서, 방금 만든 요소에 바로 `addEventListener`를 해요.

<RunnableExample id="register-on-create" lang="web" concepts={["js.dom.add-event-listener", "js.dom.document-tree"]}>
```html
<button id="add">스티커 추가</button>
<div id="board"></div>
<script>
  const board = document.querySelector("#board");
  let made = 0;

  function addSticker() {
    made++;
    const sticker = document.createElement("button");
    sticker.textContent = "스티커 " + made;
    sticker.addEventListener("click", () => {
      sticker.textContent = sticker.textContent + " ★";
    });
    board.append(sticker);
  }

  document.querySelector("#add").addEventListener("click", addSticker);
</script>
```
</RunnableExample>

실행한 뒤 **스티커 추가**를 몇 번 누르고, 만들어진 스티커를 눌러 보세요. 몇 번째로 만든 스티커든 자기 글자에만 별이 붙어요. 스티커마다 만들어지는 순간 자기 함수가 등록되고, 그 함수가 같은 자리의 `sticker`를 기억하기 때문이에요.

**3. 개수와 안내는 화면에서 다시 세요.** 남은 개수를 변수에 따로 들고 있으면, 추가·완료·삭제마다 더하고 빼다가 화면과 어긋나기 쉬워요. 대신 목록에서 `.todo`와 `.todo.done`의 개수를 그때그때 세어 글자를 다시 쓰는 함수(예: `updateStatus()`)를 하나 만들고, 목록이 바뀌는 곳마다 불러요.

### 막히면 이렇게 확인해요

- 체크가 실패하면 그 단계의 체크 설명을 먼저 읽어요. 체크는 문제에 적힌 클래스 이름(`todo`, `todo-text`, `delete`, `done`, `hidden`)으로 요소를 찾아요.
- 화면이 그대로면 `console.log`로 값을 찍어 봐요. 특히 입력창에서 읽은 글자, 찾은 요소(`null`이 아닌지), 넣은 클래스 이름(점이 붙지 않았는지)을 확인해요.
- 이 모듈의 흔한 실수들, 즉 함수에 괄호를 붙여 등록하기, `on`을 붙인 이벤트 이름, 함수 밖에서 한 번만 읽은 `value`, `querySelector`와 `querySelectorAll` 혼동이 프로젝트에서도 그대로 나와요.
</Section>

<Section kind="summary">
- 큰 기능은 작은 단계로 나눠, 한 단계를 만들 때마다 실행해 확인해요.
- 입력은 폼의 `submit`에서 받고, `preventDefault()`로 기본 동작을 막고, `value`는 함수 안에서 읽어 `trim()`해요.
- 새 요소는 `createElement`로 만들어 `append`하고, 그 요소의 이벤트는 만드는 자리에서 등록해요.
- 남은 개수와 안내 문구는 목록이 바뀔 때마다 화면에서 다시 세어 써요.
</Section>
