<Section kind="objectives">
- 처리할 수 없는 입력을 받았을 때 `throw new Error(...)`로 알리는 함수를 만들 수 있어요.
- `try...catch`가 실행되는 순서를 예측하고, `catch`에서 오류 객체의 `name`과 `message`를 읽을 수 있어요.
- `try...catch`로 잡을 수 있는 오류(실행 중 오류)와 잡을 수 없는 오류(문법 오류)를 구별할 수 있어요.
- `finally`가 언제 실행되는지 예측할 수 있어요.
</Section>

<Section kind="intro">
모듈 1에서 오류 메시지를 읽는 법을 배웠어요. 그때 오류는 "나면 프로그램이 거기서 멈추는 것"이었어요. 그런데 실제 프로그램에서는 오류가 날 수 있는 상황이 늘 있어요.

- 사용자가 가격 칸에 `삼천`이라고 써서 숫자로 바꿀 수 없어요.
- 잔액보다 많은 돈을 보내려고 해요.
- 서버에서 받은 회원 정보에 있어야 할 속성이 빠져 있어요.

이럴 때마다 프로그램 전체가 멈추면 곤란해요. 쇼핑몰에서 상품 하나의 가격이 잘못되었다고 화면 전체가 하얗게 멈추면 안 되겠죠. "이 상품은 가격을 읽을 수 없어요"라고 알려 주고 나머지는 계속 보여 줘야 해요.

이 단원에서는 오류를 **직접 던지고(`throw`)**, 던져진 오류를 **잡아서 처리하고(`try...catch`)**, 오류가 나든 안 나든 **꼭 해야 할 일을 하는(`finally`)** 방법을 배워요. 앞 단원들에서 배운 객체가 여기서도 나와요. 오류도 `name`과 `message` 속성을 가진 객체거든요.
</Section>

<Section kind="principle">
### 오류는 객체예요

`new Error("설명")`은 오류 객체를 만들어요. 오류 객체에는 모듈 1에서 읽던 두 부분이 속성으로 들어 있어요.

| 속성 | 뜻 | `new Error("잔액이 부족해요")`에서 |
|---|---|---|
| `name` | 오류 종류 | `"Error"` |
| `message` | 설명 | `"잔액이 부족해요"` |

JavaScript가 스스로 내는 오류도 같은 모양이에요. 없는 변수를 쓰면 `name`이 `"ReferenceError"`인 오류 객체가, `undefined`의 속성을 읽으면 `name`이 `"TypeError"`인 오류 객체가 만들어져요. `console.log`로 오류 객체를 출력하면 `Error: 잔액이 부족해요`처럼 `name: message` 모양으로 보여요.

### throw: 오류를 던져요

`throw 오류객체;`는 그 자리에서 실행을 멈추고 오류를 **던져요**.

```js
function withdraw(balance, amount) {
  if (amount > balance) {
    throw new Error("잔액이 부족해요");   // 여기서 멈춤
  }
  return balance - amount;               // 위에서 던지면 실행되지 않음
}
```

- `throw`는 출력이 아니에요. `return`처럼 함수를 끝내지만, 값을 돌려주는 대신 오류를 던져요.
- 던진 오류를 아무도 잡지 않으면, 모듈 1에서 본 실행 중 오류와 똑같이 **프로그램 전체가 멈추고** 콘솔에 `Error: 잔액이 부족해요`와 줄 번호가 나와요.
- 함수가 "이 입력으로는 일을 할 수 없다"고 알리는 방법이에요. `return "오류"`처럼 이상한 값을 돌려주면 부른 쪽이 알아채지 못하고 그 값으로 계속 계산할 수 있지만, 던진 오류는 무시할 수 없어요.

### try...catch: 던져진 오류를 잡아요

```js
try {
  // 오류가 날 수 있는 코드
} catch (err) {
  // 오류가 나면 실행되는 코드. err에 오류 객체가 들어 있음
}
// 이어지는 코드
```

실행 순서는 두 가지 중 하나예요.

| 상황 | 실행 순서 |
|---|---|
| `try`에서 오류가 나지 않음 | `try` 블록 전체 → (`catch` 건너뜀) → 이어지는 코드 |
| `try`의 어떤 줄에서 오류가 남 | `try`를 그 줄까지 → **`try`의 나머지는 건너뜀** → `catch` 블록 → 이어지는 코드 |

여기서 두 가지가 중요해요.

1. 오류가 난 줄 뒤의 `try` 블록으로는 **다시 돌아가지 않아요**. `catch`는 "오류를 고치고 다시 하기"가 아니라 "오류가 났을 때 대신 할 일"이에요.
1. `catch`로 잡은 오류는 처리된 오류라서 **프로그램은 멈추지 않아요**. `catch`가 끝나면 `try...catch` 다음 줄부터 계속 실행돼요.

`try` 안에서 부른 함수가 던진 오류도 잡혀요. 함수 안에서 던진 오류는 그 함수를 끝내고, 부른 자리로 거슬러 올라가며 가장 가까운 `try...catch`를 찾아요.

### try...catch가 잡지 못하는 오류: 문법 오류

모듈 1에서 JavaScript는 코드를 두 단계로 다룬다고 했어요. **문법 검사**를 먼저 하고, 통과하면 **실행**해요.

`try...catch`는 실행 단계에서 동작하는 문장이에요. 그런데 문법 오류(`SyntaxError`)는 실행하기 **전에** 코드 전체를 검사할 때 나요. 문법 오류가 있으면 프로그램은 첫 줄부터 아예 시작되지 않으니, `try...catch`도 실행될 기회가 없어요. 그래서 `try` 블록 **안에** 괄호를 빠뜨려도 `catch`는 그 오류를 잡지 못해요.

| 오류 | 언제 나나요 | `try...catch`로 잡을 수 있나요 |
|---|---|---|
| `SyntaxError` (괄호·따옴표 빠뜨림 등) | 실행 전 문법 검사 | 아니요. 프로그램이 시작되지 않아요 |
| `ReferenceError`, `TypeError` | 실행 중 | 예 |
| `throw`로 던진 오류 | 실행 중 | 예 |

문법 오류는 잡는 것이 아니라 **고치는** 오류예요.

### finally: 항상 마지막에 실행돼요

`try...catch` 뒤에 `finally` 블록을 붙이면, 그 블록은 **어떤 경우에도** 마지막에 실행돼요.

```js
try {
  // ...
} catch (err) {
  // ...
} finally {
  // 오류가 나든 안 나든 항상 실행
}
```

- `try`가 오류 없이 끝나도 실행돼요.
- 오류가 나서 `catch`가 실행되면 `catch` 뒤에 실행돼요.
- `try`나 `catch` 안에서 `return`해도, 함수가 끝나기 직전에 실행돼요.

그래서 "불러오는 중" 표시 끄기처럼 성공하든 실패하든 반드시 해야 하는 **정리 작업**을 `finally`에 둬요.
</Section>

```js
try {
  console.log(parsePrice("3000"));

  console.log("여기는 실행될까요?");

  console.log(err.name);
  console.log(err.message);
}

```

<Section kind="examples">
세 번째 예제는 `finally`가 언제 실행되는지 확인해요. 회원 정보를 불러오는 함수를 두 번 불러요. 두 번째에는 `undefined`를 넘겨요.

<RunnableExample id="finally-order" lang="js" predict predictKind="console" concepts={["js.errors.finally", "js.errors.try-catch"]}>
```js
function loadProfile(user) {
  console.log("불러오는 중...");
  try {
    console.log("이름: " + user.name);
    return "성공";
  } catch (err) {
    console.log("실패: " + err.name);
    return "실패";
  } finally {
    console.log("로딩 표시 끄기");
  }
}

console.log(loadProfile({ name: "민지" }));
console.log(loadProfile(undefined));
```
</RunnableExample>
</Section>

- 첫 호출은 오류가 없어요. 5번 줄에서 `return "성공"`을 만나지만, 함수가 끝나기 **직전에** `finally`가 실행되어 `로딩 표시 끄기`가 먼저 나오고, 그다음 14번 줄이 반환값 `성공`을 출력해요.
- 두 번째 호출에서는 `user`가 `undefined`라서 4번 줄의 `user.name`이 `TypeError`를 내요. JavaScript가 낸 오류도 `throw`로 던진 오류처럼 잡혀요. `catch`가 `실패: TypeError`를 출력하고 `return "실패"`를 만나지만, 이번에도 `finally`가 먼저 실행돼요.
- 성공해도, 실패해도, `return`이 있어도 `finally`는 실행됐어요.

- `try...catch`는 실행 단계의 문장이라, 실행되지 않은 프로그램 안에서는 아무것도 잡을 수 없어요.
- 문법 오류는 메시지와 줄 번호를 보고 **고쳐야** 해요. `console.log("try 안");`으로 고치면 `시작`, `try 안`, `끝`이 나와요.

<Section kind="pitfalls">
<Pitfall misconception="js.mc.throw-just-logs">
<Wrong>`throw new Error("수량이 잘못됐어요")`는 `console.log`처럼 메시지를 보여 주고, 다음 줄이 이어서 실행된다.</Wrong>
<Actual>`throw`는 그 자리에서 실행을 멈춰요. 함수 안이면 함수가 끝나고 `return`도 실행되지 않아요. 잡는 곳이 없으면 두 번째 예제처럼 프로그램 전체가 멈춰요.</Actual>
<Right>`throw`는 "더 진행할 수 없다"는 신호예요. 메시지를 보여 주는 일은 오류를 잡은 `catch`에서 `err.message`를 출력해서 해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.try-catch-catches-syntax-error">
<Wrong>`try` 블록 안에서 괄호를 빠뜨려도 `catch`가 잡아 주니까 프로그램은 실행된다.</Wrong>
<Actual>네 번째 예제처럼 `SyntaxError`는 실행 전 문법 검사에서 나요. 프로그램이 한 줄도 실행되지 않으니 `try...catch`도 실행되지 않아요.</Actual>
<Right>`try...catch`는 실행 중 오류(`ReferenceError`, `TypeError`, `throw`로 던진 오류)를 잡아요. 문법 오류는 메시지를 읽고 코드를 고쳐요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.try-resumes-after-catch">
<Wrong>`try`의 중간 줄에서 오류가 나면, `catch`가 처리한 뒤 `try`의 남은 줄로 돌아가 이어서 실행한다.</Wrong>
<Actual>첫 번째 예제의 `"여기는 실행될까요?"`는 끝까지 출력되지 않았어요. 오류가 난 줄 뒤의 `try` 블록은 건너뛰고, 다시 돌아가지 않아요.</Actual>
<Right>오류가 나도 꼭 실행해야 하는 줄은 `try` 밖(`try...catch` 다음)이나 `finally`에 둬요. 여러 개를 하나씩 처리하고 싶으면 하나마다 따로 `try...catch`로 감싸요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.caught-error-stops-program">
<Wrong>`catch`로 오류를 처리해도, 오류가 났으니 프로그램은 거기서 끝난다.</Wrong>
<Actual>첫 번째 예제의 마지막 줄 `프로그램은 계속돼요`가 출력됐어요. 잡힌 오류는 처리된 오류라서 `try...catch` 다음 줄부터 계속 실행돼요.</Actual>
<Right>프로그램을 멈추는 것은 **아무도 잡지 않은** 오류뿐이에요. 그래서 오류가 날 수 있는 부분만 `try...catch`로 감싸면, 나머지 기능은 계속 동작해요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.finally-only-on-error">
<Wrong>`finally`는 `catch`처럼 오류가 났을 때만 실행된다.</Wrong>
<Actual>세 번째 예제의 첫 호출은 오류가 없었는데도 `로딩 표시 끄기`가 나왔어요. `try` 안에서 `return`했는데도요.</Actual>
<Right>`finally`는 오류가 나든 안 나든, `return`이 있든 없든 항상 마지막에 실행돼요. 오류일 때만 할 일은 `catch`에, 언제나 할 일은 `finally`에 둬요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
쇼핑몰의 장바구니에 담을 수량을 사용자가 직접 입력한다고 해 볼게요. 입력은 항상 문자열로 들어오고, 사용자는 무엇이든 쓸 수 있어요. 수량을 검사하는 함수는 문제가 있으면 오류를 던지고, 화면을 담당하는 쪽은 그 오류를 잡아 안내 문구로 바꿔요.

```js
function toQuantity(text) {
  const qty = Number(text);
  if (!Number.isInteger(qty) || qty < 1) {
    throw new Error("수량은 1 이상의 정수로 입력해 주세요");
  }
  if (qty > 10) {
    throw new Error("한 번에 10개까지만 담을 수 있어요");
  }
  return qty;
}

function addToCart(text) {
  try {
    const qty = toQuantity(text);
    return qty + "개를 담았어요";
  } catch (err) {
    return "담지 못했어요: " + err.message;
  }
}

console.log(addToCart("3"));    // 3개를 담았어요
console.log(addToCart("두 개")); // 담지 못했어요: 수량은 1 이상의 정수로 입력해 주세요
console.log(addToCart("20"));   // 담지 못했어요: 한 번에 10개까지만 담을 수 있어요
```

- `toQuantity`는 검사만 하고, 문제를 **어떻게 보여 줄지**는 정하지 않아요. 같은 함수를 다른 화면에서도 쓸 수 있어요.
- `addToCart`는 오류를 잡아 사용자가 읽을 문장으로 바꿔요. 잘못된 입력이 들어와도 프로그램은 멈추지 않아요.
- `Number.isInteger(qty)`는 `qty`가 정수인지 알려 줘요. `"2.5"`나 `"두 개"`처럼 정수가 아닌 입력은 첫 번째 `throw`로 걸러져요.

실제 웹 개발에서는 서버에서 데이터를 받아올 때 `try...catch`를 가장 많이 써요. 네트워크가 끊기거나 서버가 이상한 데이터를 보내도 화면에 "잠시 후 다시 시도해 주세요"를 보여 주고, `finally`에서 "불러오는 중" 표시를 꺼요.

<Section kind="summary">
- 오류는 `name`(종류)과 `message`(설명) 속성을 가진 객체예요. `new Error("설명")`으로 만들어요.
- `throw`는 그 자리에서 실행을 멈추고 오류를 던져요. 아무도 잡지 않으면 프로그램 전체가 멈춰요.
- `try`에서 오류가 나면 `try`의 나머지를 건너뛰고 `catch`가 오류 객체를 받아 실행돼요. 다시 `try`로 돌아가지 않아요.
- 잡힌 오류는 프로그램을 멈추지 않아요. `catch`가 끝나면 `try...catch` 다음 줄부터 이어져요.
- 문법 오류는 실행 전에 나서 프로그램이 시작되지 않으므로 `try...catch`로 잡을 수 없어요. 고쳐야 해요.
- `finally`는 오류가 나든 안 나든, `return`이 있어도 항상 마지막에 실행돼요.
</Section>
