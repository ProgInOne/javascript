<Section kind="objectives">
- `Object.keys`·`Object.values`·`Object.entries`로 키·값 목록을 만들어 속성 개수를 세고 반복할 수 있어요.
- `for...in`으로 키를 하나씩 돌며 대괄호 표기법으로 값을 읽을 수 있어요.
- 값이 `undefined`인 속성과 아예 없는 속성을 `in` 연산자로 구별할 수 있어요.
- 옵셔널 체이닝(`?.`)과 `??`로 없을 수 있는 중첩 속성을 오류 없이 읽을 수 있어요.
</Section>

<Section kind="intro">
성적표 프로그램을 만든다고 해 볼게요. 과목별 점수를 객체에 담았어요.

```js
const scores = { 국어: 90, 영어: 84, 수학: 72 };
```

평균을 내려면 모든 점수를 더하고 과목 수로 나눠야 해요. 지금까지 배운 방법으로는 `scores.국어 + scores.영어 + scores.수학`처럼 과목 이름을 하나하나 적어야 해요. 그런데 과학이 추가되면요? 학생마다 듣는 과목이 다르다면요? 과목 이름을 코드에 미리 적어 둘 수 없을 때가 많아요.

또 회원 정보처럼 **있을 수도 있고 없을 수도 있는 속성**도 자주 만나요. 별명은 적은 사람도 있고 안 적은 사람도 있고, 주소 객체가 아예 없는 회원도 있어요. 이런 객체에서 `user.address.city`를 읽다가 프로그램이 멈추면 곤란하겠죠.

이 단원에서는 객체의 속성을 **모르는 채로 하나씩 돌아보는 방법**과, 속성이 **있는지 확인하고 안전하게 읽는 방법**을 배워요.
</Section>

<Section kind="principle">
### 객체를 배열로 바꿔서 돌기: `Object.keys`·`values`·`entries`

객체에는 배열처럼 `length`나 순서 번호가 없어요. 그래서 JavaScript는 객체의 내용을 **배열로 뽑아 주는 함수** 세 개를 줘요.

| 함수 | 돌려주는 배열 | `{ 국어: 90, 영어: 84 }`의 결과 |
|---|---|---|
| `Object.keys(obj)` | 키(속성 이름) 목록 | `["국어", "영어"]` |
| `Object.values(obj)` | 값 목록 | `[90, 84]` |
| `Object.entries(obj)` | `[키, 값]` 짝의 목록 | `[["국어", 90], ["영어", 84]]` |

결과가 배열이니까 배열 단원에서 배운 것을 그대로 쓸 수 있어요.

- 속성이 몇 개인지: `Object.keys(obj).length`
- 값을 하나씩 돌기: `for (const score of Object.values(scores)) { ... }`
- 키와 값을 함께 돌기: `for (const entry of Object.entries(scores)) { ... }`에서 `entry[0]`이 키, `entry[1]`이 값이에요. 다음 단원 "구조 분해와 전개"에서 이것을 더 짧게 쓰는 방법을 배워요.

`Object.keys`처럼 앞에 `Object.`을 붙여 부르고, 돌아볼 객체를 괄호 안에 넣는다는 점을 기억하세요. `scores.keys()`가 아니에요.

### 키를 하나씩 받는 반복: `for...in`

```js
for (const key in obj) {
  // key에는 속성 이름(문자열)이 하나씩 들어와요
}
```

`for...in`은 객체의 키를 하나씩 `key`에 넣으며 본문을 반복해요. 들어오는 것은 **값이 아니라 키**예요. 값은 `obj[key]`로 읽어요. `key`는 변수이므로 점 표기법(`obj.key`)이 아니라 대괄호 표기법을 써야 해요. `obj.key`는 이름이 정말 `"key"`인 속성을 찾아요.

키가 나오는 순서는 대부분 속성을 넣은 순서예요. 다만 `"1"`, `"2"`처럼 정수 모양인 키는 작은 수부터 먼저 나와요. 순서가 중요하면 키를 따로 배열에 정해 두는 편이 안전해요. `Object.keys`·`values`·`entries`의 순서도 같은 규칙이에요.

모듈 8에서 배열에 `for...in`을 쓰면 요소 대신 `"0"`, `"1"` 같은 인덱스 문자열이 나왔던 것을 기억하나요? `for...in`은 원래 객체의 키를 도는 반복이라서 그래요. 배열의 값은 `for...of`, 객체의 키는 `for...in`이에요.

### 속성이 있는지 확인하기: `in` 연산자

`"키" in obj`는 객체에 그 이름의 속성이 **있으면 `true`, 없으면 `false`**예요.

없는 속성을 읽으면 `undefined`가 나온다고 배웠어요. 그런데 속성이 있고 **값이 `undefined`**인 경우도 결과는 똑같이 `undefined`예요. 그래서 `obj.key === undefined`만으로는 "없는 것"과 "있는데 값이 비어 있는 것"을 구별할 수 없어요. 구별해야 할 때는 `in`을 써요.

| 객체 | `obj.nickname` | `"nickname" in obj` |
|---|---|---|
| `{ nickname: "코코" }` | `"코코"` | `true` |
| `{ nickname: undefined }` | `undefined` | `true` |
| `{}` | `undefined` | `false` |

### 없을 수 있는 단계 건너뛰기: 옵셔널 체이닝 `?.`

`user.address.city`에서 `user.address`가 `undefined`면, `undefined`의 `city`를 읽으려다 `TypeError`가 나요. 이럴 때 `?.`를 써요.

- `a?.b`는 `a`가 `null`이나 `undefined`면 **오류 없이 `undefined`**를 돌려주고, 아니면 `a.b`를 읽어요.
- 키가 변수에 있으면 `a?.[key]`처럼 써요.
- `??`(모듈 3)와 함께 쓰면 기본값을 정할 수 있어요. `user.address?.city ?? "지역 미설정"`

`?.`는 **바로 앞의 값**만 확인해요. `user?.address.city`는 `user`만 확인하므로, `user`는 있고 `address`가 없으면 `.city`에서 여전히 `TypeError`가 나요. 없을 수 있는 단계 **바로 뒤**에 `?.`를 붙이세요.
</Section>

- `Object.keys`는 키를, `Object.values`는 값을 넣은 순서대로 배열에 담아요.

- `scores.length`는 `undefined`예요. 객체에는 `length`라는 속성이 없으니까요. 없는 속성을 읽은 것이라 오류는 아니에요.

<Section kind="examples">
두 번째 예제는 `for...in`으로 과목을 하나씩 돌며 점수를 출력하고 평균을 내요. 과목이 늘어도 반복 코드는 그대로예요.

<RunnableExample id="for-in-average" lang="js" concepts={["js.obj.for-in", "js.obj.keys-values-entries"]}>
```js
const scores = { 국어: 90, 영어: 84, 수학: 72 };
let total = 0;

for (const subject in scores) {
  console.log(subject + ": " + scores[subject] + "점");
  total += scores[subject];
}

const count = Object.keys(scores).length;
console.log("평균: " + total / count + "점");
```
</RunnableExample>
</Section>


- 2번 줄: `address` 속성이 없으니 `undefined`예요. 없는 속성을 읽는 것은 오류가 아니에요.
- 3번 줄: `user.address`가 `undefined`라서 `?.`가 거기서 멈추고 `undefined`를 돌려줘요.
- 4번 줄: 왼쪽이 `undefined`이므로 `??`가 오른쪽 기본값 `"지역 미설정"`을 골라요.
- 5번 줄: `?.` 없이 `undefined`의 `city`를 읽으려 해서 `TypeError`가 나요. 메시지의 `reading 'city'`는 "`city`를 읽으려다 실패했다"는 뜻이고, 그 앞의 값(`user.address`)이 `undefined`였다는 것을 알려 줘요.

<Section kind="pitfalls">
<Pitfall misconception="js.mc.object-has-length">
<Wrong>배열처럼 `scores.length`로 과목이 몇 개인지 알 수 있다.</Wrong>
<Actual>일반 객체에는 `length` 속성이 없어서 `scores.length`는 `undefined`예요. 오류가 나지 않아 `total / scores.length`가 조용히 `NaN`이 되기도 해요.</Actual>
<Right>속성 개수는 `Object.keys(scores).length`로 세요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.for-of-object">
<Wrong>`for (const score of scores)`처럼 객체도 `for...of`로 돌면 값이 하나씩 나온다.</Wrong>
<Actual>

일반 객체는 `for...of`로 돌 수 없어요.

```js
const scores = { 국어: 90, 영어: 84 };
for (const score of scores) { } // TypeError: scores is not iterable
```

"iterable(반복할 수 있는)이 아니다"라는 뜻이에요.
</Actual>
<Right>값을 돌려면 `for (const score of Object.values(scores))`, 키와 값을 함께 돌려면 `Object.entries`나 `for...in`을 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.for-in-gives-values">
<Wrong>`for (const x in scores)`의 `x`에는 점수(값)가 하나씩 들어온다.</Wrong>
<Actual>`x`에는 `"국어"`, `"영어"` 같은 **키**가 들어와요. 그래서 `total += x;`는 숫자 대신 글자를 이어 붙여 `"0국어영어"` 같은 결과를 만들어요.</Actual>
<Right>값은 `scores[x]`로 읽어요. 이름도 `subject`, `key`처럼 키라는 것이 드러나게 붙이면 헷갈리지 않아요. 값만 필요하면 `Object.values`를 돌아요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.dot-with-variable-key">
<Wrong>`for...in` 안에서 `scores.subject`라고 쓰면 지금 돌고 있는 과목의 점수가 나온다.</Wrong>
<Actual>`scores.subject`는 변수 `subject`와 상관없이 이름이 `"subject"`인 속성을 찾아서, 매번 `undefined`가 나와요.</Actual>
<Right>키가 변수에 들어 있으면 항상 대괄호 `scores[subject]`를 써요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.undefined-value-means-missing">
<Wrong>`profile.nickname === undefined`이면 `profile`에는 `nickname` 속성이 없다.</Wrong>
<Actual>세 번째 예제의 `nickname`은 값이 `undefined`였지만 `"nickname" in profile`은 `true`였고, `Object.keys`에도 들어 있었어요.</Actual>
<Right>"속성이 있는가"를 물을 때는 `"nickname" in profile`을 써요. `=== undefined`는 "값이 비어 있는가"에 가까운 질문이에요.</Right>
</Pitfall>

<Pitfall misconception="js.mc.optional-chaining-guards-rest">
<Wrong>`user?.address.city`처럼 앞에 `?.`를 한 번 쓰면 `address`가 없어도 오류가 나지 않는다.</Wrong>
<Actual>

`?.`는 바로 앞의 값만 확인해요. `user`가 있으면 그대로 `user.address`를 읽고, 그 결과 `undefined`에서 `.city`를 읽다가 오류가 나요.

```js
const user = { name: "준호" };
console.log(user?.address.city); // TypeError: Cannot read properties of undefined (reading 'city')
```
</Actual>
<Right>없을 수 있는 값 **바로 뒤**에 `?.`를 붙여요. 여기서는 `user.address?.city`예요. `user`도 없을 수 있으면 `user?.address?.city`처럼 단계마다 붙여요.</Right>
</Pitfall>
</Section>

<Section kind="in-practice">
쇼핑몰 서버에서 받은 주문 데이터는 주문마다 들어 있는 속성이 조금씩 달라요. 배송 메모를 적은 주문도 있고, 쿠폰을 쓴 주문만 `coupon` 객체가 있어요. 영수증을 만드는 코드는 이런 차이를 견뎌야 해요.

```js
const order = {
  items: { 떡볶이: 4000, 김밥: 3000 },
  coupon: { name: "첫 주문", amount: 1000 },
};

let total = 0;
for (const entry of Object.entries(order.items)) {
  console.log(entry[0] + " " + entry[1] + "원");
  total += entry[1];
}
const discount = order.coupon?.amount ?? 0;
console.log("메모: " + (order.memo ?? "없음"));
console.log("결제: " + (total - discount) + "원");
// 떡볶이 4000원
// 김밥 3000원
// 메모: 없음
// 결제: 6000원
```

- 상품 이름을 코드에 적지 않고 `Object.entries`로 돌아서, 어떤 주문이 와도 같은 코드로 영수증을 만들어요.
- 쿠폰이 없는 주문이면 `order.coupon`이 `undefined`라 `?.`가 멈추고, `??`가 0을 골라요. `order.coupon.amount`라고 썼다면 쿠폰 없는 주문에서 프로그램이 멈췄을 거예요.

실제 웹 개발에서 서버나 설정 파일에서 받은 데이터는 대부분 객체예요. "모든 속성을 돌며 화면에 보여 주기"와 "선택 항목은 확인하고 읽기"는 거의 매일 쓰는 패턴이에요.
</Section>

<Section kind="summary">
- `Object.keys`·`Object.values`·`Object.entries`는 객체의 키·값·`[키, 값]` 짝을 배열로 돌려줘요. 객체에는 `length`가 없으니 개수는 `Object.keys(obj).length`로 세요.
- 일반 객체는 `for...of`로 바로 돌 수 없어요(`is not iterable`). 위의 배열을 만들어 돌아요.
- `for (const key in obj)`의 `key`에는 키가 들어오고, 값은 `obj[key]`로 읽어요.
- `"key" in obj`는 속성이 있는지 알려 줘요. 값이 `undefined`인 속성도 있는 속성이에요.
- `a?.b`는 `a`가 `null`·`undefined`면 오류 대신 `undefined`예요. 바로 앞의 값만 확인하니 없을 수 있는 단계마다 붙이고, `??`로 기본값을 정해요.
