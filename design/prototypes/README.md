# ProgInOne 디자인 프로토타입 (M2)

[UI/UX 설계](/docs/design/ui-ux.md#디자인-프로토타입-계획)의 프로토타입 계획에 따라 만든 **정적 HTML 프로토타입** 입니다.
실제 앱 코드와 분리된 일회성 산출물이며, 시각 방향을 정한 뒤에는 결정 기록과 UI/UX 설계 문서에 결과만 남깁니다.

- 상태: 결정됨 (2026-11-14). 아래 [결정할 것](#결정할-것)의 추천안 1~4와 레슨 제목 28px를 모두 채택했습니다([D-024](/docs/decisions.md)).
- 작성: 2026-11-14
- 콘텐츠: JavaScript 기초 › 값과 변수 › 변수와 상수(`variables`, 핵심 단원). 로렘 입숨 없음.

## 여는 방법

빌드 단계가 없습니다. 브라우저로 `index.html`을 여세요.

```shell
open design/prototypes/index.html
```

- 화면 왼쪽 아래의 툴바에서 **시안(A/B/C)** 과 **테마(라이트/다크)** 를 바꿉니다. 키보드로는 Tab으로 그룹에 들어가 ←/→로 이동합니다.
- 상태는 주소에 남습니다: `learn-practice.html?d=b&t=dark`. `&shot=1`을 붙이면 툴바를 숨깁니다(스크린샷용).
- 실습 화면에서 `⌘J`로 튜터 드로어를 여닫고, 과정 상세에서 모듈 헤더를 눌러 아코디언을 여닫을 수 있습니다.
- 폰트(Pretendard, JetBrains Mono)는 프로토타입에 한해 jsDelivr CDN에서 불러옵니다. 실제 앱은 번들에 포함합니다(NFR-09).

| 파일 | 화면 |
|---|---|
| `index.html` | 목록, 시안 설명, 로고 후보 |
| `dashboard.html` | 대시보드 (오늘의 학습, 오늘의 복습, 개념 지도, 과정 진도, 최근 활동) |

## 다시 찍기와 검사

```shell
cd design/prototypes
npm install                      # playwright 1.64.1, axe-core 4.11.4
npx playwright install chromium  # 최초 1회
npm run shots                    # screenshots/ 에 62장 (특정 화면만: node capture.mjs dashboard)
npm run contrast                 # 토큰 대비 측정 (node contrast.mjs --md 로 표 출력)
node a11y.mjs                    # axe-core WCAG 2.2 A/AA 자동 검사
```

스크린샷 이름 규칙: `<화면>-<시안>-<테마>-<폭>.png`.
읽기 모드는 스크롤 안쪽도 찍습니다: `learn-read-s2-*`(예측 후 실행·흔한 실수), `learn-read-s3-*`(const 설명·확인 문제).
뷰포트는 1440×900(모든 화면), 1280×800·1024×768(학습 화면)입니다. reduced-motion을 강제합니다.

## 시안 비교

세 시안은 모두 같은 토큰·컴포넌트를 쓰고, `[data-direction]` 덮어쓰기만 다릅니다.

| 안 | 바뀌는 것 | 계획의 확인 질문 | 관찰 결과 |
|---|---|---|---|
| **A 밝은 교실** | 기본 토큰 그대로. 캔버스 `neutral-25`, 넓은 상단 여백, 에디터 라이트 | 실습 모드에서 코드 영역이 충분히 구분되는가 | 구분은 됩니다(에디터 `neutral-50` 바탕, 패널 경계, 현재 줄·오류 줄 강조). 다만 문제 패널·에디터·결과·튜터가 모두 흰색이라 1440px에서 네 영역의 위계가 약하고, 시선이 에디터로 모이지 않습니다. |
| **B 밝은 교실 + 어두운 작업대** | 라이트 테마에서 `.workbench`(에디터·테스트·콘솔)만 다크 의미 토큰으로 재매핑 | 명암 대비가 피로하지 않은가, 한 제품처럼 보이는가 | 에디터가 즉시 "작업할 곳"으로 읽히고, VS Code에 익숙해질 학습자에게 친숙합니다. 반면 밝은 문제 패널·튜터 드로어 사이에 어두운 블록이 끼어 경계가 강하고, **레슨의 코드 블록(라이트)과 실습 에디터(다크)의 같은 코드가 다르게 보입니다.** 다크 테마에서는 A와 같습니다. |
| **C 차분한 교실** | 캔버스 `neutral-50`, 흰 카드, 레슨 본문도 카드에 담음, 카드 패딩·간격 약 15% 축소 | 장시간 학습 피로, 정보 밀도 | 카드와 바탕의 단계가 생겨 대시보드·과정 상세의 위계가 가장 분명합니다. 읽기 모드에서 본문이 종이처럼 떠 있어 긴 글 읽기 영역이 명확합니다. 밀도 차이는 1440px에서 크지 않아 대시보드가 한 화면에 조금 더 들어오는 정도입니다. |

### 추천: C(차분한 교실) + 라이트 에디터 기본, 어두운 작업대는 설정 옵션

1.  **둘러보기·읽기 화면은 C.** 카드–캔버스 단계가 정보 위계를 가장 잘 드러내고, 레슨을 카드에 담으면 "읽는 영역"이 분명해집니다. 인프런의 흰 캔버스 톤을 크게 벗어나지 않으면서 장시간 학습에서 화면 전체가 하얗게 빛나는 느낌을 줄입니다.
1.  **에디터는 라이트(A)를 기본으로.** 레슨 코드 블록과 실습 에디터가 같은 모습이어야 "본문에서 본 코드를 직접 써 본다"는 전이가 자연스럽습니다(입문자 대상). B의 장점(작업 영역 집중)은 라이트 에디터에서도 현재 줄·오류 줄 강조와 패널 경계로 상당 부분 얻을 수 있습니다.
1.  **B는 설정의 "작업대 테마: 어둡게"로 제공.** 토큰 구조상 `.workbench` 범위 재매핑 한 블록이라 구현 비용이 거의 없습니다. 실력이 오르면 어두운 에디터를 선호할 수 있으므로 선택권을 남깁니다.

`index.html` 하단에서 라이트·다크·20px·단색 버전을 비교할 수 있습니다.

| 안 | 형태 | 장점 | 단점 |
|---|---|---|---|
| 1 맞물린 꺾쇠 (문서 명세안, 헤더에 사용) | 둥근 사각형 안 `‹ ›`가 점(학습자)을 감쌈 | 코드 학습 앱임이 바로 드러남, 20px에서도 선명 | 코드 꺾쇠 심볼은 개발 도구에서 흔함 |
| 2 차오르는 고리 | 거의 다 찬 진도 링 + 중심 점 | 앱의 진도 링과 같은 시각 언어, "꾸준히 채움" | 실제 진도 링 UI와 혼동 가능, 코드 느낌이 약함 |
| 3 네 조각 하나 | 세 타일(레슨·실습·복습) + 원(학습자) | "All-in-One"을 가장 직접 표현, 숙련 명도 스케일과 연결 | 앱 런처·대시보드 아이콘처럼 보일 수 있음 |

### 문서에 반영할 토큰 수정 제안

측정 결과, UI/UX 설계 문서의 토큰 중 세 곳이 문서 자신의 대비 목표를 만족하지 못했습니다.

| 토큰 | 문서 값 | 문제 | 프로토타입 값 |
|---|---|---|---|
| `--jade-600` (라이트 기본 버튼 배경) | `oklch(0.560 0.120 168)` | 흰 글자 4.34:1 (목표 4.5:1). 버튼 글자 14px라 큰 텍스트 예외도 아님 | `oklch(0.545 0.120 168)` → 4.60:1. 눈으로는 차이가 거의 없음 |
| `--color-text-tertiary` (라이트) | `neutral-500` | 작은 캡션(시각, 문제 수 등)에 쓰면 4.27:1 | 새 기본 토큰 `--neutral-550: oklch(0.540 0.008 168)` → 흰 바탕 5.04:1, `neutral-50` 바탕 4.63:1 |
| 입력 테두리 | 라이트 `--color-border-strong` = `neutral-300`, 다크 `neutral-600` | 1.4.11 비텍스트 3:1 미달 (1.68:1, 2.72:1) | 의미 토큰 `--color-border-input` 신설: 라이트 `neutral-500`(4.27:1), 다크 `neutral-500`(4.15:1). 장식용 강한 테두리는 기존 값 유지 |

## 접근성 자동 검사

`node a11y.mjs`: 4개 화면 × 3시안 × 2테마 = 24조합 모두 **axe-core WCAG 2.2 A/AA 위반 0건** 입니다.
검사 중 발견해 고친 것: 완료 항목의 `opacity` 처리로 생긴 대비 미달, 링크에 쓴 `aria-selected`, 라벨만 있는 `span`, 값 없는 `separator`, 포커스할 수 없는 스크롤 영역(튜터 대화).

그 밖에 적용한 것: 랜드마크(`header`·`nav`·`main`·`aside`), 건너뛰기 링크, `:focus-visible` 2px 링, 숙련 아이콘의 `role="img"` + 텍스트 레이블, 정오·숙련을 색과 모양으로 함께 표시, `prefers-reduced-motion`에서 이동 애니메이션 제거, `lang="ko"`, 키보드로 조작 가능한 툴바(라디오 그룹 + 화살표 키).

## 결정할 것

1.  **시각 방향**: 추천은 C(차분한 교실) + 라이트 에디터 기본, 어두운 작업대는 설정 옵션.

1.  **로고**: 1안 추천.
1.  **토큰 수정 3건 승인**: `jade-600` 명도, `neutral-550` 추가, `--color-border-input` 신설.

## 남은 문제와 한계

- **인프런 실제 화면 관찰은 하지 못했습니다.** 계획의 "실제 화면 직접 관찰" 단계는 로그인한 수강 화면이 필요해, 이번 프로토타입은 문서의 레퍼런스 분석에 기대었습니다. 사용자가 실제 화면을 보고 차이를 알려 주면 보정합니다.
- **20분 시나리오 점검은 사람이 해야 합니다.** 계획의 평가 방법 2번(각 안으로 단원 하나를 20분 학습)은 정적 프로토타입으로는 흐름이 끊깁니다. 화면을 직접 넘겨 보며 느낌을 확인해 주세요.
- 빈·로딩·오류 상태, 객관식·예측·파슨스 전용 실습 레이아웃, 웹 실습 3분할, 1920px은 만들지 않았습니다.
- 다크 오답 피드백 배경, 1440px에서 튜터를 열었을 때 문제 패널 폭(약 370px)은 실제 앱에서 리사이즈 기본값으로 다시 조정할 대상입니다.
- 레슨 제목 크기(프로토타입 32px, 문서 `--text-h1` 28px)를 정해야 합니다.
